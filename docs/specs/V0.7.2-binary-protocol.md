# V0.7.2 二进制 IPC 协议 v1

## 1. 基本规则

- 所有多字节整数和 IEEE-754 浮点数均为 little-endian。
- 所有 offset 从整个 ArrayBuffer 的第 0 字节计算。
- 所有段 offset 为 4 字节对齐，段之间不得重叠；未声明尾随字节拒绝。
- 解码顺序固定为：总长→公共头→段表→每段范围/标量/计数→UTF-8/有限浮点/索引语义。
- 最大成功响应为 128 MiB。所有乘加必须在分配和建立 TypedArray 前检查溢出。
- 协议版本独立于应用版本；本文件定义 version `1`。
- JSON number 表达的 `sessionId`、`taskId` 必须位于 `1..=2^53-1`，Rust 在达到上限后返回既有耗尽错误，不输出无法由 JavaScript 无损表示的编号。

## 2. 公共头（32 字节）

| Offset | 宽度 | 类型 | 字段 | 规则 |
|---:|---:|---|---|---|
| 0 | 4 | bytes | magic | ASCII `MCWE` |
| 4 | 2 | u16 | version | `1` |
| 6 | 2 | u16 | kind | `1=surface`，`2=mesh`，`3=map tile` |
| 8 | 4 | u32 | headerLength | `32` |
| 12 | 4 | u32 | totalLength | 必须等于 ArrayBuffer.byteLength |
| 16 | 4 | u32 | metadataOffset | 4 字节对齐 |
| 20 | 4 | u32 | metadataLength | 受限 UTF-8 JSON object |
| 24 | 4 | u32 | sectionTableOffset | `32` |
| 28 | 4 | u32 | sectionCount | surface/map tile 固定 3；mesh 固定 4 |

metadata 紧跟所有段数据之后，按 4 字节对齐起始；JSON 只允许协议定义的小型摘要和聚合警告。解析后必须是普通 object，不能覆盖头部计数、偏移或数组长度。

## 3. 段表项（每项 16 字节）

| 相对 Offset | 宽度 | 类型 | 字段 |
|---:|---:|---|---|
| 0 | 2 | u16 | sectionId |
| 2 | 2 | u16 | scalarType |
| 4 | 4 | u32 | offset |
| 8 | 4 | u32 | byteLength |
| 12 | 4 | u32 | elementCount |

scalarType：`1=u8`、`2=i8`、`3=u16`、`4=u32`、`5=i32`、`6=f32`。byteLength 必须严格等于 elementCount×标量宽度。

## 4. Surface v1（kind=1）

固定逻辑格数 `144×144=20736`，顺序为 `index=z*144+x`：x 从西到东递增，z 从北到南递增。

| sectionId | scalar | count | 内容 |
|---:|---|---:|---|
| 1 | u32 | 20736 | `0x00RRGGBB` 表面颜色 |
| 2 | i32 | 20736 | 世界表面 Y；无有效列时值必须为 0 且由状态区分 |
| 3 | u8 | 20736 | `0=success,1=missing,2=unsupported,3=corrupt`；`4=cancelled` 仅为内部状态保留值，完整成功响应必须拒绝 |

metadata 必须包含：`sessionId`、`taskId`、`originBlockX/Z`、`centerChunkX/Z`、`centerX/Y/Z`、`centerSource`、可空 `worldSpawn`、`successfulChunks`、`failedChunks`、受限聚合 warnings。`centerSource` 仅允许 `playerRespawn`、`worldSpawn`、`originFallback`；`worldSpawn` 为 `null` 或严格的 `{x,y,z}` 整数对象。`centerSource=worldSpawn` 时中心必须与 `worldSpawn` 相同，`centerSource=originFallback` 时中心必须为 `(0,0,0)`。`failedChunks` 只统计 `unsupported+corrupt`，正常未生成的 `missing` 单独统计并通过聚合信息报告。世界名称/显示路径只在世界选择 JSON 响应返回，不复制到密集载荷。

## 5. Mesh v1（kind=2）

坐标使用以选区最小世界 X/Z 为局部 `(0,0)` 的 f32；Y 保持世界 Y。position 和 normal 均为 xyz 三元组。

| sectionId | scalar | 内容 |
|---:|---|---|
| 10 | f32 | positions，count 必须为 vertexCount×3 |
| 11 | f32 | normals，count 必须等于 positions count，分量有限且为轴向 -1/0/1 |
| 12 | u32 | indices，每项 `< vertexCount`，count 为三角形数×3 |
| 13 | u32 | batch table，每批固定 8 个 u32 |

每个 batch 的 8 个 u32：

| 索引 | 字段 | 规则 |
|---:|---|---|
| 0 | layer | `0=opaque,1=cutout,2=translucent,3=fluid,4=fallback` |
| 1 | rgb | `0x00RRGGBB` |
| 2 | alphaBits | f32 alpha 的原始 bits，有限且 `0..=1` |
| 3 | firstIndex | indices 起点 |
| 4 | indexCount | 6 的倍数且范围有效 |
| 5 | blockCount | 统计值 |
| 6 | faceCount | indexCount/6 |
| 7 | reserved | 必须为 0 |

metadata 必须包含：`sessionId`、`taskId`、目标 chunk 矩形、`originWorldX/Z`、bounds、总体 block/face/vertex/index/batch 数、局部失败和聚合 warnings。头部/段表计数是数组真值，metadata 统计必须一致。

## 5.1 Map tile v1（kind=3）

地图瓦片沿用同一 v1 envelope 与颜色/高度/状态三段结构，每段固定 `256×256=65536` 项。`blocksPerPixel` 只允许 `1/2/4/8/16`；瓦片方块边长为 `256×blocksPerPixel`，`originBlockX/Z` 必须严格等于 `tileX/Z×瓦片方块边长`。像素聚合和高度明暗遵循 Java `MapTileRenderer`。

metadata 固定包含：`sessionId`、`taskId`、`tileX/Z`、`blocksPerPixel`、`originBlockX/Z`，以及 success/missing/unsupported/corrupt 四类区块计数。计数总和必须等于瓦片覆盖区块数，并与像素状态数量一致。前端仍只提交会话编号与有界整数瓦片身份，不提交世界路径。

## 6. 错误与取消

- 成功响应只包含协议 buffer；Command 失败通过类型化 `AppError` reject。
- 空 buffer、未知 magic/version/kind、重复/缺少 section、错位、重叠、截断、尾随数据、非法 UTF-8/JSON、NaN/Infinity 和索引越界均拒绝整份新结果。
- cancelled/outdated/session-outdated 不编码成功载荷，不提交半成品。
- 前端解析失败时保留旧完整视图并释放新 buffer 引用。

## 7. 黄金向量

- Rust 编码器是字节布局的唯一生产来源。
- 仓库保存不含真实世界内容的最小 surface/mesh 黄金向量；当前以测试专用 `.bin.gz.b64` 文本保存，解压后仍是未经改写的 Rust v1 字节。
- Rust 测试锁定编码结果的 FNV-1a 64 位哈希，TypeScript 解压夹具后核对同一哈希再解码；畸形向量从黄金副本精确改写单一字段。
- v1 首次提交或发布后，若布局发生不兼容改变，新增协议版本和对应解码器，不原地修改 v1。首次提交前修正契约时，必须同步更新规范、Rust 编码器、TypeScript 解码器、两端哈希和同一黄金向量，不保留已知错误字段作为伪兼容层。

## 8. 当前兼容载荷范围

`surface-v1` 的生产载荷固定为 1024² 个颜色、高度和状态元素；`originBlock=centerBlock-512`，最多相交 65×65 区块。每个相交区块只计数一次，边缘区块只验证载荷范围内的像素。原点和坐标上限必须独立做有界验证，不能由区块半径间接推导。

Envelope 版本、字段、section 表与传输方式保持不变。解码器只接受 144² 测试兼容载荷和 1024² 生产载荷，不接受任意数组长度；当前协议不新增尺寸字段，尺寸由受限 section count 判定。Rust 编码器和 TypeScript 解码器必须配套更新与验证。

三维 `chunkRect` 的宽和深均为整数 1..8；界面提供 1/3/5/8 正方形预设。后端必须验证完整目标区块位于精确二维方块边界内。一圈邻区可以用于读取边界信息，但不得进入目标网格；128 MiB 响应上限和网格上限保持有效。

大范围独立黄金向量固定为：`center=(-1,64,17)`、`origin=(-513,-495)`、全部区块缺失、相交区块数 4225；Rust 与 TypeScript 的 FNV-1a 64 位值均为 `252811299370147227`。144² 与 1024² 两组黄金向量共同构成当前 v1 兼容契约。
