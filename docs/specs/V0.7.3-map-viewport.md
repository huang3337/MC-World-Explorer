# V0.7.3 二维视口与渐进结果规格

- **契约状态**：已确认，当前有效
- **确认日期**：2026-09-17
- **适用范围**：`tauri-rewrite` 的二维视口任务、瓦片状态、渐进结果、完整度和增量 IPC

本规格落实 Tauri DECISION-021 至 DECISION-023，描述当前有效的二维行为契约；代码实现和验收进展只见[当前阶段状态](../progress/CURRENT.md)。

## 1. 目标与边界

目标体验继承 Java 稳定版：世界会话建立后立即出现可交互地图；当前视口中心优先；固定两个地图 worker；单瓦片完整生成前可以显示局部结果；旧倍率画面保留到新倍率结果覆盖；可见区域进入终态后再预取外围；回看和缩放能够复用结果。

- Minecraft 存档严格只读。
- 前端只提交 session ID 和受限视口参数，不提交世界路径。
- 通用重任务继续使用现有单 worker 有界执行器；地图使用独立调度域。
- session ID、后端分配的视口任务 ID、任务代次和迟到结果拒绝继续有效。
- 调度队列、结果队列、IPC 批次、内存缓存和后续磁盘缓存全部有界。
- 缺失、不支持、损坏、未知方块视觉回退、请求失败、取消和过期不能互相代替。
- `surface-v1` 作为既有协议保留，但正式二维入口不再依赖固定 1024×1024 surface。

## 2. 视口任务

一次视口任务表示当前会话中一个已经稳定到数据倍率的可见范围。输入包含：

- `sessionId`；
- 有限世界坐标 `centerX/centerZ`；
- 有限正整数 CSS 像素尺寸 `viewportWidth/viewportHeight`；
- `blocksPerPixel`，只允许 `1/2/4/8/16`。
- `displayBlocksPerPixel`，实际显示的每 CSS 像素覆盖方块数，必须为 `0.25..=16` 内的有限数；它可在滚轮动画或放大显示时不同于瓦片数据倍率。

后端验证会话和所有乘加边界；以 `displayBlocksPerPixel` 和 CSS 宽高确定实际可见世界范围，以 `blocksPerPixel` 确定 256×256 数据瓦片的世界边长，再计算与视口相交的瓦片。前后端必须按同一范围核对目标集合。目标以距视口中心的平方距离排序；相同距离按 Z、X 和提交序稳定排序。后端分配单调递增且不复用的 `viewportTaskId`，立即返回任务摘要，不等待瓦片完成。当前可见目标全部进入终态后才允许提交外围一圈预取。

CSS 视口宽高分别限制为 `1..=16384`，一次任务最多包含 64 个可见瓦片；超限在进入调度队列前拒绝。长轮询单次等待预算为 250 ms，超时返回合法空批次而不是密集重试或伪造终态。

新视口替换旧视口时：

- 共有且身份相同的已完成瓦片直接复用；
- 正在排队或运行的相同瓦片重新绑定到新任务，不重复计算；
- 不再需要的排队任务移除，运行任务协作取消；
- 旧任务已经产生但尚未提交的结果由 session ID 与 viewportTaskId 拒绝。

滚轮动画可以使用连续显示倍率，但只在稳定后提交五个数据倍率之一。动画期间继续绘制旧倍率完整结果，不把拉伸后的旧结果计入新视口完整度。

## 3. 瓦片身份

逻辑瓦片身份包含世界来源、维度、图层、倍率、瓦片坐标和渲染版本。session ID 和 viewportTaskId 用于授权、归属和迟到结果拒绝，不替代可复用瓦片身份。后续磁盘缓存沿用同一逻辑身份，但不持久化 session ID 或任务 ID。

## 4. 状态模型

### 4.1 当前可见目标状态

- `unloaded`：尚未接纳为当前任务目标。
- `queued`：已进入有界调度队列。
- `running`：地图 worker 正在处理。
- `partial`：至少一个有效局部结果已经提交，尚未形成终态。
- `ready`：完整最终瓦片已经严格解码并提交。
- `failed`：整瓦片请求失败，具有稳定错误代码，可以重试。

`ready` 和 `failed` 是当前视口的目标终态。取消和过期属于任务生命周期结果，不是可以继续显示为当前目标终态的数据。

### 4.2 最终瓦片内部来源状态

- `success`：受支持区块成功解码和采样。
- `missing`：Region 头中对应区块槽位未占用，是真实不存在。
- `unsupported`：区块存在，但格式或压缩不在已确认支持范围。
- `corrupt`：区块存在，但结构或载荷损坏。

Region 文件暂时无法打开、共享冲突、其他 I/O 请求失败、调度器关闭、任务取消、结果过期、协议编码失败和 IPC 失败不得伪装成上述四种成功载荷状态。它们形成整瓦片 `failed` 或任务级取消/过期。未知方块名称只使用稳定视觉回退并产生聚合 warning，所属区块仍是 `success`。

### 4.3 视口状态

- `loading`：至少一个当前可见目标仍为 `unloaded/queued/running/partial`。
- `settled`：所有当前可见目标均为 `ready` 或 `failed`。
- `complete`：视口已经 `settled`，所有可见目标均为 `ready`，且没有已存在但因 `unsupported/corrupt` 未显示的区块。
- `partial-complete`：视口已经 `settled`，但至少一个目标 `failed`，或最终瓦片包含 `unsupported/corrupt`。
- `empty-complete`：`complete` 的一种；当前可见范围经 Region 头证明全部为真实 `missing`。

“请求已经结束”只能称为 `settled`，不能自动显示“当前视口已完整加载”。真实 `missing` 不阻止完整；`unsupported`、`corrupt` 和整瓦片 `failed` 必须阻止完整并给出计数或可定位提示。

## 5. 渐进结果

- 每个 worker 在首次产生可显示像素后立即发布首个局部结果。
- 后续只有进度或像素实际变化时才发布，目标节流间隔约 100 ms。
- 最终结果不受节流延迟，完成后立即进入结果队列。
- 局部结果携带 session ID、viewportTaskId、瓦片身份、单调递增 revision、完成区块数和总区块数。
- 同一瓦片只接受 revision 递增的结果；最终结果提交后拒绝其后所有局部结果。
- 局部结果不得进入最终瓦片缓存、导出或视口完整度计算。
- 尚未处理区域必须表达为 `unloaded`，不能伪装为 `missing`。
- 前端仅替换局部结果明确覆盖的区域；协议解析失败时保留先前可用画面。

局部二进制载荷使用有界矩形补丁。通常只发送变化区域；恢复同一会话中断前的瓦片进度时，首次补丁可覆盖整张 256×256 瓦片，以便前端没有保留旧图像时也能显示已完成部分。补丁携带瓦片身份、revision、矩形范围、颜色、高度和来源状态；详细字节布局纳入二进制协议规格和双端黄金向量。

## 6. 增量 IPC

增量 IPC 固定采用“启动视口任务＋单长轮询拉取有界批次”：

1. `start_map_viewport` 使用 JSON 返回 viewportTaskId 和目标摘要。
2. 前端对同一任务最多保持一个 `next_map_viewport_batch` 请求。
3. 后端等待有结果、任务终止、关闭唤醒或有限超时，返回一个原始二进制批次。
4. 前端严格解码并提交后再请求下一批。

组件卸载或启动响应已过期时，前端以 `sessionId` 和 `viewportTaskId` 调用 `cancel_map_viewport`。后端仅取消身份完全匹配的当前地图视口，并唤醒其长轮询；重复或迟到的取消不影响新视口。该命令不接受路径，也不取消通用执行器任务。

该方式保持最多一个在途批次，由应用明确限制结果队列和批次字节数，并能在取消和关闭时唤醒等待请求。不得改用全局事件、Base64、临时文件、本地 HTTP 服务或无背压的密集消息推送。

## 7. 有界性

- 地图 worker 固定为 2，不随 CPU 数增长。
- 地图调度队列容量固定为 96 个等待任务；两个运行任务不计入该容量。
- 当前 WorldSession 的区块缓存采用访问序 LRU，最多 512 项且累计保守内存预算不超过 128 MiB；成功项同时保存解码区块和 256 列表面采样，稳定的 missing/unsupported/corrupt 结果可以按来源状态缓存。
- 当前 WorldSession 的未完成瓦片进度缓存采用访问序 LRU，最多 8 项且累计保守内存预算不超过 32 MiB；只保存来源未变化时已处理区块的累积值、状态、完成标记和计数，供取消后继续生成，不作为最终瓦片或视口完整度。
- 当前 WorldSession 的最终瓦片缓存采用访问序 LRU，继承 Java 的 128 项上限，并增加 96 MiB 累计保守内存预算上限。
- 区块项按维度、区块坐标和对应 Region 来源状态识别；未完成进度与最终瓦片按维度、图层、倍率、瓦片坐标、渲染版本和全部相交 Region 来源状态识别。当前只实现的主世界表面层也必须保留这些身份边界。
- 每次命中前重新核对相关 Region 的存在性、长度和最后修改时间；来源变化立即视为未命中并淘汰旧项。生成期间来源发生变化时不得写入缓存。
- Permission、共享冲突、其他 I/O 请求失败、取消、任务过期和 worker 失败不得缓存为 missing/unsupported/corrupt；局部瓦片不得进入最终瓦片缓存。
- 三类内存缓存由 WorldSession 独占；候选世界失败不影响当前缓存，世界成功切换后新会话从空缓存开始，旧任务收束后随旧会话释放，应用关闭不写磁盘。
- 可见目标和外围一圈预取目标分别最多 64 个，超限请求在排队前拒绝或按中心距离截断预取。
- 结果队列按字节和项目数双重限制。
- 结果队列最多保存 64 个项目且保守累计载荷不超过 32 MiB，单个结果项目不得超过 2 MiB；两个 worker 的生产速率不能绕过这些上限。
- 同一瓦片最多保留一个尚未消费的最新局部结果；新局部结果合并或替换旧局部结果。
- 最终结果和稳定失败不得静默丢弃；必要时先淘汰可替换的局部结果，再协作阻塞或取消生产者。
- 单 IPC 批次最多 16 个结果项目且完整 envelope 不超过 8 MiB，不能依赖 128 MiB 全局成功响应上限作为正常容量；详细布局使用二进制协议 v1 的 `kind=4`。
- 视口更新、世界切换、组件卸载和应用关闭释放等待者、队列元素和 ArrayBuffer 引用。

## 8. 前端提交与显示

- 世界会话建立后立即挂载 MapViewport，不等待 surface-v1。
- 未产生结果的当前区域显示明确的“未加载”视觉和文本等价信息。
- `missing/unsupported/corrupt` 使用互不相同的视觉；整瓦片 `failed` 使用独立覆盖层和重试入口。
- 重试入口重新启动当前视口任务；已有 `ready` 瓦片通过会话缓存复用，整瓦片 `failed` 不进入缓存并重新读取。
- 同键旧图像已为 `ready` 时，新请求的局部补丁不得把它降级为逐块覆盖画面；仍需等待当前任务的真实终态才可计入当前视口完整度，失败结果仍应显式显示。
- 单个瓦片或补丁提交后立即重绘，不等待同批其他结果。
- 新倍率数据逐步覆盖旧倍率画面；旧倍率只作为视觉保留，不参与新任务计数。
- 状态栏分别显示加载中、已收束但存在失败、完整、空范围完整和取消。
- 外围预取不进入当前视口状态栏，也不阻止 `settled/complete`。

## 9. 自动化验收

1. 世界会话成功后无需完成固定 surface 即可显示可交互视口。
2. 两个地图 worker 可以同时运行，峰值永不超过 2；通用执行器仍保持单 worker。
3. 可见目标早于预取目标，中心目标早于外围目标，同优先级顺序稳定。
4. 新任务对相同瓦片重新绑定且不重复生成，移除目标能够协作取消。
5. 首个局部结果在完整瓦片前提交；局部 revision 递增，终态后拒绝迟到局部结果。
6. session、viewportTaskId、tile identity 任一不匹配的结果都不能改变画布或完整度。
7. `missing`、`unsupported`、`corrupt`、`unloaded`、整瓦片 `failed` 和未知方块回退保持可区分。
8. 只有全部可见目标 ready 且不存在 unsupported/corrupt 时才为 complete；全部真实缺失可以 empty-complete。
9. 拖动、缩放、定位和返回旧区域不会提交旧代次结果；新倍率未就绪时保留旧画面。
10. 负坐标、Region 边界、五个倍率和极端乘加通过固定样本。
11. 结果队列满时只合并或淘汰可替换局部结果，不丢最终结果和失败。
12. 世界切换、组件卸载和关闭能唤醒等待中的批次请求并释放地图资源。
13. 同一会话重复请求相同瓦片命中最终瓦片缓存；切换倍率或相邻计算能够命中来源未变化的区块缓存，不再次解压、解码和采样。
14. 区块、未完成进度和最终瓦片缓存分别验证命中、访问序淘汰、项数上限、字节上限、来源变化失效和清空；未完成进度在区块缓存已淘汰部分旧项时仍可续载，不能越过来源或 WorldSession 边界，也不得充当最终瓦片。
15. 核心首次处理完一个区块后即可产生覆盖对应像素及必要阴影依赖边缘的矩形补丁；连续补丁 revision 严格递增，约 100 ms 节流期间累计脏矩形，最终瓦片不等待节流。
16. 结果队列同时验证项目和字节上限；同瓦片局部结果只保留最新项，容量紧张时优先淘汰可替换局部结果，最终结果和稳定失败只能被消费、取消或关闭解除，不能静默丢失。

## 10. 性能与真实存档验收

真实存档测试继续需要开发者单独批准。批准前必须报告测试目标、操作步骤、通过标准、生成产物及只读证明。

同机、同存档、同视口、同倍率至少重复三次，分别记录世界会话成功到视口可交互、首个可见像素、首个完整可见瓦片、当前视口 settled/complete、冷缓存、会话内热缓存、返回旧区域、倍率切换、取消响应、关闭收束、峰值内存和文件句柄，并与 Java 稳定版同范围比较。

首个可见结果必须早于完整视口，并实际观察到至少一个中间提交。性能硬阈值在取得同机 Java/Tauri 基线后由开发者确认，不预设没有证据的固定毫秒目标。
