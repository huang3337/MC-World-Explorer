# V0.3.1 发布前完善设计

## 状态

- **设计日期**：2026-07-30
- **确认状态**：开发者已逐项确认
- **适用版本**：V0.3.1
- **提交限制**：遵守 Rule 18；版本开发完成前不提交、不推送、不创建标签、不发布软件包

## 背景

V0.3 已具备地表与高度带浏览、离散缩放、自由拖动、地图块缓存、玩家与出生点标记、传送门识别、多人玩家列表和当前视口 PNG 导出。

V0.3.1 作为软件包发布前的最后完善版本，集中处理四类问题：

1. 地图块加载失败时缺少明确、可控的局部恢复入口。
2. 多人玩家标记缺少身份提示和列表定位后的视觉确认。
3. 当前缓存清理功能缺少容量信息和清理结果反馈，按钮名称也没有完整描述现有行为。
4. `1 方块/像素` 的现有放大上限不足以舒适查看局部方块分布。

本版本同时建立完整的自动化、真实存档、长时间交互、旧版本升级和便携包验收门槛。V0.3.1 不扩展为新的地图功能版本。

## 设计目标

- 单个地图块失败时不破坏其余地图，可自动尝试恢复，也可由用户点击该块重试。
- 玩家标记能够明确对应玩家身份，玩家列表定位后能够快速确认目标。
- 缓存清理前后提供可核对的文件数量和容量反馈。
- 在不扩展地图块缓存格式的前提下提供 `2×` 和 `4×` 高倍率视觉放大。
- 保持地图缓存、运行时玩家信息和界面展示数据之间的边界。
- 通过完整验收后再由开发者决定是否提交、构建最终软件包和发布。

## 明确不做

- 不增加新的标记类型。
- 不增加标记聚合、自动避让或永久名称标签。
- 不增加任意连续缩放等级或高倍率视觉放大对应的磁盘瓦片缓存。
- 不增加自动缓存淘汰、自动过期或自动清理。
- 不读取模组资源包来还原完整方块纹理。
- 不进行全世界预生成。
- 不增加三维地图。
- 不让“清理存档缓存并重新加载”承担失败地图块的重试职责。

## 一、失败地图块恢复

### 状态模型

失败状态以当前世界和 `MapTileKey` 为边界，只存在于运行时，不写入磁盘缓存。

每个当前视口需要的地图块具有以下界面状态：

- `LOADING`：正在首次加载、自动重试或手动重试。
- `READY`：已有可显示的有效地图块。
- `FAILED`：自动尝试结束后仍失败，可以点击重试。

切换世界或发生使地图块键失效的维度、显示层、渲染版本变化时，丢弃旧失败状态。普通拖动离开视口后再拖回同一地图块，不重新开始无限自动重试；该块保持可点击失败状态，直到手动重试成功或上下文失效。

### 自动重试

- 地图块首次加载失败后自动重试一次。
- 每个地图块在同一有效上下文中最多进行两次自动加载尝试。
- 第二次仍失败后进入 `FAILED`。
- 自动重试沿用现有任务上下文和过期结果隔离，旧世界、旧维度、旧显示层或旧缩放任务不得覆盖当前画面。
- 自动重试只针对失败块，不取消或阻塞其他地图块。

### 失败外观

- 如果同一地图块已有可用旧画面，保留旧画面作为底图。
- 旧画面上覆盖半透明红色斜线和红色边框。
- 如果没有可用旧画面，使用深色占位底图，再叠加相同失败样式。
- 只允许复用同一个 `MapTileKey` 对应的旧画面，不得跨维度、显示层或缩放等级借用画面。
- 悬停失败块时显示手形指针和提示“加载失败，点击重试”。

### 点击重试

- 失败块的整个可见区域都是重试命中区域。
- 一次点击只重新加载该地图块一次。
- 重试期间进入 `LOADING` 并阻止重复点击。
- 重试成功后替换失败外观，恢复正常地图块。
- 重试仍失败时返回 `FAILED`，等待下一次明确点击。
- 鼠标按下与释放的总位移不超过 4 个逻辑像素，且释放时仍命中同一失败块，才视为点击重试。
- 超过阈值时继续执行地图拖动，不触发重试。
- 标记命中优先于失败块命中，现有标记点击和悬停行为不变。

### 状态与导出

- 当前视口只要仍有加载中或失败的必需地图块，PNG 导出保持禁用。
- 状态栏显示当前视口失败地图块数量。
- 其他已完成地图块继续显示和交互。
- 失败覆盖层只用于界面诊断，不进入磁盘缓存，也不得出现在成功导出的 PNG 中。

## 二、多人玩家标记

### 展示数据边界

保持现有 `MapMarker` 瓦片缓存格式不变。玩家名称、UUID 和原始坐标作为运行时界面展示数据管理，不写入传送门地图块缓存。

界面层使用带可选身份信息的展示标记：

- 传送门和出生点只有现有类型与坐标信息。
- 玩家展示标记引用现有 `PlayerLocation`，包含 UUID、显示名称、维度和原始 X/Y/Z。
- 展示层负责 Tooltip、命中和短时高亮，不改变地图块生成器的职责。

### 玩家 Tooltip

- 鼠标命中可见玩家标记时显示玩家名称、维度和 X/Y/Z。
- 维度使用界面显示名，并附带维度 ID，避免模组维度名称含糊。
- 坐标使用 `PlayerLocation` 的原始双精度值，界面保留一位小数。
- 地图标记绘制位置继续沿用现有向下取整规则。
- 鼠标离开、开始拖动、关闭玩家标记、切换世界或未命中标记时立即隐藏 Tooltip。
- 不创建永久玩家名称标签。

### 玩家列表定位与高亮

- 玩家列表保持现有排序、重名短 UUID 区分和维度可用性处理。
- 点击有效玩家后，自动切换到其所在维度。
- 定位后强制使用地表总览和默认 `2 方块/像素`。
- 视口以玩家 X/Z 为中心。
- 如果玩家标记开关处于关闭状态，定位时自动打开，以保证目标可见。
- 目标玩家标记显示约 3 秒的外圈高亮，不改变绿色基础标记颜色。
- 高亮不阻塞缩放、拖动或其他操作。
- 选择另一名玩家时立即替换旧高亮。
- 切换世界、目标标记不可用或高亮时间结束时移除高亮。
- 玩家列表定位不会改变“重置视图”保存的维度默认中心。

## 三、清理存档缓存并重新加载

### 按钮名称与现有行为

按钮名称改为“清理存档缓存并重新加载”。

该名称准确描述现有行为，V0.3.1 不改变其视图语义：

- 只清理当前存档对应的缓存目录。
- 包括该存档的静态预览和全部地图块缓存。
- 不影响其他存档，也不修改 Minecraft 存档文件。
- 清理成功后清空内存地图块和当前画面，并重新请求当前视口。
- 保留当前维度、显示层、中心位置和缩放等级。
- 传送门随地图块重新生成。
- 已加载的玩家集合继续作为运行时固定标记使用，本操作不重新扫描 `playerdata`。

### 清理前统计

- 点击按钮后在后台统计当前存档缓存的文件数量与总字节数。
- 统计期间禁用按钮，避免重复任务。
- 统计范围必须与随后允许删除的当前存档缓存目录完全一致。
- 缓存目录不存在时显示为 0 个文件、0 B，仍可确认并执行重新加载。
- 统计失败时恢复按钮，显示错误，不直接执行删除。

确认窗口显示：

- 当前存档名称。
- 缓存文件数量。
- 人类可读容量。
- 将删除静态预览和地图块缓存的说明。
- 清理成功后会重新加载当前视口的说明。
- 不影响存档和其他世界的只读安全说明。

### 清理结果

缓存清理器返回实际成功删除的文件数量与字节数，而不是仅复用清理前估算值。

- 全部成功：显示“已清理 X 个文件，释放 Y，正在重新加载”。
- 部分文件删除失败：显示失败原因和已经释放的数量；由于缓存已经发生变化，仍清空内存地图块并重新加载当前视口。
- 清理前即无缓存：显示“没有可清理的缓存，正在重新加载”。
- 整个任务未删除任何内容且失败：保留当前画面，不触发重新加载。

删除过程继续执行严格路径保护：

- 目标必须位于便携程序缓存根目录之下。
- 目标不得等于缓存根目录。
- 不跟随符号链接访问缓存目录之外的内容。
- 任何路径边界验证失败都拒绝执行。

## 四、组件边界与数据流

### 地图加载控制

`MapViewerController` 继续负责当前世界上下文、请求调度、状态栏和导出可用性。它维护地图块自动尝试次数与失败集合，并向 `MapViewport` 提供失败状态和单块重试回调。

`MapTileScheduler` 继续负责优先级和后台任务，不引入无上限重试。`MapTileService` 继续负责内存、磁盘命中与生成，不保存界面失败覆盖层。

### 视口交互

`MapViewport` 负责：

- 绘制失败覆盖层。
- 失败块和标记的命中测试。
- 区分点击与拖动。
- 展示玩家 Tooltip 和短时高亮。
- 在现有 `1 方块/像素` 数据级别之上执行 `2×` 和 `4×` 视觉放大。

视口只发出“重试这个键”或“用户选择这个标记”的明确事件，不自行创建后台任务。

### 高倍率视觉缩放

高倍率缩放只改变视口显示比例，不增加新的世界采样精度：

- 现有离散数据级别保持 `16`、`8`、`4`、`2`、`1 方块/像素`。
- 在 `1 方块/像素` 之后增加两个视觉级别：
  - `2×`：`0.50 方块/屏幕像素`，每个方块显示为 `2×2` 屏幕像素。
  - `4×`：`0.25 方块/屏幕像素`，每个方块显示为 `4×4` 屏幕像素。
- 滚轮和 `+`、`-` 按钮按 `16 → 8 → 4 → 2 → 1 → 0.50 → 0.25` 顺序切换，反向操作按相反顺序返回。
- 两个高倍率级别继续请求、复用和缓存 `1 方块/像素` 地图块；`MapTileKey`、磁盘目录和缓存文件格式保持不变。
- 高倍率绘制使用像素化放大，不进行会模糊方块边界的平滑重采样。
- 缩放动画继续使用现有对数插值，并保持鼠标指针所指世界坐标稳定。
- 拖动、标记绘制与命中、失败块点击、当前视口 PNG 导出都使用当前视觉比例换算。
- 状态栏分别显示 `0.50 方块/像素` 和 `0.25 方块/像素`。
- 到达 `0.25 方块/像素` 后继续放大不改变视口，也不重复请求地图块。
- “重置视图”和玩家列表定位仍使用现有默认 `2 方块/像素`，不自动进入高倍率级别。

### 缓存维护

缓存统计与删除属于缓存模块：

- 统计返回不可变的文件数量和总字节数。
- 删除返回实际删除结果和可选失败信息。
- 控制器只负责后台执行、确认窗口、状态反馈和成功后的视口刷新。

## 五、错误处理

- 自动重试异常：记录地图块键和异常摘要，第二次失败后进入可点击状态。
- 手动重试异常：回到可点击失败状态，不影响其他块。
- 过期任务完成：通过当前上下文校验丢弃，不更新画面、失败数量或导出状态。
- 玩家身份信息缺失：继续使用现有短 UUID 回退。
- 玩家维度不可用：保持现有提示，不改变当前视图。
- 缓存统计失败：不显示不可靠容量，不执行清理。
- 缓存部分删除：报告实际释放量，刷新当前视口以消除内存与磁盘状态差异。
- 世界在缓存任务期间被切换：任务不得清理新世界，不得刷新新世界视口；只允许按任务启动时捕获的目标世界完成受限操作。

## 六、自动化测试

### 失败地图块

- 首次失败后自动重试一次。
- 第二次失败进入 `FAILED`，不继续循环。
- 点击失败块只提交一个对应键的任务。
- 重复点击在加载期间被抑制。
- 手动失败后可以再次点击。
- 4 像素以内判为点击，超过阈值判为拖动。
- 标记命中优先。
- 同键旧画面可以作为底图，不同键旧画面不可复用。
- 失败数量、状态文本和导出禁用正确。
- 旧上下文结果不会污染当前视图。

### 玩家展示

- 玩家 Tooltip 包含名称、维度 ID 和一位小数坐标。
- 非玩家标记不要求玩家身份信息。
- 玩家列表定位切换到地表总览、默认缩放和玩家中心。
- 玩家开关关闭时定位会自动开启。
- 目标高亮约 3 秒后消失。
- 新选择和世界切换会取消旧高亮。

### 缓存维护

- 统计空目录、单文件、多层目录和大文件容量。
- 统计范围与清理范围一致。
- 只允许当前世界缓存目录。
- 拒绝缓存根目录、越界路径和符号链接越界。
- 返回实际删除文件数与字节数。
- 覆盖全部成功、部分失败、完全失败和无缓存结果。
- 清理后保留当前视图状态并重新请求当前视口。
- 清理操作不重新扫描玩家文件。

### 高倍率视觉缩放

- 缩放级别顺序和两端边界正确。
- `1 → 0.50 → 0.25 方块/像素` 及反向切换正确。
- 高倍率级别始终映射到 `1 方块/像素` 地图块键，不创建新的磁盘缓存级别。
- 指针锚点在动画前后对应同一世界坐标。
- 高倍率下拖动、标记命中和失败块点击坐标换算正确。
- 到达最大级别后继续放大不会改变状态或重复触发地图块请求。
- 状态栏文本、重置视图、玩家定位和 PNG 导出行为正确。

### 回归

- 运行完整自动化测试套件。
- 保持现有地表、高度带、缩放、拖动、重置、玩家定位、传送门和 PNG 导出测试通过。

## 七、真实环境验收

### 真实存档

- 使用包含主世界、下界和末地的真实存档。
- 使用包含多人 `playerdata` 和名称缓存的真实存档。
- 使用包含传送门和缺失地图块场景的存档。
- 游戏与可能写入这些存档的服务器必须关闭。
- 验收前后对测试存档全部普通文件生成递归 SHA-256 清单并比较，证明文件内容未变化。
- 同时记录文件数量、总容量和验收时间，避免把后续环境变化误判为程序写入。

### 30 分钟交互压力

连续约 30 分钟反复执行：

- 快速滚轮缩放。
- 进入 `2×`、`4×` 高倍率级别并逐级缩回。
- 连续拖动及拖出、拖回地图。
- 切换维度。
- 切换地表总览和高度带。
- 玩家列表跨维度定位。
- 标记开关切换。
- 失败块点击重试。
- 缓存清理并重新加载。

验收期间检查：

- 无黑色空 Tooltip 或异常小框。
- 无错位地图块和旧请求覆盖。
- 高倍率下方块边界清晰，无平滑重采样造成的模糊或接缝。
- 无无限重试或重复任务堆积。
- 无持续异常内存增长、线程增长、界面卡死或崩溃。
- 正常地图块不被单块失败阻塞。

### V0.2.1 升级

- 复制一份 V0.2.1 便携版目录作为升级测试样本，不修改原始发布包。
- 使用 V0.3.1 候选程序验证原有运行目录、日志和缓存环境下能够启动。
- 验证旧静态预览或缓存不会导致崩溃，当前世界缓存可以安全清理并重新生成。
- 验证 Minecraft 目录选择、世界列表和基础地图浏览正常。

## 八、软件包与发布门槛

1. 开发阶段的代码和文档全部保留在工作区，不进行阶段性提交。
2. 自动化、真实存档、代码审查和 30 分钟交互验收通过后，可以从当前工作区构建仅供人工验收的 V0.3.1 候选便携包。
3. 候选包不创建标签、不上传 GitHub Release。
4. 开发者完成人工验收并明确确认 V0.3.1 开发完成后，更新路线图、进度和 README，执行最终整体审查。
5. 符合 Rule 18 后创建统一版本提交。
6. 从该确定提交重新执行干净构建，生成最终 Windows x64 便携包，并记录提交、构建时间、文件大小和 SHA-256。
7. 最终包启动验证成功后，仍需开发者再次明确确认发布，才允许推送版本提交、创建标签和发布 GitHub Release。
