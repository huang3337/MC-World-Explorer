# V0.4 三维技术可行性验证设计

## 文档状态

- 状态：设计与实施验证已完成，渲染后端已确认为 LWJGL/OpenGL
- 日期：2026-08-01
- 版本范围：V0.4 内部技术验证
- 当前稳定基线：V0.3.1 二维地图
- 发布属性：不承诺用户可见功能，不发布正式 V0.4 软件包

## 背景

V0.3.1 已形成稳定的二维地图浏览能力，但当前区块解析模型只向二维采样流程提供方块名称，并未保留调色板条目中的完整 `Properties`。V0.4 的任务不是直接把三维视图接入主界面，而是用真实存档区块验证以下风险：

1. 能否可靠读取完整垂直区块数据和方块状态。
2. 能否生成几何正确、规模可控的简化体素网格。
3. JavaFX 3D 与 LWJGL/OpenGL 在当前 Java 21、Windows x64 和便携打包条件下各自表现如何。
4. 是否存在阻止后续三维路线继续推进的性能、兼容性或资源释放问题。

两个候选后端完成同条件验证后，开发者已确认选择 LWJGL/OpenGL，并将该重大技术决策记录为 `docs/decisions/DECISION-007.md`。

## 目标

- 通过命令行指定真实存档、维度和区块坐标。
- 读取目标区块完整垂直范围，并保留方块名称和全部属性。
- 使用四个水平邻区块完成目标区块边缘的面剔除。
- 将所有普通非空气方块简化为不透明立方体，优先验证几何正确性。
- 按已确认的空气接触规则简化原版水和熔岩。
- 用统一网格快照分别驱动 JavaFX 3D 和 LWJGL/OpenGL 独立原型。
- 提供一致的轨道相机旋转、俯仰、缩放和重置操作。
- 记录加载、网格生成、首帧、帧时间、内存和资源释放数据。
- 验证两个原型在 Windows x64 下生成非发布用便携应用映像的可行性。

## 非目标

- 不接入现有主界面，不改变二维地图默认行为。
- 不实现自由飞行、动态区块加载或大范围连续世界浏览。
- 不实现原版纹理、复杂方块模型、透明材质、动画或生物群系染色。
- 不模拟流体高度、流向、斜面或动态效果。
- 不可靠识别 Mod 流体，不以名称猜测未知流体。
- 不设定最终发布版本的视距、帧率或硬件门槛。
- 不在完成对照实验前确定最终渲染后端。
- 不生成或发布正式 V0.4 软件包。

## 总体架构

```text
命令行参数
    |
    v
只读区块读取 ---- 四个水平邻区块
    |                  |
    +--------+---------+
             v
       完整方块状态模型
             |
             v
        统一网格生成器
             |
             v
         渲染快照
          /     \
         v       v
 JavaFX 3D     LWJGL/OpenGL
         \       /
          v     v
       统一测量与对比
             |
             v
    用户确认后端并记录决策
```

V0.4 新增独立的试验代码边界。现有 `ParsedChunkSections`、`ChunkSectionView` 和二维预览调用方不改变公开行为；完整状态解析不能通过破坏 V0.3.1 数据契约来实现。

## 启动入口与参数

JavaFX 3D 与 LWJGL/OpenGL 使用不同启动类和不同进程，但共享同一参数解析器。参数为：

```text
--world <存档目录>
--dimension <维度 ID>
--chunk-x <整数>
--chunk-z <整数>
[--report <JSON 文件>]
```

- `--world` 必须指向可读的 Minecraft Java 版存档目录。
- `--dimension` 使用现有 `WorldDimensionDiscovery` 发现并规范化的维度 ID，包括已支持的 Mod 维度目录。
- 区块坐标允许负数。
- `--report` 可选；未指定时只向控制台输出结果。
- 所有存档文件只读打开。V0.4 不向存档目录写入任何内容。

## 共享数据模型

### 完整方块状态

完整状态对象是不可变值，至少包含：

- 方块名称 `Name`。
- `Properties` 中的全部字符串键值。
- 经过稳定排序的属性表示，以支持相等比较、日志和测试。

现代根级 `sections/block_states` 与旧版 `Level/Sections` 调色板都进入同一模型。调色板索引解码继续兼容按 `long` 填充和跨 `long` 紧凑存储。

### 区块体积查询

区块体积查询使用世界方块坐标，并负责：

- 目标区块全部 Section Y 范围。
- 负 Y 和负区块坐标的 `floorDiv`、`floorMod` 换算。
- 四个水平邻区块的边界方块查询。
- 缺失 Section 返回空气。

只有目标区块产生几何。邻区块不进入渲染快照。

### 方块分类

分类器只做 V0.4 所需的最小判断：

- 空气：`minecraft:air`、`minecraft:cave_air`、`minecraft:void_air`。
- 原版流体：可靠识别 `minecraft:water` 与 `minecraft:lava`。
- 含水方块：保留 `waterlogged=true`，但按普通方块处理。
- 其他全部非空气方块：普通不透明立方体。
- 未知 Mod 流体：按普通不透明立方体处理，不进行启发式猜测。

## 网格生成规则

### 普通方块

- 普通非空气方块占据完整单位立方体。
- 只有相邻位置为空气时，才生成对应方向的面。
- 相邻普通方块、流体或其他非空气方块会遮挡该面。
- 玻璃、树叶、栅栏、台阶等复杂或透明方块在 V0.4 中仍按完整不透明立方体处理。

### 原版流体

- 水和熔岩只生成直接接触空气的外壳面。
- 相邻同种或不同种流体时，不生成流体交界面。
- 流体与固体相邻时，不生成流体面。
- 垂直连续流体内部面被剔除，侧面接触空气时仍可形成连续瀑布外壳。
- 流体统一使用完整单位方块边界，不读取 `level` 或 `falling` 改变表面高度。
- 含水方块不生成额外流体壳。

### 区块边界

- 目标区块四个水平边缘通过相邻区块判断是否生成面。
- 正常不存在的邻区块视为空气。
- 存在但无法解析的邻区块视为空气，同时将结果标记为边界数据不完整。
- 垂直范围外和缺失 Section 视为空气。

### 网格快照

网格生成器输出不含 JavaFX 或 OpenGL 类型的不可变快照。快照按颜色分批，至少包含：

- 顶点位置。
- 顶点或面法线。
- 三角形索引。
- 批次颜色。
- 包围盒。
- 方块数、可见面数、顶点数和索引数。
- 区块读取、状态解析和网格生成耗时。
- 边界数据是否完整及对应警告。

禁止为每个方块创建独立渲染节点。两个后端必须消费同一份快照，避免解析或网格差异污染后端比较。

## 颜色和光照

- 已知方块颜色复用现有 `BlockColorPalette` 的已知映射。
- 水和熔岩使用现有固定颜色。
- 现有调色板对未知方块使用哈希颜色；V0.4 三维适配层覆盖这一行为，统一使用中性灰色。
- 不改变 V0.3.1 二维地图的配色结果。
- 两个后端使用基础环境光和单个方向光表达立体层次。
- 不要求两个后端像素级一致，但几何轮廓、颜色类别和观察方向必须可比较。

## 相机与交互

- 使用围绕固定焦点旋转的轨道相机，不支持自由飞行。
- 默认焦点为目标区块非空气几何包围盒中心；空区块使用区块中心。
- 初始距离根据包围盒自动计算，使完整目标区块进入画面。
- 鼠标左键拖动控制水平旋转和俯仰。
- 滚轮连续缩放。
- 俯仰角受限，防止相机翻转。
- `R` 恢复统一默认视角。
- `Esc` 关闭窗口。
- 两个后端使用相同的初始角度、缩放范围和输入灵敏度。

## JavaFX 3D 后端

- 启动时检查 `Platform.isSupported(ConditionalFeature.SCENE3D)`。
- 使用启用深度缓冲的 `SubScene` 和 `PerspectiveCamera`。
- 每个颜色批次转换为一个 `TriangleMesh` 和 `MeshView`，避免逐方块节点。
- 开启背面剔除，并使用基础环境光和方向光。
- 关闭窗口后移除场景和网格引用，终止试验进程。
- 不支持 `SCENE3D` 时明确失败，不自动切换后端。

## LWJGL/OpenGL 后端

- 首轮以 OpenGL 3.3 Core 为兼容基线。
- 使用 GLFW 创建独立窗口和输入回调。
- 使用 VAO、VBO、EBO 和最小顶点/片元着色器上传并绘制颜色批次。
- 开启深度测试和背面剔除。
- 相机矩阵与 JavaFX 后端保持相同语义。
- 关闭时显式删除 GPU 缓冲、顶点数组、着色器程序、GLFW 回调和窗口，再终止 GLFW。
- OpenGL 3.3 上下文创建失败时明确失败，不自动切换后端。

## 错误处理

### 必须终止

- 参数缺失、格式错误或存档目录不可读。
- 指定维度未发现或 Region 目录不可读。
- 目标区块不存在、损坏或布局不受支持。
- 目标区块调色板、属性或方块状态存储损坏。
- 共享网格包含非法索引、非有限坐标或无法满足后端输入约束。
- 所选后端的必要图形能力或本地库不可用。

错误信息应包含阶段、存档路径、维度 ID、区块 X/Z；Section 相关错误还应包含 Section Y。

### 允许继续但必须警告

- 水平邻区块存在但无法读取或解析。
- 未知方块名称或未知 Mod 流体。
- 可选 JSON 报告无法写入时，渲染可继续，但进程最终结果必须标记报告失败。

警告不能被吞掉，必须同时进入控制台输出和可选报告。

## 测量与报告

两个后端在相同输入、窗口尺寸、相机参数和操作脚本下测试。记录：

- 区块读取耗时。
- 完整状态解析耗时。
- 网格生成耗时。
- 后端上传或网格对象构建耗时。
- 从进程启动到首帧显示的时间。
- 方块数、可见面数、顶点数和索引数。
- 稳定运行时的帧时间分布和换算帧率。
- JVM 堆使用变化。
- Windows 进程工作集的外部采样结果。
- 静置和持续旋转缩放期间是否出现持续内存增长。
- 关闭窗口后进程是否正常退出。

性能测试区分一次冷启动与预热后的重复运行，不将两类结果混合为单一平均值。V0.4 不预设硬性 FPS 合格线；数据用于识别明显风险和支持后端决策。

## 测试设计

### 自动测试

- 现代和旧版区块调色板中的完整属性保留。
- 单一调色板、填充存储和紧凑跨 `long` 存储。
- 负 Section Y、负区块坐标及世界坐标换算。
- 普通方块六面剔除。
- 水、熔岩、连续流体、流体与固体、含水方块规则。
- 四个水平邻区块边界剔除。
- 缺失和损坏邻区块的结果标记。
- 网格索引范围、三角形绕序、法线、包围盒和统计一致性。
- 参数校验和错误上下文。
- JSON 报告字段及稳定序列化。

### 真实存档验证

固定选择少量真实区块，至少覆盖：

- 普通地表和建筑。
- 内容较丰富的垂直范围及负 Y。
- 水体、瀑布或熔岩。
- 至少一个需要水平邻区块参与剔除的边界。

每个区块在两个后端中使用相同参数，并从多个观察方向检查几何、流体壳和边界。

### 交互与稳定性

- 静置运行一段固定时间。
- 连续执行旋转、俯仰和缩放。
- 多次执行视角重置。
- 关闭窗口并确认无残留进程或后台线程。
- 记录崩溃、明显卡顿、渲染空白、面绕序错误和持续内存增长。

## 便携打包验证

- 两个后端分别生成非发布用 `jpackage app-image`。
- JavaFX 原型确认所需 JavaFX 模块随运行时提供。
- LWJGL 原型确认 Windows x64 本地库和许可证信息完整。
- 从与源码构建目录不同的位置启动应用映像。
- 使用真实区块完成显示、交互和正常退出的冒烟测试。
- 不覆盖 V0.3.1 正式包，不创建 GitHub Release。

## 验收条件

V0.4 技术验证至少满足：

1. 至少一个候选后端可以显示真实目标区块的完整垂直简化几何。
2. 完整方块状态得到保留，负 Y、负坐标和水平区块边界正确处理。
3. 普通方块和原版流体遵守已确认的面生成规则。
4. 轨道旋转、俯仰、缩放和重置稳定可用。
5. 测量数据能够区分共享管线耗时和后端耗时。
6. 稳定性测试未发现持续内存增长或无法结束的进程。
7. 至少一个后端的 Windows x64 便携应用映像可启动和退出。
8. 形成 JavaFX 3D 与 LWJGL/OpenGL 的对比结论，包括限制和残余风险。

通过这些条件不等于自动采用任何后端，也不等于 V0.4 成为面向用户的发布版本。

## 重大决策门禁

完成两个候选后端的验证后，必须暂停开发并向用户提交：

- 相同真实区块下的功能结果。
- 加载、网格、首帧、帧时间和内存数据。
- Windows x64 便携打包结果。
- 已知限制、失败环境和后续架构影响。
- 推荐后端及不采用另一后端的理由。

只有用户明确确认后，才能：

1. 在 `docs/decisions/` 新增正式决策记录。
2. 将选定后端作为后续三维开发基础。
3. 调整路线或进入依赖该决定的后续阶段。

该门禁已于 2026-08-01 完成：开发者明确选择 LWJGL/OpenGL。JavaFX 继续承担现有二维主界面，JavaFX 3D 对照原型暂时保留为验证证据但不继续扩展。V0.4 整体完成、提交和推送仍受各自确认门禁约束。

## 已确认结论汇总

- 首轮使用真实单区块端到端验证。
- 存档、维度和区块坐标由命令行指定。
- 目标区块渲染，四个水平邻区块只参与边界剔除。
- 所有普通非空气方块简化为不透明立方体。
- 原版水和熔岩只显示直接暴露于空气的外壳面。
- 不模拟流体高度和斜面。
- 含水方块按普通不透明方块处理。
- 未知 Mod 流体按普通不透明方块处理。
- 颜色复用现有已知映射，三维未知方块使用中性灰色。
- 使用轨道相机，不支持自由飞行。
- 不设硬性 FPS 门槛，保留完整测量数据。
- 对比 JavaFX 3D 与 LWJGL/OpenGL；jMonkeyEngine 仅作为两者均不理想时的备选。
- 最终后端已由开发者确认为 LWJGL/OpenGL，并记录为 `DECISION-007`。
