# V0.3 多人玩家标记与玩家列表设计

## 状态

- **设计日期**：2026-07-29
- **确认状态**：开发者已确认
- **适用版本**：V0.3
- **提交限制**：遵守 Rule 18，不提交、不推送、不打包

## 背景

V0.3 当前只从 `level.dat -> Data.Player` 取得一个玩家位置。多人游玩过的存档通常还会在 `playerdata/<UUID>.dat` 保存各玩家最后一次写盘的位置、维度和状态。

真实样本“刀剑”包含四个有效玩家数据文件，并能通过实例目录的 `usernamecache.json` 和 `usercache.json` 将 UUID 映射为玩家名称。开发者确认 V0.3 应显示全部可读取玩家，并提供玩家列表用于跨维度定位。

同次人工体验还发现：地图 Canvas 永久安装了空文本 Tooltip，鼠标滚轮缩放后可能显示无文字的黑色小框。该问题作为 V0.3 界面缺陷一并修复。

## 已确认范围

- 只读解析当前存档 `playerdata/*.dat`。
- 在现有绿色“玩家”开关下显示全部有效玩家标记。
- 工具栏增加“玩家列表”菜单按钮。
- 点击玩家名称后自动切换到玩家最后所在维度。
- 跳转后固定使用地表总览、`2 方块/像素`，并以玩家 X/Z 为中心。
- 修复空 Tooltip 黑框。
- 保持现有玩家与传送门绘制顺序，不增加标记避让或聚合。

## 不属于本次范围

- 在线服务器实时位置。
- 玩家轨迹、历史位置或登录时间线。
- 皮肤头像、在线状态或网络查询。
- 写入或修复 `playerdata`。
- 修改玩家和传送门重叠时的绘制优先级。

## 方案选择

采用独立多人玩家读取器，不把玩家集合解析塞入 `LevelDatReader`。

备选方案：

1. 扩展 `LevelDatReader` 和 `WorldInfo`：文件较少，但会把世界基础信息、玩家集合和名称缓存解析混在一起。
2. 展开菜单时临时扫描：初始加载较轻，但会重复读取磁盘，并增加菜单交互中的错误处理。

独立读取器可以保持现有单玩家信息兼容逻辑不变，并让玩家文件解析、名称回退和损坏隔离分别测试。

## 数据模型

新增不可变 `PlayerLocation`：

- UUID
- 显示名称
- 维度 ID
- X/Y/Z
- 玩家文件最后修改时间

位置保留 NBT 中的双精度值；生成地图标记时沿用现有规则向下取整。UUID 来自文件名，不信任 NBT 内部可选字段。

## 玩家数据读取

新增 `PlayerDataReader`：

1. 枚举 `world/playerdata` 下文件名为标准 UUID 的 `.dat` 文件。
2. 使用 Adventure NBT 以 GZIP 和固定读取上限解析。
3. 要求 `Pos` 至少包含三个有限数值，`Dimension` 能转换为非空维度 ID。
4. 单个文件损坏、字段缺失或数值非法时记录警告并跳过，不中断其他玩家。
5. 不修改文件，不创建存档内缓存。

如果至少读取到一个有效 `playerdata`，地图使用该集合生成玩家标记；如果目录不存在或没有有效结果，回退到现有 `level.dat` 单玩家位置。

## 名称解析

按以下顺序只读查找：

1. 世界目录。
2. 世界目录的父目录。
3. 世界目录的祖父目录。

每层依次读取 `usernamecache.json`、`usercache.json`。查找范围固定，不递归扫描磁盘。

当前项目不为此引入新的 JSON 依赖；名称解析器只接受这两种已知缓存结构和标准 UUID。字符串转义异常、JSON 损坏或名称为空时忽略该条目。无法取得名称时显示 UUID 前八位。

## 加载与状态

选择世界后，玩家读取与维度发现保持在后台执行，不阻塞 JavaFX 线程。切换到其他世界时通过世界上下文编号拒绝旧结果。

玩家列表属于当前世界的运行时数据，不写入地图瓦片缓存。重新选择或重新扫描世界后读取磁盘中的最新玩家位置。

## 玩家菜单

在现有“玩家”标记开关旁增加 `MenuButton`：

- 无世界时禁用并显示“玩家列表”。
- 加载完成后显示“玩家列表（数量）”。
- 条目按显示名称排序，格式为 `玩家名（维度显示名）`。
- 名称相同时追加 UUID 前八位。
- 未发现对应维度时保留条目并标记“维度不可用”。

点击有效条目后关闭菜单并执行定位。

## 跨维度定位

玩家跳转使用一个明确的待执行导航对象，包含玩家和目标维度：

1. 根据维度 ID 查找当前世界已发现的 `WorldDimension`。
2. 找不到时不改变当前地图，在状态栏提示目标维度不可用。
3. 找到后自动选择目标维度。
4. 如果维度高度仍在后台解析，保留待执行导航，等待 `DimensionState` 激活。
5. 激活后强制设置 `PreviewLayer.surfaceOverview()`。
6. 将视口中心设置为玩家 X/Z，并将离散与视觉缩放同时设置为 `MapZoomLevel.BLOCKS_2`。
7. 更新工具栏、固定标记、瓦片请求和状态栏。

玩家跳转不改变该维度原有默认重置中心；之后点击“重置视图”仍回到存档原有默认中心。

## Tooltip 修复

不再给 Canvas 永久安装一个可能为空的 Tooltip。

- 鼠标命中可见标记时，设置文本并在指针附近显示。
- 未命中标记、鼠标离开 Canvas、拖动或切换世界时立即隐藏。
- 空文本永远不调用 `show`。

## 错误处理

- 玩家目录不存在：视为没有多人数据，使用单玩家回退。
- 单个玩家文件损坏：记录文件名并跳过。
- 名称缓存损坏：保留坐标，名称回退短 UUID。
- 玩家维度不存在：菜单保留信息，点击时给出明确状态。
- 世界切换期间旧任务完成：通过上下文编号丢弃。

## 测试与验收

- 玩家 NBT：正常坐标、Mod 维度、非法 UUID、缺少字段、非有限数值、损坏 GZIP。
- 名称缓存：两种结构、优先级、转义、损坏文件和短 UUID 回退。
- 玩家集合：有效 `playerdata` 优先，空目录回退 `level.dat`。
- 菜单模型：排序、重复名称、维度显示和不可用状态。
- 导航：跨维度、等待异步激活、地表总览、`2 方块/像素`、玩家中心。
- Tooltip：未命中和离开时不会显示空提示。
- 真实“刀剑”样本：读取四名玩家和对应名称，并比较 `level.dat`、全部 `playerdata` 的大小、修改时间和 SHA-256，证明存档只读。
- 完整测试、Rule 16 审查和 JavaFX 启动检查。

## 完成标准

- 地图能显示当前存档全部有效玩家位置。
- 玩家列表名称和维度可识别。
- 点击任意可用玩家能跨维度跳转到地表总览，以默认 `2 方块/像素` 居中。
- 无玩家数据、损坏文件和未知维度不会导致界面崩溃。
- 缩放和普通悬停不再出现空白黑色 Tooltip。
- 自动化与真实存档验收通过，存档文件保持不变。
