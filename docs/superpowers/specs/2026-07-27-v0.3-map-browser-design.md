# V0.3 地图浏览器设计

## 状态与范围

本设计由开发者于 2026-07-27 确认，适用于 V0.3 地图浏览器。

V0.3 在 V0.2.1 统一维度图层系统基础上，将固定中心的单张预览升级为按需加载的交互地图。范围包括地图拖动、五级缩放、X/Z 坐标定位、玩家/出生点/下界传送门标记、当前世界缓存清理和当前视口 PNG 导出。

本设计不包含 Mod 资源包或纹理加载、三维体素浏览、自动巡航、动态壁纸、全世界预生成或任何 Minecraft 存档写入。

## 已确认目标

- 用户可以在任意已有区块间自由拖动浏览，地图允许完全离开视口，不设置边缘限制。
- 地图按当前视口分块渐进加载；已有缓存立即显示，未缓存地图块在后台生成。
- 地图支持 `1、2、4、8、16 方块/像素` 五个离散缩放级别，最高精度为 `1 方块 = 1 像素`。
- 鼠标滚轮围绕指针所在世界坐标缩放，同时提供缩小、放大和重置视图按钮。
- 重置视图恢复默认缩放，并回到当前维度首次打开时的默认中心。
- 坐标定位只输入整数 X/Z，在当前维度和当前图层内跳转，不改变 V0.2.1 的高度滑块。
- 玩家、出生点和下界传送门标记默认显示，并可分别隐藏。
- 当前世界缓存默认长期保留，界面提供明确的“清理当前世界缓存”按钮。
- PNG 导出采用所见即所得方式，导出当前完整视口、当前缩放、当前图层和当前可见标记。

## 总体架构

V0.3 采用多级地图块架构，完整决策见 `docs/decisions/DECISION-004.md`。

### `MapViewport`

JavaFX 地图视口负责：

- 保存世界中心 X/Z 和当前方块/像素级别。
- 处理鼠标拖动、滚轮缩放和缩放按钮。
- 计算屏幕坐标与世界坐标的双向转换。
- 显示地图块、加载占位、错误占位和标记叠加层。
- 在尺寸变化时保持世界中心稳定，不自行读取 Region 文件。

### `ViewportCoordinator`

视口协调器负责：

- 根据视口尺寸、中心和缩放级别计算当前可见地图块。
- 在拖动停顿约 `200ms` 后提交新请求。
- 让视口中心附近的地图块优先。
- 取消尚未开始且已经离开视口的低优先级任务。
- 使用请求编号阻止旧世界、旧维度或旧图层结果覆盖当前画面。

### `TileScheduler`

地图块调度器负责限制后台并发，并按以下顺序取得地图块：

1. 本次运行的内存缓存。
2. 通过来源校验的磁盘缓存。
3. 后台读取 Region 并生成新地图块。

初始实现最多同时执行两个生成任务。该数值可以根据自动化和真实存档性能结果在 V0.3 内调整，但不得取消并发上限。

### 地图块服务

新增独立的地图块身份、缓存、生成和来源校验组件，继续复用现有能力：

- `WorldDimension` 和 `PreviewLayer`：维度与地表/高度带语义。
- `RegionFileReader` 和 `SurfaceSampler`：只读 Region、区块和方块列解析。
- `BlockColorPalette` 和现有渲染规则：方块颜色及稳定未知方块回退色。
- `PortablePaths`：程序根目录和严格便携存储边界。

`MainController` 只负责选中世界、维度、图层和顶层命令，不继续承载地图平移、缩放、任务队列和地图块缓存内部状态。

## 地图块模型

每个地图块固定为 `256 × 256` 像素，地图块键至少包含：

- 世界稳定标识。
- 维度 ID。
- 图层类型和高度范围。
- 方块/像素级别。
- 地图块 X/Z 坐标。
- 渲染版本。

单个地图块在五级缩放下分别覆盖 `256、512、1024、2048、4096` 方块。负世界坐标必须使用向下取整的地图块计算，确保原点两侧没有重叠或空隙。

缩放时先取得鼠标指针对应的世界坐标，再改变缩放级别并调整视口中心，使该世界坐标在屏幕上的位置保持不变。缩放只使用五个离散级别，不产生任意比例的模糊中间缓存。

内存缓存采用有上限的最近使用集合，初始上限为 128 个已解码地图块。被内存释放的地图块仍保留磁盘缓存，拖回后只需读取本地 PNG，不重新解析存档。

## 磁盘缓存与失效

所有缓存继续写入程序根目录 `cache/`，不得写入 AppData 或 Minecraft 存档。建议结构：

```text
cache/
└─ 世界标识/
   └─ map-v03/
      └─ 维度标识/
         └─ 图层标识/
            └─ bpp-1/
               └─ x-0/
                  ├─ tile-0--1.png
                  └─ tile-0--1.json
```

每个 PNG 配套保存元数据，记录地图块身份、渲染版本，以及覆盖范围内相关 Region 文件的存在状态、大小和最后修改时间。

读取磁盘缓存时重新取得对应 Region 状态：

- 文件新增、删除、大小变化或修改时间变化时，该地图块失效。
- 只让覆盖变化 Region 的地图块失效，其他区域继续复用。
- 玩家位置和出生点在重新打开存档时重新读取，不依赖地图块缓存。
- 损坏 PNG 或元数据自动删除并重新生成一次。

PNG 和元数据先写入同目录临时文件，再使用原子替换写入最终位置。缓存校验采用大小和修改时间，不为正常浏览计算 Region SHA-256。

有效缓存不自动清理。界面的“清理当前世界缓存”按钮在二次确认后删除当前世界的所有维度、图层和缩放级别缓存，包括该世界已有的 V0.2.1 静态预览缓存，但不影响其他世界。清理成功后重新生成当前视口；清理失败时保留内存画面并显示失败位置。

## 地图生成与渐进显示

地图块生成继续遵守当前图层语义：

- `SURFACE_OVERVIEW` 在完整垂直范围内寻找最高可见地表。
- `HEIGHT_BAND` 只在当前 32 格高度带内寻找可通行地面。
- 缺失区块使用固定深色空白，不伪造地形，也不计为错误。
- 单个损坏或不支持区块只影响当前地图块的局部结果，不中止其他地图块。

高缩放级别按对应方块范围生成确定性的低分辨率地图块，不依赖系统图片平滑缩放。已有地图块逐块显示；未完成区域显示稳定占位，生成一块替换一块。拖动和缩放期间 JavaFX UI 线程不得执行 Region、NBT、PNG 编解码或磁盘缓存操作。

## 标记系统

统一标记模型至少包含类型、维度、世界坐标和显示信息。

- 玩家标记只在玩家当前维度与所选维度一致且坐标可靠时显示。
- 世界出生点标记只在主世界显示。
- 下界传送门不执行全维度预扫描，只扫描当前实际加载地图块覆盖的区块。
- 高度带只记录该高度范围内的传送门；地表总览在当前地图块完整垂直范围内识别传送门。
- 相邻的传送门方块合并为一个标记；跨地图块边界的结果在叠加层按坐标邻接去重。
- 标记默认全部显示，玩家、出生点和传送门可分别隐藏。
- 悬停标记显示类型及 X/Z 坐标；单击标记后将其移动到视口中心。

传送门扫描失败不阻止地形显示，只省略对应标记并记录日志。

## 界面与交互

世界预览页使用已确认的顶部双层工具栏：

第一层保留 V0.2.1 的维度、地表总览和高度滑块。

第二层依次提供：

- X、Z 输入框和定位命令。
- 玩家、出生点、传送门三个显示开关。
- 缩小、放大和重置视图。
- 清理当前世界缓存。
- 导出当前视口 PNG。

地图区域占据其余可用空间。状态区显示当前中心 X/Z、方块/像素级别、已完成/可见地图块数量和局部失败数量。

坐标定位只接受整数。无效输入保留当前画面，并在输入框附近显示简短错误。定位成功后把目标坐标置于视口中心，并按当前缩放、维度和图层加载。

## 导出

当前视口所有可见地图块完成前禁用导出。完成后按视口实际像素尺寸合成 PNG，并包含当前开启的标记，不包含工具栏和状态文字。

导出继续复用 V0.2 的规则：

- 默认写入程序根目录 `exports/`。
- 不覆盖已有文件。
- 默认目录不可用时只能由用户明确选择其他位置。
- 禁止写入当前 Minecraft 世界目录及其后代目录。
- 导出失败不得破坏缓存源文件。

## 错误与取消

- 切换世界、维度或图层时取消旧请求，并由请求编号隔离晚到结果。
- 缓存重建再次失败时显示单块错误占位，其他地图块继续工作。
- 单个区块失败、传送门扫描失败和未知 Mod 方块不得导致整个视口失败。
- 程序根目录不可写、缓存清理失败或导出失败时显示简短错误，并把完整原因写入程序根目录 `logs/`。
- 用户继续拖动时可以丢弃尚未开始的旧地图块请求；已开始的只读任务应响应取消检查。

## 测试与验收

### 自动化测试

- 负坐标地图块计算、五级缩放边界和缩放锚点稳定性。
- 缓存路径隔离、原子替换、损坏恢复和 Region 新增/删除/修改后的精确失效。
- 五级地图块生成、空白区块、取消、传送门连续方块合并和跨地图块去重。
- 视口防抖、任务优先级、并发上限、取消和旧请求隔离。
- 坐标输入、重置视图、标记开关、缓存清理和当前视口合成导出。
- 严格便携路径、导出路径保护和存档只读边界。

### 真实存档与人工验收

- 缓存视口重新打开时直接复用，不重新解析 Region。
- 未缓存区域逐块出现，拖动和缩放期间 JavaFX 界面保持响应。
- 未缓存默认中心优先在三秒内显示可用地图内容；完整视口允许继续渐进生成。
- 主世界、下界、末地和已经支持的 Mod 维度均可浏览。
- 生成前后对相关 `level.dat`、`playerdata` 和 Region 文件比较大小、修改时间及 SHA-256，结果必须完全一致。
- 人工确认拖动、缩放、坐标定位、重置视图、标记、缓存清理和 PNG 导出。
- 按 `DEVELOPMENT_RULES.md` Rule 16 对 V0.3 涉及的生产文件逐一审查。

## 实施顺序

每个开发任务只处理一个明确目标：

1. 地图块坐标与缓存身份。
2. 多级地图块生成和精确失效。
3. 视口调度、渐进加载与取消。
4. JavaFX 平移、缩放和重置视图。
5. 坐标定位与三类标记。
6. 界面内缓存清理和当前视口导出。
7. 自动化测试、真实存档只读验收、人工验收和整体审查。

V0.3 开发期间遵守 Rule 18，不创建阶段性提交。只有开发者明确确认版本完成并完成最终审查后，才允许统一提交、构建和发布。
