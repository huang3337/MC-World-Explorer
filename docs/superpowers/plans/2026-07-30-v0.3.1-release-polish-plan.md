# V0.3.1 发布前完善实施计划

## 状态

- **计划日期**：2026-07-30
- **设计依据**：`docs/superpowers/specs/2026-07-30-v0.3.1-release-polish-design.md`
- **决策依据**：`docs/decisions/DECISION-006.md`
- **执行状态**：功能、172 项自动化测试、真实存档只读验证、开发者人工确认、升级验证、软件包启动、最终整体审查和正式发布均已完成
- **提交与发布**：开发者已明确确认 V0.3.1 完成，并授权统一提交、推送、创建标签和 GitHub Release

## 执行原则

- 每项功能先增加失败测试，再实现最小改动，最后运行相关回归测试。
- 延续现有 JavaFX、后台 `Task`、上下文编号和地图块调度结构，不更换框架或重写地图系统。
- 失败状态、玩家展示信息、缓存维护结果和视觉缩放级别分别建模，不把四类职责堆入同一个类。
- 每完成一个任务只保留工作区变更，不创建阶段性提交。
- 遇到超出已确认设计的重大技术决策时暂停，并请开发者确认后记录新的 decision。

## 任务 1：有限地图块重试状态

### 目标

用独立、可测试的运行时模型表达首次加载、一次自动重试、持续失败和手动重试，避免控制器中散落计数与布尔状态。

### 预计文件

- 新增 `src/main/java/com/mcworldexplorer/map/MapTileLoadTracker.java`
- 新增 `src/test/java/com/mcworldexplorer/map/MapTileLoadTrackerTest.java`

### 测试先行

覆盖：

- 新键从首次加载开始。
- 首次失败返回“自动重试”。
- 第二次失败进入可点击失败状态。
- 失败状态不会自行提交第三次自动任务。
- 手动重试一次只进入一个加载状态。
- 手动重试失败后重新变为可点击。
- 成功后清除失败和加载状态。
- 重复加载开始请求被拒绝。
- 清空上下文后不保留旧键状态。
- 失败数量只统计当前失败键，不统计正在加载键。

### 实现

- 以 `MapTileKey` 为键维护加载状态和自动尝试次数。
- 使用明确枚举表达 `LOADING`、`READY`、`FAILED`，并用返回值表达“自动重试”或“显示失败”。
- 不保存图像，不访问 JavaFX，不创建线程。
- 上下文失效由控制器调用统一清理。

### 验证

```powershell
.\gradlew.bat test --tests com.mcworldexplorer.map.MapTileLoadTrackerTest
```

## 任务 2：控制器接入自动重试与失败状态

### 目标

把有限重试模型接入现有地图块请求流程，保持任务优先级、过期结果隔离和其他地图块并行加载。

### 预计文件

- 修改 `src/main/java/com/mcworldexplorer/ui/MapViewerController.java`
- 修改 `src/test/java/com/mcworldexplorer/ui/MapViewerControllerTest.java`
- 视实现边界补充 `src/test/java/com/mcworldexplorer/map/MapTileSchedulerTest.java`

### 测试先行

覆盖纯逻辑边界：

- 同一个键首次失败后只重新提交一次。
- 第二次失败通知视口进入失败状态。
- 手动重试回调只请求传入键，不刷新全部视口。
- 世界、维度或显示层上下文改变后，旧失败结果被丢弃。
- 当前视口失败数量进入状态文本。
- 当前视口存在加载中或失败键时导出禁用。
- 视口全部目标键完成后导出恢复。

### 实现

- 用 `MapTileLoadTracker` 替换单一 `failedTiles` 计数来源。
- 为首次失败安排一次同优先级单键重试。
- 保留现有 `contextId` 和请求编号校验；重试结果也必须通过相同校验。
- 视口目标键变化时只统计当前目标中的失败键。
- 已离开视口但仍属于当前上下文的失败键保留；再次进入时直接显示失败状态，不自动循环重试。
- 向视口注册单键重试回调。
- 切换世界、维度、显示层或清理缓存时清空对应失败跟踪状态。

### 验证

```powershell
.\gradlew.bat test --tests com.mcworldexplorer.ui.MapViewerControllerTest --tests com.mcworldexplorer.map.MapTileSchedulerTest
```

## 任务 3：失败地图块绘制与点击交互

### 目标

在 `MapViewport` 中绘制失败覆盖层，并稳定地区分标记点击、失败块点击和地图拖动。

### 预计文件

- 修改 `src/main/java/com/mcworldexplorer/ui/MapViewport.java`
- 新增 `src/test/java/com/mcworldexplorer/ui/MapViewportTest.java`
- 必要时新增一个仅包含命中与点击判定的包内纯逻辑辅助类

### 测试先行

覆盖：

- 失败键命中使用对应地图块屏幕边界。
- 同一个 `MapTileKey` 的旧图像可以保留，不同键不能作为失败底图。
- 按下与释放位移不超过 4 像素且命中同一失败块时触发重试。
- 位移超过 4 像素时只拖动，不重试。
- 释放到另一个地图块时不重试。
- 标记和失败块重叠时优先命中标记。
- `LOADING` 状态拒绝重复点击。
- 清空视口和切换状态时清除失败 Tooltip、按压候选和临时高亮。

### 实现

- 视口维护当前目标键中的失败集合和加载集合，不拥有自动尝试次数。
- 在正常地图、局部地图和回退地图之后绘制失败覆盖层。
- 有同键旧图像时保留底图；否则绘制深色占位。
- 使用半透明红色斜线与红色边框表现失败。
- 悬停失败块时显示“加载失败，点击重试”和手形指针。
- 鼠标按下时记录失败块候选与初始坐标，释放时再判断是否为点击。
- 保持现有标记点击居中行为优先。
- 手动重试只通过回调上报 `MapTileKey`，后台任务仍由控制器创建。

## 任务 5：缓存统计与删除结果模型

### 目标

### 预计文件

- 修改 `src/main/java/com/mcworldexplorer/map/WorldMapCacheCleaner.java`
- 修改 `src/test/java/com/mcworldexplorer/map/WorldMapCacheCleanerTest.java`

### 测试先行

覆盖：

- 缓存目录不存在时统计为 0 个文件、0 B。
- 多层目录统计普通文件数量和字节总数。
- 清理返回实际删除数量和字节数。
- 只清理选中世界，其他世界缓存保持不变。

- 不跟随符号链接删除外部文件。

### 实现

- 在 `WorldMapCacheCleaner` 中增加不可变 `Summary` 和 `ClearResult` 结果。

- 遍历时不启用符号链接跟随。
- 删除前读取文件大小，成功删除后才累加实际释放字节。
- 部分失败保存失败数量和首个简短原因，不向界面暴露无必要的完整路径列表。
- 清理目录本身时继续保证目标不等于便携缓存根。

## 任务 6.5：高倍率视觉缩放

### 目标

在不改变地图块采样、缓存键和磁盘格式的前提下，将最大放大倍率从 `1 方块/像素` 扩展到 `2×` 和 `4×`。

### 预计文件

- 新增：`src/main/java/com/mcworldexplorer/map/MapDisplayZoom.java`
- 修改：`src/main/java/com/mcworldexplorer/map/MapViewportState.java`
- 修改：`src/main/java/com/mcworldexplorer/ui/MapViewport.java`
- 修改：`src/test/java/com/mcworldexplorer/map/MapCoordinateModelTest.java`
- 修改：`src/test/java/com/mcworldexplorer/ui/MapViewportTest.java`

`MapZoomLevel`、`MapTileKey`、`MapTileRenderer` 和磁盘缓存路径保持数据级别语义，不加入小数级别。

### 测试先行

增加失败测试覆盖：

- 显示级别顺序为 `16 → 8 → 4 → 2 → 1 → 0.50 → 0.25 方块/像素`。
- `0.50` 和 `0.25` 的来源瓦片级别均为 `MapZoomLevel.BLOCKS_1`。
- 两端继续缩放时返回原级别，不产生新的目标变化。
- 视觉缩放允许范围为 `0.25..16 方块/像素`。
- 高倍率切换前后鼠标指针对应的世界坐标保持稳定。
- 高倍率下视口可见地图块键仍只包含 `BLOCKS_1`。
- 已稳定在高倍率时不被判断为临时缩放画面。
- 重置和玩家列表定位仍恢复 `2 方块/像素`。

### 实现

1. 新增 `MapDisplayZoom`，每个显示级别包含：
   - 当前视觉 `blocksPerPixel`。
   - 对应的来源 `MapZoomLevel`。
   - 前后级别导航和最近级别选择。
2. `MapViewportState` 分别保存：
   - 已确认的显示级别。
   - 动画中的连续视觉比例。
   - 供地图块调度使用的来源瓦片级别。
3. 保留 `zoom()` 作为来源瓦片级别接口，避免改动 `ViewportCoordinator`、`MapTileKey` 和缓存模块。
4. `MapViewport` 的按钮、滚轮归位和缩放动画改为以 `MapDisplayZoom` 为目标。
5. 最终稳定画面关闭图像平滑，保证 `2×`、`4×` 方块边界清晰；动画期间继续平滑过渡。
6. 处于最小或最大显示级别时，继续同方向缩放直接忽略，不触发 `zoomTargetChanged`。
7. 状态栏继续使用现有视觉比例显示，因此自然显示 `0.50` 和 `0.25 方块/像素`。

### 验证

```powershell
.\gradlew.bat test --tests com.mcworldexplorer.map.MapCoordinateModelTest --tests com.mcworldexplorer.ui.MapViewportTest
```

人工快速检查：

- 滚轮和 `+`、`-` 按钮都能进入 `2×`、`4×` 并逐级返回。
- 放大过程中鼠标所指位置不漂移。
- `4×` 稳定画面边缘清晰，没有模糊和瓦片接缝。
- 高倍率下拖动、玩家 Tooltip、标记点击和失败块点击位置正确。
- 重置和玩家列表定位仍回到 `2 方块/像素`。
