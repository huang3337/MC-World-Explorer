# V0.4 三维技术可行性验证实施计划

## 状态

- 计划日期：2026-08-01
- 设计依据：`docs/superpowers/specs/2026-08-01-v0.4-3d-feasibility-design.md`
- 当前稳定基线：V0.3.1 二维地图
- 当前状态：全部任务、解析自检、重大决策、最终整体审查和开发者完成确认均已完成
- 最终渲染后端：LWJGL/OpenGL，见 `docs/decisions/DECISION-007.md`
- 提交约束：V0.4 开发完成并获开发者明确确认前，不创建提交、不推送 GitHub

## 技术基线

- Java 21。
- JavaFX 21，现有 `javafx.controls` 和 `javafx.fxml` 配置保持不变。
- LWJGL 使用当前已核对的稳定版 `3.4.1`，只引入 core、GLFW、OpenGL 和 Windows x64 natives。
- OpenGL 首轮基线为 3.3 Core。
- Adventure NBT 和现有 Region 读取器继续负责只读存档输入。
- 两个候选后端只在 `experimental.v04` 边界内使用，不改写 V0.3.1 主界面入口。

## 执行原则

- 每个共享逻辑任务先写失败测试，再做最小实现，最后运行目标测试。
- 不为每个方块创建渲染节点，不实现贪心网格、纹理、透明排序或动态区块加载。
- 不为了复用而重构现有 `ParsedChunkSections` 和 `ChunkSectionView`；V0.4 先建立隔离模型，后端确定后再评估长期归属。
- 存档始终只读；报告、截图和测量数据只写入显式指定路径或项目 `build/` 目录。
- 每完成一个任务保留工作区变更，不做阶段性提交。
- 发现需要改变已确认架构、替换候选后端或扩大 V0.4 范围时立即暂停并请求确认。

## 任务 1：完整方块状态解析模型

### 目标

在不改变二维解析契约的前提下，读取真实区块全部 Section，并保留调色板条目的 `Name + Properties`。

### 预计文件

- 新增 `src/main/java/com/mcworldexplorer/experimental/v04/data/VoxelBlockState.java`
- 新增 `src/main/java/com/mcworldexplorer/experimental/v04/data/VoxelSection.java`
- 新增 `src/main/java/com/mcworldexplorer/experimental/v04/data/VoxelChunk.java`
- 新增 `src/main/java/com/mcworldexplorer/experimental/v04/data/VoxelChunkParser.java`
- 新增 `src/main/java/com/mcworldexplorer/experimental/v04/data/VoxelDataException.java`
- 新增 `src/test/java/com/mcworldexplorer/experimental/v04/data/VoxelChunkParserTest.java`

### 测试先行

覆盖：

- 现代根级 `sections/block_states` 调色板。
- 旧版 `Level/Sections` 调色板。
- 无 `Properties`、单个属性和多个属性。
- 属性映射不可变且顺序稳定。
- 单调色板 Section 不需要 `data`。
- 4 位和 5 位以上调色板索引。
- 填充存储和跨 `long` 紧凑存储。
- 负 Section Y。
- 缺失 `Name`、非法属性、非法调色板大小和非法存储长度。
- 调色板索引越界时包含 Section Y 和方块局部坐标。

### 实现

- `VoxelBlockState` 使用不可变、稳定排序的字符串属性映射。
- `VoxelSection` 负责局部 `0..15` 坐标查询。
- `VoxelChunk` 保存 Section Y 到 Section 的不可变映射，并支持世界 Y 查询。
- `VoxelChunkParser` 复制当前已验证的位存储解码规则，但不让二维类依赖试验包。
- 缺失 Section 返回空气；损坏 Section 抛出带原因枚举的异常。

## 任务 4：统一体素网格生成器

### 目标

将目标区块转换为按颜色分批的后端无关网格快照，并落实普通方块、流体和区块边界规则。

### 预计文件

- 新增 `src/main/java/com/mcworldexplorer/experimental/v04/mesh/MeshBatch.java`
- 新增 `src/main/java/com/mcworldexplorer/experimental/v04/mesh/MeshBounds.java`
- 新增 `src/main/java/com/mcworldexplorer/experimental/v04/mesh/RenderSnapshot.java`
- 新增 `src/main/java/com/mcworldexplorer/experimental/v04/mesh/VoxelMesher.java`
- 新增 `src/test/java/com/mcworldexplorer/experimental/v04/mesh/VoxelMesherTest.java`

### 测试先行

覆盖：

- 单个普通方块生成 6 面、24 顶点和 36 索引。
- 两个相邻普通方块隐藏内部两面。
- 普通方块相邻流体时普通方块界面被遮挡。
- 单个水或熔岩方块只在邻居为空气的方向生成面。
- 垂直和水平连续流体隐藏内部面。
- 不同原版流体相邻时不生成交界面。
- 流体与固体相邻时不生成流体面。
- 含水方块按普通立方体处理。
- 目标区块边界读取四邻遮挡。
- 缺失邻区块产生外侧面；损坏邻区块同时保留警告标记。
- 负 Y 顶点坐标正确。
- 顶点和法线均为有限值，索引全部在范围内。
- 六个方向的绕序一致，背面剔除后外表面可见。
- 同色面进入同一批次，未知方块进入中性灰批次。
- 空区块生成空快照和稳定的默认包围盒。

### 实现

- 使用右手坐标语义：世界 X、Y、Z 原值进入共享快照，Y 向上。
- 每个可见方格面生成 4 个独立顶点和 2 个三角形；V0.4 不做贪心合并。
- 每个面携带固定法线，索引使用统一逆时针绕序。
- 以 RGB 颜色作为批次键，构建完成后冻结数组。
- 快照同时保存包围盒、方块数、面数、顶点数、索引数和边界完整性。
- 在构造结束时执行一次内部一致性校验，非法快照不得进入后端。

### 验证

```powershell
.\gradlew.bat test --tests com.mcworldexplorer.experimental.v04.mesh.VoxelMesherTest
```

### 测试先行

覆盖：

- 共享网格交错或分离缓冲布局计算正确。
- 每个批次的字节数、索引偏移和绘制数量正确。
- OpenGL 视图、投影和法线矩阵与共享相机语义一致。

- 左键拖动、滚轮、`R` 和 `Esc` 更新共享相机状态。
- 记录 GPU 资源创建、首帧和帧间隔。
- `finally` 中按逆序删除批次缓冲、着色器程序、回调、窗口并终止 GLFW。

## 任务 8：集成回归与后端同条件冒烟

### 目标

证明新增原型没有破坏稳定二维程序，并排除明显的空画面、绕序和坐标问题。

### 自动验证

```powershell
.\gradlew.bat clean test
.\gradlew.bat run
```

检查现有二维程序可以正常启动、打开存档和浏览地图。

### 图形冒烟

对同一个真实区块分别启动两个后端，检查：

- 窗口和画面非空。
- 初始画面包含完整目标区块。
- 从上方、侧面和下方观察时外表面绕序正确。
- 负 Y 几何位置正确。
- 区块边缘没有因坐标换算形成裂口或重复偏移。
- 水体和瀑布只保留空气接触外壳。
- 普通方块保持不透明立方体。
- `R` 恢复一致视角，`Esc` 正常退出。
- 控制台和 JSON 报告没有未处理异常或非法数值。

### 停止条件

## 任务 10：真实存档只读验证与性能采样

### 目标

在统一输入和操作下形成可复核的后端证据，而不是凭主观流畅度选择技术栈。

### 预计文件

- 生成但不跟踪 `build/reports/v04-3d/*.json`
- 后续更新 `docs/progress/V0.4.md`

### 测试样本

固定选择至少三个真实区块：

- 普通地表和建筑较多的区块。
- 垂直内容丰富并包含负 Y 的区块。
- 包含水体、瀑布或熔岩的区块。

至少一个样本必须依赖水平邻区块完成边界剔除。样本路径和坐标只记录在本地验收材料中，不硬编码到源码。

### 只读证明

- 关闭 Minecraft 和会写入样本存档的服务器。
- 对样本存档普通文件生成验收前 SHA-256 清单、文件数量和总容量。
- 完成全部测试后重新生成清单并比较。
- 任一存档文件变化均视为阻断问题，除非能证明来自外部程序。

### 测量协议

- 每个后端、每个区块记录一次冷启动。
- 预热后重复运行至少五次，单独计算中位数，不与冷启动混合。
- 使用相同窗口尺寸和初始相机。
- 静置 60 秒，再连续旋转、俯仰和缩放 60 秒。
- 记录读取、解析、网格、后端上传和首帧耗时。
- 记录面数、顶点数、索引数和批次数。
- 记录帧时间分布、JVM 堆变化和 Windows 进程 `WorkingSet64`。
- 关闭窗口后确认进程在合理时间内退出，且无残留进程或锁定文件。

### 比较边界

- 不用单次峰值或平均 FPS 直接下结论。
- JavaFX 和 LWJGL 使用相同共享网格统计；若不同，先修复测量条件。
- 区分共享管线耗时与后端耗时。
- 记录显卡、驱动、Java 版本、显示缩放和测试时间。
- 若无法强制独立显卡或集成显卡路径，明确标记未验证，不猜测结果。
