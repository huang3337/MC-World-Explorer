# V0.3 地图浏览器实施计划

## 状态

- **计划日期**：2026-07-27
- **设计状态**：开发者已确认
- **代码状态**：已实现并通过自动化、真实目录只读验收、逐文件审查和开发者人工界面验收
- **提交状态**：按照 `DEVELOPMENT_RULES.md` Rule 18，V0.3 完成前不创建阶段性提交

设计依据：

- `docs/superpowers/specs/2026-07-27-v0.3-map-browser-design.md`
- `docs/decisions/DECISION-004.md`
- `docs/decisions/DECISION-001.md`
- `docs/decisions/DECISION-003.md`

## 实施原则

- 每个任务只解决一个明确目标，完成对应测试后再进入下一项。
- 保留 V0.2.1 的固定预览入口和测试，直到多级地图视口完成替换并通过回归验收。
- 不更换 Java 21、JavaFX 或 Gradle，不引入新的 UI 框架。
- 不读取 Mod 资源包，不实现三维渲染、自动巡航、动态壁纸或全世界预生成。
- 所有 Minecraft NBT 与 Region 数据保持只读。
- 缓存、日志、导出和配置继续遵守严格便携模式。

## 完成标准

V0.3 只有同时满足以下条件才可提交开发者确认完成：

1. 路线图约定的拖动、缩放、坐标定位和三类标记全部可用。
2. 当前世界缓存清理和当前视口 PNG 导出通过人工验收。
3. 默认测试、真实目录测试和存档只读校验全部通过。
4. V0.2.1 的维度、图层、缓存、导出和错误恢复没有回归。
5. V0.3 涉及的生产文件按 Rule 16 完成逐文件审查，活动问题全部处理或经开发者确认忽略。
6. 开发者完成人工界面验收并明确确认版本完成。

## 任务 3：地图块磁盘缓存与精确失效

**目标**：完成地图块 PNG、元数据、跨启动复用和按 Region 失效，不接入 UI。

计划新增：

- `src/main/java/com/mcworldexplorer/map/MapTileSourceState.java`
- `src/main/java/com/mcworldexplorer/map/MapTileCache.java`
- `src/main/java/com/mcworldexplorer/map/MapTileCacheResult.java`
- `src/test/java/com/mcworldexplorer/map/MapTileCacheTest.java`

实现要求：

- 缓存结构为世界根下的 `map-v03/维度/图层/bpp-N/`。
- PNG 与 JSON 元数据按地图块坐标隔离，负坐标文件名保持稳定。
- 元数据记录完整地图块键、渲染版本和覆盖范围内 Region 的存在状态、大小与修改时间。

- 校验只访问地图块覆盖范围内的 Region，不扫描整个维度。
- PNG 与元数据都使用同目录临时文件和原子替换。
- 损坏、缺失或身份不匹配的缓存返回未命中，并删除仅限该地图块的坏文件。
- 不计算日常缓存校验 SHA-256。

- 有效缓存跨实例命中。
- Region 新增、删除、大小和时间变化分别失效。
- 无关 Region 变化不影响当前地图块。
- 损坏 PNG、损坏 JSON、临时文件和原子替换。
- 缓存路径边界和世界目录边界。

- `src/main/java/com/mcworldexplorer/map/MapTileRenderer.java`
- 对应单元与集成测试

实现要求：

- 按地图块边界只读取覆盖范围内 Region 和区块。
- 复用 `PreviewLayer` 的地表总览与高度带语义。
- `1 方块/像素` 保留现有方块颜色和高度明暗。
- `2、4、8、16 方块/像素` 沿用现有 `PreviewRenderer` 的规则：只平均已填充方块列的 RGB 和高度，全部缺失时使用固定深色，再按相邻输出像素平均高度执行有限明暗。

- 缺失区块保持固定深色，不计失败。
- 非零损坏 Region、损坏区块和不支持压缩继续计入结构化失败。

## 任务 7：内存缓存与视口调度

**目标**：在无 JavaFX 控件依赖的情况下完成可见地图块计算、任务优先级、防抖和旧请求隔离。

计划新增：

- `src/main/java/com/mcworldexplorer/map/MapTileMemoryCache.java`
- `src/main/java/com/mcworldexplorer/map/MapTileScheduler.java`
- `src/main/java/com/mcworldexplorer/map/ViewportCoordinator.java`
- 对应测试

实现要求：

- 内存缓存最多保留 128 个已解码地图块，使用最近使用顺序淘汰。
- 只请求当前视口及一圈必要边界地图块。
- 缓存命中优先于新生成，距离视口中心较近者优先。
- 最多同时执行两个生成任务。
- 拖动停顿约 `200ms` 后刷新可见请求。
- 离开视口且尚未开始的任务取消；正在运行的任务响应监视器取消。
- 世界、维度、图层或请求编号变化后，旧结果不得提交到当前视口。

测试先覆盖：

- 中心距离优先级。
- 防抖期间只提交最后一次视口。
- 并发上限和取消。
- 128 个条目的最近使用淘汰。
- 晚到旧结果被丢弃。
