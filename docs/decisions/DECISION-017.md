# DECISION-017：V0.7.3 实例资源接入与 Mod 通用解析

- **日期**：2026-10-26
- **状态**：开发者明确同意此前通用方案，并要求作为 V0.7.3，先规划后持续开发；完成目标为门禁，仅重大决策再确认。
- **前置基线**：V0.7.2 已审查通过、提交并推送，72145b093841302ee0060ae23ce16563e8862dce。

## 决策内容

保持 Java/JavaFX/LWJGL 与只读架构。以存档所属游戏实例建立资源上下文，合并原版客户端、对应 Mod JAR、实际启用资源包及存档资源；纹理/模型根据引用自动选择，来源顺序和内容身份参与缓存。优先自动定位，无法判定时提供手动选择实例作为备用，禁止混入其他整合包。

先接入资源与真实降级分类，再修标准字段/模型表达，依据实际样本扩展通用 loader/格式。按模型格式、loader 或渲染族复用，不逐块手工配纹理。动态代码生成形体不能假称静态可解；纯 Java renderer/动态联网皮肤/游戏运行时烘焙桥接不自动纳入本期。

## 选择与原因

逐个方块补丁无法扩展；直接启动/执行 Mod 代码会改变独立浏览与只读资源边界。选择在已建立的 BlockResourceSource 之上添加受控实例资源源，并复用标准解析/几何/图集，通用格式按样本收益推进。

## 长期影响及约束

多归档不是无限预加载：按 namespace 与实际状态读取，限制归档数/索引/解压/缓存及句柄。资源包按实例启用顺序，冲突可追溯；文件更改、删除、顺序改变均使相关场景缓存失效。格式本身不含足够静态数据时保留明确诊断，不能通过忽略未知几何字段或空模型统计虚报覆盖。

具体任务与验收见 [V0.7.3](../progress/V0.7.3.md)。不更换框架、删除核心模块或开始执行游戏/Mod；若需要此类重大变更再讨论。
