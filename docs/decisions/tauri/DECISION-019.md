# DECISION-019：IPC 混合使用 JSON 控制信息与原始二进制密集数据

- **状态**：已确认
- **确认日期**：2026-09-06
- **确认人**：项目开发者
- **适用范围**：`tauri-rewrite` 的世界信息、二维数据、三维网格、警告和错误 IPC

## 背景

世界摘要、状态和错误适合使用可读的类型化 JSON；栅格、顶点、法线、颜色和索引若展开为 JSON，会显著增加序列化体积、时间和 WebView 峰值内存。

## 最终选择

- 小型控制信息使用字段固定、严格验证的 JSON DTO。
- 二维和三维密集数据使用带魔数、独立协议版本、长度和分段描述的原始二进制 `ArrayBuffer`。
- 动态二维地图允许同一视口任务分批返回有界二进制增量；每批仍遵守版本、身份、长度和资源校验。
- 成功数据与稳定错误通道分离，不以空 buffer、特殊颜色或畸形成功载荷表示失败。
- Rust 编码器和 TypeScript 解码器使用同一组黄金字节定义验证协议。

## 不可变边界

前端必须完整校验协议后才能提交状态或创建 GPU 资源。密集数据不改用 JSON 数组、Base64、共享内存、临时文件或本地 HTTP 服务；前端也不因协议获得世界文件路径。

## 影响

新增不兼容二进制布局必须提升协议版本。具体字节布局、字段宽度和载荷上限由当前协议规格维护，不在本决策中重复。
