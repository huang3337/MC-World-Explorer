# DECISION-015：世界发现与打开由受控 Rust Command 管理

- **状态**：已确认
- **确认日期**：2026-09-06
- **确认人**：项目开发者
- **适用范围**：`tauri-rewrite` 的世界目录选择、候选发现和世界打开

## 背景

前端直接调用通用目录选择或文件系统 API，会把路径和通用权限引入 WebView。世界发现与打开必须保持与只读解析相同的后端信任边界。

## 最终选择

- 官方 Tauri dialog 仅由项目专用 Rust Command 包装，不向 WebView 开放通用 dialog 或文件 scope。
- Rust 可对用户选定的世界、`saves` 目录、游戏根目录或版本集合进行有界只读扫描，并向前端返回不透明候选编号和展示信息。
- 前端选择候选编号后，由 Rust 重新校验实际路径；验证成功后才建立或替换当前 WorldSession。
- 用户取消选择是正常的“未选择”结果，不清空已有有效世界。
- 展示路径仅用于界面告知，不能作为后续 Command 的读取授权。

## 原因与影响

这一边界恢复 Java 稳定版的目录扫描与快速选择体验，同时确保 Vue 不获得任意文件访问能力。候选列表不是活动世界会话，也不是世界快照。
