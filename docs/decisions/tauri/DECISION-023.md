# DECISION-023：二维地图采用独立有界渐进调度架构

- **状态**：已确认
- **确认日期**：2026-09-13
- **确认人**：项目开发者
- **适用范围**：`tauri-rewrite` 的二维地图生成、缓存、调度、增量 IPC、取消与关闭

## 背景

二维地图需要同时加载多个中心优先瓦片，并在单个瓦片完整生成前持续提供局部结果。全应用单 active、单 pending、单 worker 模型会使瓦片相互替换；固定表面后再生成瓦片也会重复读取和采样。

## 最终选择

- 二维地图使用独立的固定双 worker 调度域；非地图重任务继续使用单 worker 有界执行边界。
- 地图调度采用有界中心优先队列，并支持可见瓦片优先、外围预取、相同瓦片去重、任务重新绑定和协作取消。
- 后端以视口任务组织工作，通过有界二进制增量响应提交局部和最终瓦片结果。
- 当前 WorldSession 内使用有界两级内存缓存，复用解码区块和最终瓦片；不建立磁盘持久缓存。
- 当前视口完整度只由当前会话和当前代次的可见瓦片终态证明，外围预取不阻塞完成。
- 世界切换和关闭必须停止新请求、取消并收束两个调度域、唤醒等待中的增量请求、释放缓存和世界资源。

## 不可变边界

调度、结果队列、缓存和 IPC 都必须有明确上限。不得通过增加无界并发、删除资源限制、吞掉失败或混淆缺失状态提高速度。会话 ID、任务代次、迟到结果拒绝、前端无路径能力和存档严格只读继续有效。

## 原因与影响

该架构恢复 Java 稳定版的双 worker、中心优先、外围预取、渐进显示和结果复用体验，同时把改动限制在二维地图调度域。代价是应用需要协调两个有界执行域及其关闭顺序；具体容量、状态、重试、协议字段和测试要求由另行确认的当前规格与实施计划维护，不属于本重大决策记录。
