# DECISION-021：二维地图使用 Canvas 2D 动态瓦片视口

- **状态**：已确认
- **确认日期**：2026-09-06
- **确认人**：项目开发者
- **适用范围**：`tauri-rewrite` 的二维地图显示与二维到三维选区入口

## 背景

二维地图需要以较低 DOM 和 GPU 复杂度显示大范围表面栅格，并保持稳定的世界坐标、缩放、平移和选区映射。固定中心表面无法满足 Java 稳定版的连续地图浏览体验。

## 最终选择

- 使用 Canvas 2D 绘制动态地图瓦片和交互覆盖层，不为每个方块创建 DOM/SVG 节点，也不让二维依赖 Three.js 场景。
- 世界会话建立后立即挂载地图视口；固定 1024×1024 表面不再是二维首屏前置条件。
- 地图支持以 Java 稳定版为基线的中心定位、平移、缩放、负坐标、区块边界和有限三维选区。
- 基础地图数据与中心、出生点、悬停、选区、加载和失败提示分层绘制。
- 颜色解析、Minecraft 坐标和区块状态由 Rust 结果提供，前端不重复实现 NBT、Palette、表面采样或方块分类。

## 不可变边界

Canvas backing store 和缓存必须有资源上限。未加载、真实缺失、不支持、损坏和整瓦片请求失败必须可区分，且不能仅靠颜色传达。组件卸载、世界切换和结果替换必须释放前端缓冲与监听器。

## 影响

二维地图保持独立于三维渲染器，便于在不改变存档读取边界的情况下恢复 Java 地图体验。详细瓦片、状态、坐标和交互契约由二维地图规格维护。
