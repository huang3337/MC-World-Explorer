# DECISION-020：Rust 管理单个只读 WorldSession

- **状态**：已确认
- **确认日期**：2026-09-06
- **确认人**：项目开发者
- **适用范围**：`tauri-rewrite` 的世界身份、后续 Command 授权、世界切换和资源生命周期

## 背景

如果每个 Command 都重新接收前端传回的世界路径，会重复跨越路径安全边界，并可能把旧界面请求用于新世界。复制世界快照则会引入存档数据写入、容量和清理责任。

## 最终选择

- Rust 应用层只持有一个当前有效的只读 WorldSession。
- 会话拥有 `WorldSource`、必要保护资源、世界摘要和应用生命周期内单调递增且不复用的会话 ID。
- 前端只获得会话 ID 与展示信息；后续业务 Command 必须在开始和接纳结果时核对当前会话，且不得接收世界路径作为读取授权。
- 候选世界验证成功后原子替换当前会话；候选取消或失败保留原会话，旧会话结果在替换后全部过期。
- 当前会话允许持有身份、容量和来源失效规则明确的有界内存缓存。
- 跨启动二维瓦片缓存由独立的严格便携缓存服务管理，不由 WorldSession 持有，也不构成世界副本；缓存身份与来源失效语义继承 Java 稳定行为。

## 不可变边界

WorldSession 固定读取授权和资源所有权，不是不可变世界快照。运行中的外部世界变化仍需通过来源身份检查和受控错误处理。世界切换与关闭必须先收束引用旧会话的后台任务，再释放保护句柄和内存缓存。持久瓦片缓存只能写入 EXE 便携目录，不能写入存档、AppData 或前端提供的位置。

## 影响

应用重启后必须重新选择并验证世界；会话 ID 不持久化，也不是安全凭据。未来只有在需要同时保持多个活动读取会话时，才需要重新确认会话架构。
