# DECISION-016：关闭主窗口时协调释放便携目录并退出应用

- **状态**：已确认
- **确认日期**：2026-09-05
- **确认人**：项目开发者
- **适用范围**：V0.7.1，`tauri-rewrite` 的 Tauri 应用生命周期

## 背景

Task 13 已验证 WebView2 数据实际位于 EXE 便携目录，但关闭唯一主窗口后宿主进程残留并持续持有目录锁。窗口消失或 WebView2 子进程退出不能代替宿主进程正常退出。

## 最终选择

- 关闭标签为 `main` 的唯一主窗口代表退出整个 MC World Explorer。
- 收到 main 的 `CloseRequested` 时阻止默认销毁，先幂等释放 `PreparedWebviewData` 保护句柄，再请求 Tauri 正常退出。
- `ExitRequested` 执行同一幂等释放，覆盖其他退出来源；不阻止退出、不改变退出码。
- 生命周期状态使用 `Mutex<Option<PreparedWebviewData>>`，第一次调用取得并在锁外释放，重复或并发调用安全空操作。
- 非 main 窗口关闭不退出应用，也不释放保护句柄。

## 排除方案与边界

- 不在窗口创建后立即释放句柄，继续保留运行期目录保护。
- 不使用 `std::process::exit`、强制结束、托盘后台化、前端关闭协议或新 Command。
- 不修改 WebView 目录规则、`mcwe-core`、依赖、capability、CSP 或发布形态。
- 退出开始后的短暂窗口不承诺抵御同权限恶意进程操作目录；应用此时不得继续业务读写。

## 验证要求

自动化必须覆盖释放一次、重复与并发释放、main/非 main 关闭决策及调用顺序。重新构建后必须实际验证主进程和关联 WebView2 进程在人工关闭后 10 秒内自然退出、目录锁释放且 AppData 不变。

本决策不授权重新构建、真实启动验收、提交、推送、合并、标签或发布。
