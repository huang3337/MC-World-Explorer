# DECISION-013：Java 主线优先完善浏览体验与地点回访

- **状态**：路线调整已获开发者授权；各版本细化设计和实现尚未开始
- **确认日期**：2026-10-25
- **确认人**：项目开发者
- **适用范围**：Java V0.6.0 之后的产品开发顺序与版本范围

## 背景与授权

开发者明确决定暂时搁置 Tauri 技术探索、回归完善 Java，并在产品与界面审查后要求根据建议重构文档路线，再继续开发。本记录将该授权落实为 Java 后续路线；不表示开发者已验收具体布局、地点数据格式或渲染方案。

Java V0.6 已有二维地图及受控范围三维。现阶段优先解决能力呈现、世界辨认、跨启动地点回访与建筑辨识度，形成完整个人使用流程。Tauri 实验不再作为 Java 发布前置条件；本决策不对两者性能作未经同条件测量的结论。

## 备选方案

### A：沿原顺序优先扩展三维技术

先原版资源，再自由移动与动态区块流送，之后双模式整合，搜索和整理延至 V1.1。优点是三维技术连续；代价是界面、世界查找和地点回访继续滞后，V1.0 依赖较重的流送运行时。

### B：先完善个人浏览流程，再扩大三维范围

先界面、世界查找与地点回访，再原版资源、地点三维展示及稳定交付。继续复用现有渲染与受控范围，不将无限浏览作为 V1.0 前提。代价是原版资源和自由浏览排期后移，需要明确旧新版本映射。

### C：继续推进 Tauri 对等迁移

继续承担功能对等、桌面体验和资源释放验证；不能直接解决产品层级和持续使用动机问题。当前开发者已明确暂停该方向。

## 最终选择

按开发者授权采用 B：Java 为继续开发的主线，保留 Java 21、JavaFX、LWJGL/OpenGL、Gradle 与既有独立三维窗口。

| 新版本 | 目标 | 与原路线关系 |
|---|---|---|
| V0.7 | 浏览工作区与界面层级 | 新增近期优先目标 |
| V0.8 | 世界查找与辨认 | 原 V1.1 搜索、封面辨认等基础能力前移 |
| V0.9 | 命名地点与回访 | 新增持续使用流程；不等同于世界收藏夹 |
| V0.10 | 原版视觉资源与建筑辨识 | 承接原 V0.7，保留降级边界 |
| V0.11 | 地点与三维展示衔接 | 承接整合目标，增加最小视图保存与图片展示 |
| V0.12 | 整体加固与发布准备 | 承接原 V0.9 的升级、性能和候选包验收 |
| V1.0 | 个人世界与地点浏览器 | 稳定交付完整回访流程，不要求动态区块流送 |

原 V0.8 的自由移动与动态区块流送，以及原 V2.0/V3.0 的巡航、展示与壁纸移入 V1.0 后候选方向，不继续预设版本编号或工期。

## 长期影响

- 已完成的 V0.1–V0.6、发布标签、软件包、历史测量和历史决策保持原语境，不反写历史版本范围。
- 原计划尚未开始的版本按新路线解释；旧记录中提及的“V0.7 原版资源”等属于当时计划，应结合本映射阅读。
- 地点和相机视图属于用户数据，须与可清理缓存分离并设计身份关联、错误恢复及升级边界。
- 三维继续受控范围与独立窗口。嵌入、自由移动或流送若启动，应单独作为重大技术决策评估。
- 每次仍只开发一个目标；阶段设计、实现、验证、版本完成、提交和发布遵守原有门禁。
- 本次只重整正式路线和状态文档，不修改业务代码、构建版本号或发布内容。
