# DECISION-013：V0.7 采用 Tauri、Rust、Vue 和 Three.js 完成 V0.6 框架迁移

- **状态**：已确认
- **确认日期**：2026-08-24
- **确认人**：项目开发者
- **适用分支**：`tauri-rewrite`
- **适用版本**：V0.7.1 至 V0.7.6

## 决策背景

MC World Explorer V0.6.0 已使用 Java 21、JavaFX 和 LWJGL/OpenGL 完成存档管理、二维地图，以及从二维区域选择进入独立窗口查看有限范围简化三维场景的正式流程。继续在该技术栈中实现完整视觉资源系统，会在后续迁移时重复实现最复杂的资源、渲染和应用边界。

项目同时希望降低最终发布物对 JVM 和并列运行时目录的依赖，并把世界考古等产品特色留到框架迁移完成后重新规划。因此，V0.7 不再沿用原“原版视觉资源”路线，而作为 V0.6 的完整框架迁移版本线。

该选择改变桌面框架、界面技术、核心语言、三维呈现方式、项目结构和后续路线，属于长期重大架构决策。

## 备选方案

### A：继续使用 JavaFX 和 LWJGL

- 保留现有源码和已验证的二维、三维基础。
- 使用 `jlink`、`jpackage` 等方式继续优化体积。
- 重写成本最低，但后续仍长期维护 JVM、JavaFX 与独立 GLFW 窗口边界。

### B：迁移到 Tauri、Rust、Vue 和 Three.js

- Tauri 2 负责 Windows 桌面壳和受控 IPC。
- Rust 负责存档解析、地图数据、体素数据、网格和后台任务。
- Vue 3 与 TypeScript 负责界面和前端状态。
- Three.js 与 WebGL 2 负责 WebView 内嵌三维场景。
- 建立不依赖 Tauri、Vue 或 Three.js 的独立 `mcwe-core` crate。

该方案重写成本较高，但符合轻量桌面壳、单窗口界面、Rust 只读核心和最终单 EXE 的长期目标。

### C：使用 Rust、egui 和 wgpu

- 全部采用原生 Rust UI 与渲染。
- 运行时边界直接，但 UI、二维交互和三维界面需要承担更多底层实现及维护成本。

## 最终选择

选择 **B：迁移到 Tauri、Rust、Vue 和 Three.js**。

- 使用 Tauri 2 稳定版、Vue 3、TypeScript、Vite 和 npm。
- 使用稳定的 `x86_64-pc-windows-msvc` Rust 工具链。
- Rust 核心位于独立 `mcwe-core` crate，不依赖 Tauri 或前端。
- 前端只通过类型明确的 Tauri Command 或 Channel 获取数据，不直接访问 Minecraft 文件。
- Three.js 在 V0.7.2 首次需要三维垂直切片时引入；V0.7.1 不提前添加。
- 复用 Java V0.6 已验证的算法语义和测试证据，但不逐类、逐行翻译旧代码。
- 迁移中发现的旧版疑似缺陷先记录，由开发者决定保持兼容或另行批准行为变化。

## 版本与仓库边界

- V0.7.1 至 V0.7.6 是 `tauri-rewrite` 上的迁移里程碑。
- V0.6.0 继续作为稳定发布版保留在 `main` 和 Git 历史中。
- V0.7 整体迁移完成前不替代 V0.6，不合并到 `main`。
- 每个 `0.7.x` 的完成、提交和推送分别需要开发者明确确认。
- V0.7 不创建正式标签或 GitHub Release，也不自动规划 V0.8 及以后路线。

## 只读与便携边界

- Minecraft 世界、Region、NBT、玩家和维度文件只能以只读方式打开。
- 核心层不提供创建、写入、删除、移动、重命名或修复存档的 API。
- 程序数据只允许位于 EXE 所在便携目录的 `cache/`、`logs/`、`exports/` 和 `config/`。
- 不写入 AppData 或注册表，不引入 sidecar、Shell 权限或当前范围不需要的网络与文件系统写插件。

## 最终发行目标

最终 Windows x64 发布物目标是一个可直接运行的 `MC-World-Explorer.exe`：

- 无需安装。
- 不附带 JVM、Node.js、sidecar、并列 DLL 目录或外置资源目录。
- 依赖目标 Windows 系统已有的 WebView2 Runtime。
- 首次运行后只在 EXE 所在便携目录创建程序自己的数据目录。

V0.7 里程碑可以验证单 EXE 可行性，但不因此自动获得正式发布授权。

## 对既有决策的影响

- `DECISION-001`、`002`、`003`、`004`、`006` 和 `008` 中的数据、安全与架构原则继续有效。
- `DECISION-007` 的 LWJGL/OpenGL 技术选择作为 Java V0.6 历史依据保留，但不再约束 V0.7 的三维实现。
- `DECISION-009` 的独立 LWJGL 窗口方案作为 V0.6 历史依据保留；V0.7 改为 Tauri 主窗口内的 Three.js 视图。
- `DECISION-010` 的环绕、平移、点击阈值和重置交互语义继续作为 Three.js 重实现参考。
- `DECISION-011` 和 `012` 的仓库治理规则继续有效。
- `DECISION-005` 仅保留为历史发布安排，不作为 V0.7 开发规则。

## 选择原因

- 将存档解析和计算密集型任务迁移到 Rust，有利于建立明确的类型、所有权、错误和只读边界。
- Vue 与 TypeScript 更适合重新组织单窗口桌面界面和异步状态。
- Three.js 可以在 Tauri WebView 内统一二维选择与三维查看流程，避免继续维护 JavaFX 与 GLFW 双窗口协调。
- 独立 `mcwe-core` 能隔离领域算法与 UI 框架，降低长期框架耦合。
- 以 `0.7.x` 分段迁移可以逐步验证工程、解析、二维、三维和单 EXE，而不把一次大重写直接视为完成。

## 长期影响

- V0.7 需要重新实现并逐项验证 V0.6 核心功能，重写成本显著，不能依赖界面能启动就宣称迁移完成。
- Java V0.6 与 Rust V0.7 必须通过固定样本、行为对照和真实存档只读证据确认语义一致。
- Tauri IPC、Vue 异步状态、Rust 任务取消和 Three.js GPU 资源释放成为新的长期审查重点。
- 最终单 EXE 依赖系统 WebView2；完全离线捆绑 WebView2 不属于当前轻量发行目标。
- V0.7 完成后，才根据实际兼容性、性能、维护成本和单 EXE 结果重新决定后续产品路线。

本决策不自动授权任何里程碑完成、提交、推送、打包、发布、合并 `main` 或开始下一版本。
