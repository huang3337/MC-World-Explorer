# DECISION-007：后续三维渲染采用 LWJGL/OpenGL

- **状态**：已确认
- **确认日期**：2026-08-01
- **确认人**：项目开发者
- **适用版本**：V0.4 及后续三维开发

## 决策背景

V0.4 使用同一套真实存档解析、体素网格和环绕相机，隔离实现了 JavaFX 3D 与 LWJGL/OpenGL 两个候选后端。两个后端均通过真实区块显示、自动截图、持续运行、资源释放和 Windows x64 非发布 app-image 验证，因此需要根据实测结果确定后续三维路线的基础后端。

该选择会长期影响渲染架构、原生依赖、资源生命周期、便携打包、性能上限和后续纹理及动态区块能力，属于重大技术决策。

## 备选方案

### A：LWJGL/OpenGL

- 使用 OpenGL 3.3 Core 和显式 GPU 资源管理。
- 优势是上传成本、帧时间稳定性、工作集和后续渲染扩展空间更好。
- 代价是需要携带 Windows 原生库，并显式管理窗口、上下文、着色器和 GPU 资源生命周期。

### B：JavaFX 3D

- 继续依赖现有 JavaFX 技术栈完成三维渲染。
- 优势是依赖和现有界面整合更简单。
- 代价是当前实测上传时间、P95 帧时和工作集均高于 LWJGL，且大型场景的扩展余量较弱。

### C：暂停三维路线

- 保留 V0.4 验证成果，不指定后端，也不进入依赖三维后端的后续开发。
- 可避免立即承担新技术栈成本，但不能继续推进路线图中的三维能力。

## 实测依据

三个真实区块在两个后端中得到完全一致的方块数、流体数、外壳面数、总面数和几何边界。36 次正式测量中，两个后端均可持续运行 120 秒，后半程工作集未出现持续增长，存档 716 个文件的大小和 SHA-256 前后完全不变。

| 指标 | JavaFX 3D | LWJGL/OpenGL |
|---|---:|---:|
| GPU/场景上传耗时 | 31.11-38.51 ms | 10.57-12.46 ms |
| 首帧耗时 | 789.38-932.74 ms | 738.09-740.06 ms |
| P95 帧时 | 16.348-16.384 ms | 4.543-4.601 ms |
| 峰值工作集 | 215.9-220.4 MB | 179.7-185.4 MB |

两个 Windows x64 非发布 app-image 均已完成独立启动、截图、自动退出和文件锁释放验证。

## 最终选择

选择 **A：LWJGL/OpenGL** 作为后续三维渲染基础。

- 后续正式三维管线以共享数据模型和 LWJGL/OpenGL 后端为主。
- JavaFX 继续承担现有二维主界面，不将“选择 LWJGL”解释为替换整个 JavaFX UI 框架。
- JavaFX 3D 对照原型暂时保留为 V0.4 验证证据，不继续作为正式三维后端扩展。
- 本决策不代表 V0.4 已成为面向用户的发布版本，也不自动授权进入 V0.5、提交或推送。

## 选择原因

- 在相同网格和相机条件下，LWJGL 的上传耗时约为 JavaFX 3D 的三分之一。
- LWJGL 的 P95 帧时明显更低，帧间一致性更适合后续交互浏览。
- LWJGL 的峰值工作集更低，三组长时样本后半程均保持稳定。
- OpenGL 的显式缓冲、着色器和资源生命周期为纹理、批处理、动态区块和更大可视范围提供了更清晰的扩展路径。
- Windows x64 原生依赖与 app-image 已验证可打包、启动和释放，当前不存在阻断路线的部署问题。

## 未选方案处理

- JavaFX 3D 原型和测量结果保留在 `experimental.v04` 与验证证据中，用于复核本决策。
- 后续不得向 JavaFX 3D 原型继续添加正式三维功能。
- 在 LWJGL 正式管线能够覆盖必要验证后，可单独评估归档或删除 JavaFX 3D 原型；删除前仍需执行影响审查，不在本决策中提前删除。
- jMonkeyEngine 继续只作为两个已验证方案均出现阻断问题时的备选，不进入当前实现范围。

## 长期影响

- 项目将长期维护 LWJGL core、GLFW、OpenGL 及对应平台原生库，并在打包时校验其完整性。
- 三维资源必须继续使用显式创建与释放边界，窗口关闭和异常路径都必须释放 OpenGL、GLFW 和线程资源。
- 二维地图模式仍是稳定基线并长期保留；三维功能不得破坏现有只读边界、缓存格式和 JavaFX 二维工作流。
- V0.4 只证明 Windows x64 NVIDIA 独显环境的技术可行性。Intel 核显、其他显卡厂商、远程桌面和更大场景必须在面向用户发布前继续验证。
- V0.5 及后续设计可以采用 LWJGL/OpenGL，但仍需遵守各版本门禁，不得把 V0.4 原型直接视为正式架构。
