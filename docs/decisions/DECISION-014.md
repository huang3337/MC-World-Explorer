# DECISION-014：Windows 只读来源使用逐级目录句柄保护

- **状态**：已确认
- **确认日期**：2026-09-04
- **确认人**：项目开发者
- **适用范围**：V0.7.1 Task 6，`tauri-rewrite` 的 `mcwe-core`

## 背景与备选方案

仅使用路径规范化、根目录前缀检查和随后打开文件，不能阻止检查与打开之间的目录替换。Task 6 要求拒绝符号链接或 junction 回绕，不能将静态路径检查误认为并发安全保证。

- 普通路径检查：实现简单，但不能覆盖上述时间间隙。
- Windows 逐级目录句柄保护（采用）：在打开后检查句柄元数据，并保留祖先目录句柄直到目标文件安全打开；通过共享模式防止保护期间的删除、重命名和写打开。
- 引入第三方能力式文件系统库：可以减少平台代码，但会增加依赖及语义审查范围，当前不采用。

## 最终选择与实现边界

- Windows 细节封装在 `world_source` 内，不依赖 Tauri，不新增第三方依赖或 `unsafe`。
- 世界根必须是明确的绝对文件系统路径；相对文件名必须由普通路径分量构成。拒绝父目录跳转、绝对路径、设备命名空间、备用数据流及有歧义的 Windows 文件名。
- 使用 `FILE_FLAG_OPEN_REPARSE_POINT` 打开每一级对象，检查句柄元数据并拒绝所有重解析点；即使链接目标仍在根内也不跟随。
- 使用 `FILE_FLAG_BACKUP_SEMANTICS` 获取目录句柄；保护期间只允许读共享，拒绝不兼容的现有写入/删除句柄，不降级重试。
- 从路径锚点逐级持有祖先目录句柄。目录句柄只覆盖一次校验/打开操作，不由世界来源长期持有。
- 文件只读打开，返回只实现读取与定位的封装，不暴露原始 `File`、写入、元数据修改或原始句柄接口。文件句柄在读取封装释放时关闭。
- 根类型只验证文件系统边界，不验证 `level.dat` 或世界格式。每次打开重新校验根路径，不将根类型视为不可变世界快照。
- 当前正式目标为 Windows x64；其他平台明确返回不支持，不能静默退化为存在竞态的路径检查。

## 影响和验证要求

- 保护期间可能暂时阻止涉及对象的写打开、重命名或删除；已有冲突句柄时返回稳定错误。该行为不能保证正在运行的 Minecraft 世界具备跨文件一致性。
- 拒绝全部重解析点意味着链接式世界路径、挂载点或部分云同步路径可能被拒绝；这是当前安全取舍，不声称完整路径兼容。
- 硬链接和有权限修改挂载/设备命名的高权限攻击者不属于目录链接防逃逸保证；只读 API 仍不修改其目标。
- 自动化覆盖合法读取、异常路径、缺失文件、符号链接、junction、句柄防替换和释放；比较合成数据的大小、修改时间与内容哈希。
- 不修改 `main`，不迁移 NBT/Region 算法，不自动开始 Task 7 或后续里程碑。

## 实现依据

- [Microsoft CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)：共享模式、目录句柄与重解析点打开语义。
- [Rust OpenOptionsExt](https://doc.rust-lang.org/std/os/windows/fs/trait.OpenOptionsExt.html)：安全 Rust 中的 Windows 打开选项。
