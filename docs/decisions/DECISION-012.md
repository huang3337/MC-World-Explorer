# DECISION-012：内部验证工具退出公开 Git 历史

- **状态**：已确认
- **确认日期**：2026-08-14
- **确认人**：项目开发者
- **适用范围**：整个 Git 历史、正式分支与发布标签

## 决策背景

V0.4 和 V0.5 开发期间创建了试验打包脚本、试验说明和测量脚本。这些工具只服务于本地技术验证，却被提交到正式仓库，使 GitHub 根目录出现仅由内部开发工具构成的 `packaging/` 和 `scripts/`。

本地打包输出、截图、报告和验证清单原本已经由 Git 忽略。继续追踪少量内部工具既不能提供完整的公开构建流程，也会让仓库结构显得混乱。

## 清理范围

从正式历史中移除以下文件：

- `packaging/build-v04-trials.ps1`
- `packaging/V0.4-TRIAL-NOTICE.txt`
- `scripts/v04/measure-v04.ps1`
- `scripts/v05/measure-v05.ps1`

V0.4、V0.5 的正式源码、测试、进度记录、重大决策和历史审查记录不属于本次清理范围。

## 备选方案

### A：仅从当前版本删除

- 当前 GitHub 根目录不再显示两个内部工具目录。
- 旧提交和 `v0.6.0` 标签仍可访问这些文件。
- 不改变历史提交哈希。

### B：清理全部正式历史

- 从 `main` 和发布标签历史中彻底移除四个文件。
- 将 `packaging/` 和 `scripts/` 整体列为本地目录。
- 修正正式文档中的具体本地路径。
- 受影响提交和 `v0.6.0` 标签获得新哈希。

## 最终选择

选择 **B：清理全部正式历史**。

- `packaging/` 和 `scripts/` 默认只保存本地打包、测量和验证工具，不进入 Git。

- 正式仓库继续保留可编译源码、自动化测试、项目文档和必要的 Gradle Wrapper。
