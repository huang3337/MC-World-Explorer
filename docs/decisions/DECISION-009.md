# DECISION-009：V0.6 使用独立 LWJGL 三维预览窗口

- **状态**：已确认
- **确认日期**：2026-08-14
- **确认人**：项目开发者
- **适用版本**：V0.6 及后续三维预览接入

## 决策背景

V0.5 已建立正式体素数据、有限区域加载、简化网格和 LWJGL/OpenGL 渲染基础，但三维功能仍通过独立内部验证入口运行。V0.6 需要第一次把三维预览接入正式用户流程，同时保持 V0.3.1 二维地图稳定基线。

JavaFX 与 GLFW 分别拥有自己的窗口、事件循环、线程和渲染资源生命周期。三维画面采用独立窗口还是嵌入 JavaFX，会长期影响正式界面结构、线程边界、故障隔离和后续 V0.8 三维浏览扩展，因此属于重大技术与界面决策。

## 备选方案

### A：JavaFX 主窗口加独立 LWJGL 三维窗口

- JavaFX 主窗口继续承载存档列表、二维地图和范围选择。
- 选定区域生成完成后，由独立 GLFW/LWJGL 窗口显示三维场景。
- 三维窗口关闭后返回原有二维浏览流程。
- JavaFX 与 OpenGL 各自在明确线程中管理事件循环和资源。

优点是可以直接复用 V0.5 已验证的 LWJGL 窗口与渲染组件，线程和资源边界清楚，三维创建或运行失败时也更容易保留二维地图。代价是三维预览不是嵌入式单窗口体验，需要明确两个窗口之间的状态和生命周期协调。

### B：将 LWJGL 画面嵌入 JavaFX 主窗口

- 在现有主界面内部提供三维视图区域。
- 需要额外解决原生 OpenGL 上下文嵌入或离屏渲染、画面传输、输入转发和双事件循环协调。

优点是界面整体感更强。代价是实现和验证复杂度明显增加，也会提前引入超出 V0.6 小范围预览目标的技术风险。

## 最终选择

选择 **A：JavaFX 主窗口加独立 LWJGL 三维窗口**。

- 正式 JavaFX 主窗口和二维地图继续保留。
- V0.6 三维预览在独立 GLFW/LWJGL 窗口中显示。
- 三维窗口使用正式 `com.mcworldexplorer.voxel` 数据、网格和 LWJGL 渲染组件，不复制解析实现。
- 新增正式 `com.mcworldexplorer.viewer` 模块，负责三维请求、后台任务协调、内存场景缓存和唯一窗口生命周期。
- JavaFX 控件与二维地图交互继续位于 `com.mcworldexplorer.ui`；正式体素数据、网格和底层 LWJGL 资源继续位于 `com.mcworldexplorer.voxel`。
- `com.mcworldexplorer.experimental.v05` 保持内部验证入口，不承载正式用户流程。
- 三维窗口创建、事件循环、OpenGL 上下文和 GPU 资源生命周期必须与 JavaFX 线程明确隔离。
- 三维窗口失败或关闭后，二维地图仍应保持可用。
- 选择框尺寸、生成期间二维界面状态和具体窗口交互已在 V0.6 设计文档中逐项确认；三维鼠标交互的后续修订见 `DECISION-010.md`。

## 选择原因

- 最直接复用 V0.5 已完成并验证的正式 LWJGL/OpenGL 基础。
- 避免在首个用户三维功能中同时承担原生画面嵌入和离屏传输风险。
- 保持 JavaFX 二维界面稳定，符合 V0.6 受控范围和优先完成原则。
- 独立线程和资源边界便于取消、失败隔离、窗口关闭和显存释放验证。
- 为后续 V0.8 交互式三维浏览保留连续扩展路径。

## 长期影响

- 正式程序需要建立 JavaFX 与三维窗口之间的请求、结果和生命周期协调层。
- 后续三维用户流程优先扩展 `com.mcworldexplorer.viewer`，不得把正式窗口生命周期继续堆入实验目录或 JavaFX 控制器。
- 同一时间允许存在的三维窗口数量、重复打开行为和主窗口操作策略必须在 V0.6 中明确。
- 三维预览不能直接访问或修改 JavaFX 控件，状态回传必须通过明确接口切回 JavaFX 线程。
- V0.6 的 Windows x64 验收必须覆盖窗口创建失败、正常关闭、重复打开和资源释放。
- 未来如改为嵌入式三维界面，需要重新作为重大技术与界面决策评估。
- 本决策不自动授权 V0.6 完成、提交、推送、打包或发布，这些门禁继续分别执行。
