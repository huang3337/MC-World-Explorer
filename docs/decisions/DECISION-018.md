# DECISION-018：开放模型规则扩展与本地实例覆盖目标

- **日期**：2026-10-26。
- **状态**：开发者已明确同意按规则模块扩展，并要求开放扩展入口、覆盖本地已有Mod；本轮记录已确认方向并规划任务，未开始新增实现。
- **当前版本**：开发者已明确授权0.7.3收口、提交与推送；本轮不实施后续规则扩展。

## 已确认的决策内容

保持Java/JavaFX/LWJGL与资源引用自动绑定。适配依据模型格式、loader声明或渲染类型，不绑定本机实例路径、整合包名称、当前样本目录或逐方块材质表。已有Mod作为验收样本；新增Mod只要使用已实现的规则，应沿相同入口解析，不要求添加名单。

开放规则接口与注册入口，提供规则能力说明、接口版本、独立示例和测试约定，为后续规则及其他开发者保留空间。共享资源读取、纹理、几何输出、预算、诊断和缓存；避免每个Mod重复建设完整管线。

最终目标是本地已盘点实例中的有效资源及实际方块状态正确解析，纹理/材质同步，达到规则级跨实例复用。具体任务与验收口径见[开放规则任务规划](../progress/MOD_RULE_EXTENSION_PLAN.md)。

## 对宽松处理的解释

接受未知Mod名称、命名空间、资源目录和经识别的无关元数据；按受支持的格式规则处理。影响几何、材质或连接关系的未知字段需要正确语义，不能靠吞错、丢部件、紫色占位或将未知模型视为空几何伪造全部通过。

未来任意新格式仍需增加规则。扩展入口可以避免修改主流程，但不能保证从未实现的算法自动推导出全部外观。

## 范围与待决事项

只读Mod本体和资源包，不因本次批准就执行Minecraft/任意Mod类或引入游戏侧导出桥接。开放适配器API与加载Mod本体是不同的执行边界。外部规则包的安装/显式启用机制、二进制兼容与信任边界应在扩展契约任务中具体设计，未选定任意JAR自动装载方案。

若完整本地覆盖被纯运行时生成数据或缺失原始素材阻塞，应保存具体证据，作为目标阻塞处理，再讨论必要方案；不能把这部分排除后宣称目标完成。

## 交付顺序建议

建议先按既定范围完成0.7.3的最后整体验算与文档收口，获得开发者明确版本完成/提交授权后再推送；新增开放框架和完整覆盖建议作为0.7.4的单一目标，不将各任务拆成多个小版本。版本号与收口提交安排仍是建议，不据此开始下一版本代码或创建提交。


2026-10-26最新执行指令：仅完成0.7.3提交推送，后续计划等待开发者要求；本记录不作为立即开启后续开发的指令。
