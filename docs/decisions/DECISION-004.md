# DECISION-004：V0.3 采用多级地图块浏览架构

- **状态**：已实施并于 2026-07-29 通过开发者人工验收
- **确认日期**：2026-07-27
- **确认人**：项目开发者
- **适用版本**：V0.3 及后续二维地图浏览器

## 决策背景

V0.2.1 以固定中心生成单张 `512 × 512` PNG，适合快速预览，但不能支持任意已有区块间的自由拖动、围绕指针缩放、坐标跳转和局部缓存复用。

开发者确认 V0.3 的地图应允许当前图像完全离开视口，并在拖入新区域后自动后台加载；曾经浏览过的区域需要在本次运行和重新启动后继续复用。地图还需要支持 `1、2、4、8、16 方块/像素` 五级缩放，并在存档发生变化后只更新受影响区域。

这些要求会长期影响地图坐标、缓存身份、任务调度和 UI 组件边界，因此作为重大技术决策记录。

## 备选方案

### 方案一：多级地图块

将世界按固定像素大小切分，并为每个方块/像素级别分别生成和缓存地图块。视口只请求当前可见地图块，缓存命中立即显示，未命中时逐块生成。

优点：

- 支持任意已有区块间连续浏览。
- 拖回旧区域和重新启动后可以精确复用。
- 可以按 Region 变化只废弃受影响地图块。
- 地图块完成一个显示一个，适合渐进加载。
- 坐标定位、标记叠加和当前视口导出具有稳定坐标基础。

缺点：

- 需要新增地图块坐标、五级缓存、视口调度和任务优先级。
- 首次浏览大范围或最远缩放时仍可能需要处理大量已有区块。
- 磁盘缓存会随浏览范围增长。

### 方案二：动态视口截图

每次拖动停止后，围绕当前中心重新生成一张完整视口图片。

优点是可以较多复用现有单图生成入口；缺点是相邻视口大量重叠、拖回旧区域难以精确复用、缩放缓存身份不稳定，无法自然实现逐块渐进显示。

### 方案三：按 Region 生成图集

每个 `.mca` Region 对应一张固定地图图像，再由界面拼接。

优点是与存档文件边界一致；缺点是五级缩放仍需要额外汇总层，地图块尺寸受 Region 结构绑定，跨 Region 标记和当前视口调度仍需独立实现。

## 最终选择

采用方案一：多级地图块架构。

核心约束：

- 地图块固定为 `256 × 256` 像素。
- 支持 `1、2、4、8、16 方块/像素` 五个离散级别。
- 地图块身份包含世界、维度、图层/高度范围、缩放级别、地图块坐标和渲染版本。
- 当前视口中心附近的地图块优先，并采用有上限的后台并发。
- 本次运行使用有上限的内存缓存，跨启动使用程序根目录 `cache/` 下的磁盘缓存。
- Region 文件新增、删除、大小变化或修改时间变化时，只让覆盖该 Region 的地图块失效。
- 有效缓存默认不自动删除；界面提供二次确认的“清理当前世界缓存”按钮，并清理该世界已有的 V0.2.1 静态预览缓存。
- 所有地图读取保持只读，不向 Minecraft 存档或 AppData 写入数据。
- V0.2.1 的统一维度与图层系统继续复用，不为各维度复制地图浏览架构。

完整设计见 `docs/superpowers/specs/2026-07-27-v0.3-map-browser-design.md`。

## 对现有实现的影响

- 保留现有 `WorldDimension`、`PreviewLayer`、Region 解压、区块解析、地表/高度带采样和方块颜色能力。
- 新增独立地图视口、地图块键、缓存、生成、调度、标记和视口导出组件。
- `MainController` 只连接世界、维度、图层和顶层命令，不继续承载地图内部任务与缓存状态。
- V0.2 的单张 PNG 导出升级为当前视口所见即所得导出，不移除导出能力。
- 严格便携存储决策 `DECISION-001` 和统一图层决策 `DECISION-003` 继续生效。

## 长期影响

后续二维地图能力应建立在地图块坐标和视口模型上，不重新引入重叠的动态大图缓存。新增标记类型可以使用统一标记叠加层，但不得借此提前实现 V1.0 三维浏览、V2.0 自动巡航或 V3.0 动态壁纸。

多级地图块缓存可能持续增长。V0.3 已确认采用用户主动清理当前世界缓存，不加入自动容量淘汰；未来若要增加全局容量上限或自动清理策略，需要单独评估对跨启动复用的影响。

## 2026-07-28 体验修订

开发者在 V0.3 人工体验检查中确认：

- 初次打开存档和首次切换维度默认显示地表总览。
- 标记开关使用与地图一致的绿色、黄色和紫色圆点，并同时作为图例。
- 滚轮期间允许使用连续视觉比例缩放当前内存画面，停止后吸附到最近的五级缓存。
- 目标级别加载期间保留并临时拉伸旧级别图块，未缓存区域中心优先渐进显示。
- 局部快照不进入完整缓存、不写磁盘、不参与导出。

该修订不增加任意倍率磁盘缓存，不改变五级地图块身份、Region 精确失效和严格便携存储，因此作为本决策的交互与调度补充，不更换多级地图块架构。

详细设计见 `docs/superpowers/specs/2026-07-28-v0.3-map-experience-revision-design.md`。

## 2026-07-29 多人玩家标记扩展

开发者确认 V0.3 从仅显示 `level.dat -> Data.Player` 的单玩家位置，扩展为优先读取当前存档 `playerdata/*.dat` 中全部有效玩家的最后保存位置。

已确认规则：

- 玩家文件保持严格只读，单个损坏文件不得影响其他玩家或地图。
- 玩家名称优先从世界附近的 `usernamecache.json`、`usercache.json` 解析，缺失时回退短 UUID。
- 工具栏使用“玩家列表”菜单，不增加常驻侧栏。
- 点击玩家后自动切换到对应维度，强制使用地表总览和 `2 方块/像素`，并以玩家坐标为中心。
- 玩家所在维度未被发现时保留信息并明确提示，不猜测其他维度。
- 有有效 `playerdata` 时由该集合提供玩家标记；没有有效结果时继续兼容现有 `level.dat` 单玩家位置。
- 玩家集合只保存在运行时，不进入地图瓦片缓存，也不写入存档。
- 保持现有玩家与传送门绘制顺序，本次不增加标记避让或聚合。

该扩展不改变多级地图块身份、Region 失效、缓存目录和地图并发架构，但会长期确定玩家数据来源、名称回退和跨维度导航行为，因此记录为本决策的正式补充。

详细设计见 `docs/superpowers/specs/2026-07-29-v0.3-multiplayer-markers-design.md`。
