# DECISION-006：二维与三维共享方块状态解析核心

- **状态**：已确认
- **确认日期**：2026-08-03
- **确认人**：项目开发者
- **适用范围**：V0.5 及后续二维与三维开发

## 背景

二维与三维各自维护 Palette 和位存储解码会造成兼容修复重复及结果分歧，而实验原型不适合作为正式模块直接扩展。

## 最终选择

- 正式方块状态、Section 和 Chunk 解析由共享核心提供，数据与网格模型不依赖 JavaFX 或 LWJGL。
- 二维通过适配层消费共享结果，必须保持既有地图行为与缓存格式。
- 正式三维数据、读取、网格和 OpenGL 组件逐层建立；实验目录只保留验证入口与历史证据。

## 不可变边界

解析兼容修复原则上只在共享核心实现一次；二维迁移必须通过固定样本和完整回归证明没有行为退化。GPU 资源仍由明确的渲染线程和上下文管理。

## 影响

后续二维和三维共享完整方块状态来源，同时允许各自使用适合的采样、网格和显示层。
