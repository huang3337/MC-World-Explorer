## 自动解析链路

选区实际 Name/Properties → namespace:block_id → blockstates 的 variants/multipart → models 的父继承与 elements → textures 变量/资源 ID → PNG/材质 → 有界图集与网格。

存档中的 palette 是名称与状态入口，不包含完整贴图或模型。客户端资源中的 JSON 引用负责选模型和纹理；启动器 assets 索引不能直接替代这条链路。按需解析当前选区使用的状态，避免启动时枚举所有可能状态或把全部客户端贴图塞进单张图集。

## 测试样本与覆盖口径

样本用于验证语义，不限制允许运行的方块集合：

| 类型能力 | 代表样本/检查点 |
|---|---|
| 完整立方体、不同材质/轴向/tint | 既有 8 种/11 状态回归；新增未登记的完整块名；合成 Mod namespace 同结构模型，证明不依赖 minecraft 或名称白名单 |
| 部分尺寸与组合 | 多材质台阶上下/双层、楼梯上下半/朝向/内外角；新增不同名称复用同结构 |
| multipart 与条件组合 | 栅栏、墙、玻璃板等连接状态；检查 AND/OR 与多部件叠加 |
| 部分面、旋转与裁剪 | 地面/墙上火把、交叉植物、门等，核对超出单格坐标、非直角元素旋转、薄片/透明轮廓 |
| 资源引用 | 父模型、多级变量、命名空间、缺失 PNG、循环、非法路径/JSON、版本不同、预算耗尽与可追踪来源 |
| 集成 | 新增实际方块无须改支持列表；已有完整方块保持；实际覆盖范围遮挡、边界、缓存、取消、窗口与只读回归 |

不以“五个名字/51 分支全部通过”作为完整完成标准。门禁必须验证：主链路无方块白名单或手工纹理配对；完整 Properties 不被名称特例静默丢弃；已支持的模型表达对任意合规资源 ID 自动生效；覆盖报告将标准解析、缺资源、特殊渲染、非法/超限分别统计。总体目标覆盖所有类型，尚不支持的类型必须明示并逐类补齐，不能无声退回旧完整立方体。

容量仍须有界。状态、模型和图片缓存按完整状态、资源来源指纹/优先级和解析版本区分；图集预算增长应明确分页或降级策略，不能仅移除白名单后使单场景准备无上限。兼容特例只能针对已有证据的语义差异集中处理。

## 特殊类型与 Mod 边界

标准资源表达的方块默认尝试，无名称、版本或 namespace 开放白名单。自定义 loader、实体/方块实体、内置特殊渲染和动态流体等进入“类型适配”清单，不凭静态 PNG 宣称正确。不能保证只靠标准模型覆盖任意 Mod 的运行时代码；未来通过资源源叠加和渲染类型适配扩展，保持错误可见与简化备用。

本版本首先打通标准模型的通用链路；特殊类型不能被混入“普通几何成功”统计，剩余类型的实施进度必须单列。动态光照、动画系统、自由流送、框架迁移不因本次方块资源方向调整自动加入。

### 已核对的事实

- 真实三维任务仅打开所选客户端 JAR；资源源叠加接口尚未接入 Mod 归档、实例启用资源包或存档资源。标准 Mod 模型即使表达已支持，也可能因根本未提供素材而降级。不能把所有降级都归为模型解析能力不足。
- 当前标准解析还会拒绝未登记的 root 字段（包括 loader、credit 等）及越界 UV 重复采样等表达。署名/编辑器元信息应与影响几何/材质的未知字段区分，不能统一忽略来虚报兼容。
- 项目配置指向本机 D:/MC/.minecraft，该目录包含多个独立实例及 Mod 归档。只读抽查“你好，新蒸程V1.5.9”的 chipped-neoforge-1.21.1-4.0.2.jar：6981 个 blockstates；前 15000 个可解析模型 JSON 没有声明 loader，27 个含 credit 字段。该样本说明资源接入及标准字段兼容有实际价值；不是全包统计，也未确认是开发者刚才测试的选区或其实际降级清单。
- NeoForge 1.21–1.21.1 官方说明支持 loader 分发，以及 composite、elements、empty、OBJ/MTL 等表达；可按 loader ID/格式实现一次后复用同类资源。Fabric 官方教程也明确部分模型直接由 Java BakedModel/BlockEntityRenderer 生成，静态 JSON 不一定含足够几何。不能承诺静态解释器覆盖任意运行时代码。

资料：[NeoForge 1.21–1.21.1 Custom Model Loaders](https://docs.neoforged.net/docs/1.21.1/resources/client/models/modelloaders/)、[Fabric 自定义模型](https://wiki.fabricmc.net/tutorial:custom_model)。

### 待选择的推荐方向

先把“当前选区所处实例”作为资源上下文，按实际启用顺序合并资源包、对应 Mod 及原版；优先自动定位、歧义时允许手动指定，绝不混入其他整合包的 Mod。按实际使用的 namespace/状态按需读取，缓存纳入归档内容/顺序/版本指纹；多 Mod 归档预算需独立设计，不能简单把目前 16 层接口上限当作整合包最大 Mod 数。

随后按实际方块出现次数统计缺资源、未知字段/标准表达、自定义 loader、依赖邻域/NBT、预算失败及无静态几何等原因。先处理标准资源兼容，再依据统计适配 composite/elements/root transform、OBJ/MTL 或其他常用格式；按 loader/格式复用，不逐方块手工配纹理。纯运行时形体保留明确诊断；以后可单独评估由用户在匹配游戏环境中导出烘焙结果的可选桥接，当前不据此启动 Minecraft 或执行 Mod。
