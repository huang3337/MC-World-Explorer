# V0.8.0 开发与验证记录

完成日期：2026-11-27

## 背景与问题根因

在 `0.7.9` 及更早版本中，增强档大选区（如 `16 × 16 = 256` 区块）跨越多个群系过渡带时，Minecraft 的 `5 × 5` 群系混合采样与种子扰动会产生数百至上千种渐变的草色、叶色与水色 RGB 值，触发双重预算膨胀：

1. **`TextureAtlas` 贴图数膨胀**：CPU 阶段按 `(基础纹理, 群系 RGB)` 组合逐一烘焙独立 `BufferedImage` 写入图集，极易触顶 `1024` 贴图上限并报 `纹理图集单项尺寸或数量超限`，导致后遍历的草方块、树叶、矮草等退化为纯色简化块。
2. **`BlockTintPreparation` 合成状态膨胀**：为每种颜色组合克隆带 `__mcwe_tint` 属性的 `BlockState`，持续占用 `MAX_STATES = 4096` 与 `32768` 模型面暂存预算。

## 开发目标

1. 升级三维网格顶点格式与 OpenGL 3.3 着色器（`/v05/shaders/voxel.vert`、`/v05/shaders/voxel.frag`），使 `OPAQUE`、`CUTOUT`、`TRANSLUCENT`、`FLUID` 全部支持逐面/逐顶点基础颜色（`aMaterial`）与可选共面第二层遮罩纹理坐标及颜色（`aOverlayUv`、`aOverlayMaterial`），在单次片元绘制内按 Porter-Duff `source-over` 公式实时合成后再乘方向光 `brightness`，消除共面深度闪烁（Z-fighting）并保持每个草方块严格为 6 个 `OPAQUE` 面，不破坏 `ModelOcclusion` 邻面剔除。
2. 解除 `TextureAtlas` 与 `BlockTintPreparation` 对群系/状态颜色的 CPU 预烘焙耦合：同一基础贴图在 `TextureAtlas` 中仅存 1 份未染色原图，将 `TextureAtlas.MAX_TILES` 提升至 `2048`、`MAX_SIZE` 提升至 `4096`（保持按实际高度 2 的幂分配）；`BlockTintPreparation` 改为在稀疏区段索引中记录世界位置对应的颜色调色板（`tintIndex -> rgb`），不再克隆 `__mcwe_tint` 合成 `BlockState`，解除颜色渐变对 `MAX_STATES = 4096` 与 `32768` 模型面预算的占用。
3. 支持 `forge:composite` / `neoforge:composite` 跨 `render_type`（如 `minecraft:solid` 底座叠加 `minecraft:cutout` 遮罩）共面双层合并，保留 `forge_data` / `neoforge_data` 静态材质覆盖及自发光静态层的 CPU 一次合成语义，区分未绑定处理器（`UNBOUND_TINT`）与缺失世界颜色输入（`TINT_UNRESOLVED`）两类降级诊断，完整保留客户端颜色表来源与数据包群系来源说明，并确保 `FluidGeometry` 保留水流面染色元数据。
4. 更新 `VoxelPreviewCoordinator.RENDER_VERSION` 为 `"v080-vertex-tint-1"`、同步 `ViewerSceneCache.estimatedBytes` 字节估算，版本号与构建目录递增至 `0.8.0`（`build/core-0.8.0`），不修改 `experimental/v04` 或 `experimental/v05` Java 类。

## 实际完成

- **顶点格式与 OpenGL 着色器升级（`voxel.mesh`、`voxel.render.lwjgl`、`/v05/shaders/`）**：
  - `MeshBatch`：扩展支持 `vertexRgb`、`overlayTextureCoordinates` 与 `overlayRgb`（`-1` 表示无遮罩，`0..0xFFFFFF` 表示遮罩颜色），完整保留原有 7/8/9 参构造器以兼容既有调用方，补齐数组非空校验、遮罩 UV 对基础 UV 的前置校验以及 `vertexColor(int)` / `hasOverlay(int)` 的 `Objects.checkIndex` 顶点下标边界检查。
  - `voxel.vert` / `voxel.frag`：扩展至 7 个顶点属性（13 个 32-bit 单元 / 52 字节步长：`aPosition`、`aNormal`、`aUv`、`aMaterial`、`aAlpha`、`aOverlayUv`、`aOverlayMaterial`），其中 `aMaterial` 的 `bit 26` 标记 `hasOverlay`；片元着色器在 `vHasOverlay > 0.5` 时采样 `vOverlayUv` 并乘以 `vOverlayColor`，按 Porter-Duff `source-over` 公式与底层纹理合成后再乘方向光 `brightness`。
  - `OpenGlMeshResources`、`TranslucentFaces`、`LwjglSceneRenderer` 与 `VoxelShaderProgram`：统一采用 13 浮点步长与 `glVertexAttribIPointer` 上传整数材质属性，所有渲染层统一启用 `uVertexMaterial = true` 并绑定 `uAtlas` 至纹理单元 `0`。
  - `ViewerSceneCache.estimatedBytes`：准确计入 `MeshBatch` 可选逐顶点颜色与遮罩 UV/颜色数组的内存占用。
- **`TextureAtlas` 去群系染色化与 `BlockTintPreparation` 稀疏调色板解耦（`voxel.resource`）**：
  - `TextureAtlas`：`MAX_TILES` 提升至 `2048`、`MAX_SIZE` 提升至 `4096`（仍按实际行高取 2 的幂分配），暴露 `tileCount()` 供测试与诊断核验。
  - `BlockTintResolver` 与 `BlockTintPreparation`：不再向 `states` / `resolved` 注入 `__mcwe_tint` 合成 `BlockState`；在状态准备阶段通过 `dynamicBoundIndices` 预先登记所有已绑定的位置依赖索引并先行应用同模型上的静态常量/状态颜色（`staticColors`），避免仅出现在 1 格邻区边界或缺失种子/群系输入的已绑定方块误报 `UNBOUND_TINT`；在有界稀疏区段索引（`MAX_SECTIONS = 2048`、`MAX_PALETTES = 65535`）中记录 `area.target()` 范围内位置对应的去重 `TintPalette`，并对失败说明与预算溢出说明统一做单状态去重。
  - `BlockTextureSet`：`Surface` 扩展 `tintIndex`、`staticRgb`、`overlayUv`、`overlayTintIndex`、`overlayStaticRgb` 及 `withFluidGeometry(...)`（保留 8/9 参旧构造器）；非自发光烘焙模型保持未染色原图入图集，共面双层叠加（含原版 `grass_block` 侧面及 `forge:composite`/`neoforge:composite` 的 `solid` + `cutout` 共面部件）合并为单个 `Surface`，按底层与顶层各自的 `singleMaterial` 合成不透明度判定 `RenderLayer`（草方块与复合方块保持 6 个 `OPAQUE` 面与完整 `1×1×1` 遮挡盒），3 层及以上叠层回退输出独立非遮挡面；含 `minimumLight > 0` 或 `shadeDirectionOverride != null` 的静态光照模型保持 CPU 一次合成语义；将未绑定处理器的说明归为 `UNBOUND_TINT`（`Severity.DEGRADED`），将已绑定处理器但缺失世界输入或超出位置调色板预算的说明归为 `TINT_UNRESOLVED`（`Severity.DEGRADED`）。
- **网格取色与流体兼容（`voxel.mesh`）**：
  - `FluidGeometry.surface(...)` 通过 `Surface.withFluidGeometry(...)` 构造水流斜面与旋转 UV，完整保留 `FLUID_WATER` 动态染色索引。
  - `ChunkMesher` 在输出可见纹理面时按世界坐标查询 `surfaceColor` 与 `overlayColor` 写入 `BatchBuilder`（无染色/无遮罩批次保持零额外数组分配），同层同 `shaded` 纹理面合并至同一 `MeshBatch`。
- **缓存版本、版本号与测试覆盖**：
  - `VoxelPreviewCoordinator.RENDER_VERSION` 更新为 `"v080-vertex-tint-1"`；`build.gradle`、`tools/package-windows.ps1` 与文档引用递增至 `0.8.0`（`build/core-0.8.0`）。
  - 适配 `OpenGlMeshResourcesTest`、`VoxelShaderProgramTest`、`TextureAtlasTest`、`LegacyClientTintFallbackTest`、`StandardBlockTintTest`、`StandardTintBoundaryTest`、`VanillaVegetationTintTest` 与 `ModalOverlayContractTest`；在 `TranslucentRenderingTest` 新增 OpenGL 3.3 双层遮罩单次片元合成像素读回测试；新增 `VertexBiomeTintAtlasScaleTest` 覆盖 800 种群系 / 500+ 渐变色压力验证、流动水染色保留、邻区边界/缺失群系诊断区分及 `neoforge:composite` 共面双层合并。

## 遇到问题

- 初次全量回归发现两项问题并修复：一是重构 `BlockTextureSet` 图像准备分支时漏计未拷贝原图的单状态工作内存，恢复按每个新 `PaintKey` 累加 `workingBytes` 后 `DynamicBlockResourcesTest` 32 MiB 预算门禁通过；二是 `ModalOverlayContractTest` 断言同步更新至 `core-0.8.0`。
- 代码审查发现并修复归档 4 项问题：
  1. `ISSUE-TINTPREP-002`（高）：仅出现在 1 格邻区边界或缺失种子/群系输入的已绑定方块此前未登记动态索引而误报 `UNBOUND_TINT`，且空颜色结果的失败说明未去重；改为在状态遍历阶段预先登记已绑定动态索引并统一经 `recordedDetails` 去重。
  2. `ISSUE-TEXTSET-010`（高）：`SurfaceKey` 原含 `renderType` 导致 `forge:composite`/`neoforge:composite` 中 `solid` 底层与 `cutout` 遮罩层无法合并而产生 `GL_LESS` 深度丢弃，且非 `UNBOUND_TINT` 的 `"颜色未解析："` 说明被标为 `INFO`；改为按 `(positions, normal, shaded, fluid)` 合并、分层判定材质并将 `"颜色未解析："` 统一标为 `DEGRADED`（`TINT_UNRESOLVED`）。
  3. `ISSUE-V05-BATCH-002`（中）：补齐 `MeshBatch` 数组参数非空校验、遮罩 UV 对基础 UV 的前置校验及 `vertexColor`/`hasOverlay` 的 `Objects.checkIndex` 越界检查。
  4. `ISSUE-TINTBNDTEST-001`（高）：同步更新条件跳过的真实客户端边界测试 `StandardTintBoundaryTest` 至 `0.8.0` 单一未克隆状态与逐坐标 `surfaceColor` 契约。

- 代码审查修复归档 4 项（`ISSUE-TEXTSET-010`、`ISSUE-TINTPREP-002`、`ISSUE-V05-BATCH-002`、`ISSUE-TINTBNDTEST-001`）。
