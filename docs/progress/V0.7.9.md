# V0.7.9 开发与验证记录

完成日期：2026-11-26

## 开发目标

1. 新增国内免翻墙双源只读检查更新模块（Gitee 优先、GitHub 自动静默回退），软件内不解析或展示任何网盘链接，严格限制外部浏览器打开的受控域名白名单。
2. 实现启动后后台守护线程静默检查更新，发现未忽略的新正式版时不弹启动打扰窗口，仅在顶栏 `[关于]` 按钮右上角显示小蓝点提示；在「设置 → 常用」提供自动检查更新开关。
3. 在主窗口根部建立统一的「软件内模态遮罩卡片」（不创建额外 OS 子窗口 `Stage`/`Dialog`），承载：
   - 重构后的「关于」卡片（消除 `ScrollPane` 与卡片容器蓝色焦点外框、作者 B站主页超链接 `https://space.bilibili.com/424431265`、常驻直达最新 Release 的 Gitee 与 GitHub 双仓库超链接、内置手动检查更新并在发现新版本时于预留空位展开醒目提示框指引自行下载 `.zip` 且关闭界面后自动消失）；
   - 前往仓库前的个人数据与缓存保留二次确认卡片；
   - 新便携包首次打开自动弹出的「导入旧版数据」卡片，并在「设置 → 常用」提供常驻补导入口。
4. 补齐 Windows 便携包打包脚本的 `jdk.crypto.ec` 模块以支持 HTTPS 握手，版本号递增至 `0.7.9`（`build/core-0.7.9`），不提前改动 `TextureAtlas` 或三维群系着色管线。

## 实际完成

- **双源只读更新检查（`com.mcworldexplorer.update`）**：
  - `AppVersion`：读取 `/mcwe-build.properties` 当前版本，实现语义化版本解析与比较（正式版高于同版本号 `-SNAPSHOT`）。
  - `AllowedExternalUrls`：所有外部浏览器打开仅允许 `https://` 且严格校验域名白名单（`gitee.com`、`github.com`、`space.bilibili.com`），提供 `GITEE_LATEST_RELEASE_URL`（`https://gitee.com/huang3337/MC-World-Explorer/releases/latest`）与 `GITHUB_LATEST_RELEASE_URL`（`https://github.com/huang3337/MC-World-Explorer/releases/latest`）并校验同仓 Release 页面路径。
  - `UpdateCheckClient`：优先以直连方式请求 `https://gitee.com/api/v5/repos/huang3337/MC-World-Explorer/releases/latest`；当超时、连接失败、返回 `404` / 空对象 `{}` / 空数组 `[]` / 缺少合法 `tag_name` 或响应超限时，自动静默回退请求 `https://github.com/huang3337/MC-World-Explorer/releases/latest`（携带 `Accept: application/json`，规避 `api.github.com` 未认证共享出口每小时 60 次 `HTTP 403` 限流，并支持系统代理与直连双路容错）。针对无 `html_url` 的响应结构，基于已校验 `tag_name` 构造同仓 `/releases/tag/<tag>` 地址，跨源默认回退地址统一指向 `/releases/latest`。连接超时 `4s`、单源读取超时 `5s`、响应体上限 `64 KiB`、JSON 嵌套深度上限 `16`，跳过 `draft` 与 `prerelease`，更新摘要过滤 URL 与网盘文本，不解析或展示任何网盘链接。
- **便携配置与旧版数据安全迁移（`com.mcworldexplorer.storage`）**：
  - `PortableSettings`：新增 `check_updates_on_startup`（默认 `true`）、`last_update_check_epoch_ms`（12 小时冷却）、`ignored_update_version`、`first_run_completed` 及首启判断（排除开发工程根目录干扰）。
  - `LegacyDataImporter`：只读复制合并旧版 `config/`（`settings.properties`、`places/`、`model-plugins/`）与 `cache/`，拒绝当前目录自身、父子嵌套目录、符号链接/重解析点越界及超限文件，不删除或修改旧目录原文件。
- **软件内模态遮罩层与交互闭环（`com.mcworldexplorer.ui`、`main.fxml`、`styles.css`）**：
  - `main.fxml` 根部调整为 `StackPane`（`appRoot`），包裹底层 `workspaceSplitPane` 与顶层 `modalOverlay`（拦截底层鼠标、滚轮与键盘事件并迁移焦点，支持 `Esc` 关闭「关于」卡片或从确认卡片返回）；顶栏 `aboutButton` 外层包裹自适应尺寸 `StackPane` 与左侧按钮严格垂直居中对齐，并在右上角提供小蓝点 `aboutUpdateBadge`。
  - `styles.css` 新增 `.modal-overlay`、`.modal-card`、`.modal-scroll:focused`、`.scroll-pane:focused`、`.update-badge-dot` 与 `.update-alert-box` 样式，消除点击「关于」卡片空白处残留蓝色焦点框的问题并提供醒目更新提示框视觉样式。
  - `AboutDialog` 重构为提供三张软件内模态卡片：「关于」卡片常驻展示直达最新 Release 的 Gitee 与 GitHub 超链接（点击均进入保留缓存二次确认卡片），`aboutUpdateBox` 默认隐藏，仅在当次打开界面点击「检查更新」发现新版本时展开醒目提示框指引前往常驻链接自行下载新版 `.zip`，关闭卡片后重置消失、再次检查更新重新出现；同时保留测试兼容包装入口。
  - `MainController` 接入启动静默检查、顶栏小蓝点刷新、首启导入卡片弹出与导入后热刷新（深浅色主题、扫描并发、三维缓存档位、存档库目录与当前存档地点标记）。
  - `SettingsDialog` 在「设置 → 常用」新增「启动时自动检查更新」复选框与「从旧版目录导入数据…」常驻按钮，并在导入成功后同步回填当前设置面板各控件状态。
- **打包与构建配置**：
  - `Launcher`、`run-app.bat`、`build.gradle` 与 `tools/package-windows.ps1` 默认启用 `-Djava.net.useSystemProxies=true`；`tools/package-windows.ps1` 的 `--add-modules` 更新为 `'java.se,jdk.unsupported,jdk.crypto.ec'`，构建输出目录与版本递增至 `0.7.9`（`build/core-0.7.9`）。

## 遇到问题

- `UpdateCheckClientTest` 首次运行时，本地回环 `HttpServer` 默认单线程执行器在 `/gitee-slow` 模拟超时睡眠期间阻塞了同进程 `/github` 回退请求；为测试服务器配置并发线程池后，超时自动回退测试稳定通过。
- `run-app.bat` 实机联调发现三项问题并完成修复：一是顶栏包裹 `aboutButton` 的 `StackPane` 默认撑满顶栏高度且设为 `TOP_RIGHT` 导致按钮上偏，限定 `maxHeight="-Infinity"` 与居中对齐后恢复水平基线一致；二是 Gitee 尚未发布首个 Release 返回 `404` 后，JVM 默认未开启系统代理且 `api.github.com` 触发共享出口每小时 60 次 `HTTP 403` 限流，切换 GitHub 回退源为 Web JSON 端点（`/releases/latest` + `Accept: application/json`）并启用系统代理与直连双路容错后，实机连通恢复正常；三是 `WorkspaceAppearance` 原先绑定在 `SplitPane` 内部节点 `mapSurface` 上，导致首帧 `SplitPaneSkin` 创建中途才挂载 `styles.css` 并刷出近 300 条 `CssStyleHelper` 未解析变量警告，改为在 `MainController.initialize` 提前绑定顶层根节点 `appRoot` 后，首帧 CSS 警告降为 0。
