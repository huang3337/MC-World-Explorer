# V0.8.1 开发与验证记录

完成日期：2026-11-27

## 背景与立项依据

针对开源社区在 GitHub Issue #1 提出的无桌面界面复用需求（例如第三方存档转换器直接在 Java 工程中引入核心库，只读解析生成的 Minecraft 世界并导出三维模型或二维地图），并确保后续版本中 SDK 与桌面客户端保持单源演进、零代码分叉、零 UI/OpenGL 反向污染，按 [DECISION-025](../decisions/DECISION-025.md) 立项实施 `0.8.1`。

## 开发目标

在严格保持 [DECISION-024](../decisions/DECISION-024.md) 纯本体交付与只读安全边界（不恢复已退出的专用 Mod 适配或旧插件脚手架生成器）的前提下完成以下目标：

1. 将单模块 Gradle 工程物理拆分为无 UI 核心库 `:mc-world-explorer-sdk`（`sdk/`）与桌面应用 `:mc-world-explorer-app`（`app/`），由 `javac` 编译期依赖图物理隔离 JavaFX、Ikonli 与 LWJGL，桌面端直接依赖 `:mc-world-explorer-sdk` 实现一次修改、双端同步生效。
2. 统一维护根工程版本号 `0.8.1`（构建树 `build/core-0.8.1/`）、`/mcwe-build.properties` 唯一归属、双模块测试工作目录与插件隔离系统属性、GNU GPL v3.0 Maven 发布配置、JitPack 构建配置（`jitpack.yml`）与 `assembleSdkDist` 分发汇总任务，适配 `tools/package-windows.ps1` 并升级 `verifyCoreIsolation` 增加 SDK 零桌面端/OpenGL 字节码纯净度门禁。
3. 在 `com.mcworldexplorer.sdk` 包中提供无头高层门面（`WorldExplorerSdk`、`McWorld`、`SceneBuildRequest`、`MapRenderRequest`、`WavefrontObjExporter`、`ObjExportResult`），支持零客户端 JAR 纯色三维 `.obj` + `.mtl` 导出、带客户端/实例资源及 `0.8.0` 逐顶点群系着色与双层共面遮罩（含旋转/高分辨率遮罩）Porter-Duff `source-over` 烘焙 `.obj` + `.mtl` + `_atlas.png` 导出，以及无头二维 PNG 地图导出。
4. 补齐 SDK 全链路单元测试、高分辨率旋转遮罩烘焙与取消清理测试、极端坐标与路径穿越防护测试、许可证与零 UI/GL 污染契约测试，编写 `docs/SDK_GUIDE.md`、`docs/releases/V0.8.1.md` 并同步 `README.md`、结构、发布与进度文档。

## 实际完成

- **架构决策记录**：
  - 新增 [DECISION-025](../decisions/DECISION-025.md) 并更新 [决策索引](../decisions/README.md)。
- **Gradle 物理双模块拆分与构建门禁**：
  - 使用 `git mv` 将无 UI 核心包（`world`、`nbt`、`region`、`storage`、`preview`、`map`、非 LWJGL 的 `viewer`、`voxel/{data,io,mesh,resource}` 及 `model-protocols/`、`vanilla-protocol/`）迁移至 `sdk/`，将桌面端包（`Launcher`、`App`、`ClientRuntime`、`WindowsGraphics`、`ui`、`update`、`viewer/lwjgl`、`voxel/render/lwjgl`、`experimental` 及桌面端资源）迁移至 `app/`，保留完整文件重命名历史且未修改 `experimental/v04` 或 `experimental/v05` 内部逻辑。
  - 配置 `settings.gradle`、根 `build.gradle`、`sdk/build.gradle`（`java-library` + `maven-publish` + `sourcesJar` + `javadocJar`，仅依赖 `adventure-nbt`、`gson`、`joml`、`slf4j-api`，POM 声明 `GNU General Public License v3.0`）、`app/build.gradle`（`application` + JavaFX，依赖 `project(':mc-world-explorer-sdk')` 并显式绑定 `compileTestJava -> :mc-world-explorer-sdk:testClasses`）、`jitpack.yml` 及 `tools/package-windows.ps1`（区分大小写精确筛选桌面端主 JAR）。
  - 唯一在 `:mc-world-explorer-sdk` 生成 `/mcwe-build.properties`；为双模块 `test` 任务统一配置 `workingDir = rootProject.projectDir` 与 `mcwe.plugin.*` 系统属性；升级根级 `verifyCoreIsolation`，拦截全部 `0.7.4` 延期类并对 `mc-world-explorer-sdk-0.8.1.jar` 全部 `.class` 条目执行零 `javafx/`、`org/lwjgl/`、`org/kordamp/ikonli/`、`ui/`、`update/`、`viewer/lwjgl/`、`voxel/render/lwjgl/`、`experimental/`、`App`、`Launcher` 字节码扫描门禁。
- **无 UI 开发者 SDK 与导出器（`com.mcworldexplorer.sdk`）**：
  - `WorldExplorerSdk`：提供 `version()`、`openWorld(Path)` 与 `scanWorlds(Path)` 静态只读入口。
  - `McWorld`：提供维度查询、`buildScene(ChunkRectangle)`、`buildScene(SceneBuildRequest)`、`exportWavefrontObj(SceneBuildRequest, Path, String)`、`renderMapImage(MapRenderRequest)` 与 `exportMapPng(MapRenderRequest, Path)`；对维度 `region` 目录与 `.mca` 文件执行 `toRealPath()` 与符号链接拦截，缺失 `region` 目录时安全返回空白底色图，全程不写入磁盘缓存。
  - `SceneBuildRequest` 与 `MapRenderRequest`：提供不可变参数构建器，内置维度规范化、选区/输出像素/采样区块上限校验，通过 `Math.subtractExact` 与 `Math.toIntExact` 拦截极端负坐标下溢与区块整数越界并统一抛出 `IllegalArgumentException`。
  - `WavefrontObjExporter` 与 `ObjExportResult`：严格校验 `baseName` 防止路径穿越；无纹理批次按 `(layer, rgb, alpha)` 生成标准 MTL `Kd`/`d` 材质；带纹理批次通过量化规范角点仿射映射（`OverlayMapping`）支持旋转/镜像及高分辨率遮罩层与底层的 Porter-Duff `source-over` 合成，输出带 1 像素挤出边缘的 `{baseName}_atlas.png`（最大行宽 `4096`，按实际使用尺寸裁剪）并翻转 Wavefront OBJ `vt` V 轴（`1.0 - v`）；支持 `CancellationSignal` 协同取消并采用同目录临时文件暂存原子替换，异常或取消时不残留半成品文件。
- **测试覆盖与正式文档收束**：
  - 新增 `WorldExplorerSdkTest`、`WavefrontObjExporterTest` 与 `SdkPurityContractTest`（3 套共 10 项测试），扩充 `ModalOverlayContractTest` 打包脚本契约断言。
  - 新增 [SDK 使用指南](../SDK_GUIDE.md) 与 [0.8.1 版本说明](../releases/V0.8.1.md)，在根 [README.md](../../README.md) 补充无 UI 开发者 SDK 简要说明并引导至 `docs/SDK_GUIDE.md`，同步更新 [项目结构](../../PROJECT_STRUCTURE.md)、[上传与发布](../RELEASING.md)、[文档目录](../README.md)、[后续版本范围](DEFERRED_WORK.md)、[版本进度索引](README.md) 与 [当前状态](CURRENT.md)。

## 遇到问题

- 拆分后 `:mc-world-explorer-app` 测试中的 `WorkspaceLayoutTest` 引用了位于 `sdk` 测试源集的 `MapSamplingFixtures`；在 `app/build.gradle` 配置 `testImplementation project(':mc-world-explorer-sdk').sourceSets.test.output` 并显式声明 `compileTestJava` 依赖 `:mc-world-explorer-sdk:testClasses` 后，清空构建缓存后单跑或全量运行均稳定通过。
- 初次编写双模块构建脚本时 `junit-platform-launcher` 误写为 `5.10.2`，修正为离线缓存已有的 `1.10.2` 后恢复离线通过。
- 六维代码审查与便携包实测共发现并修复归档 6 项问题（🔴 严重 1 项 / 🟠 高 4 项 / 🟡 中 1 项）：
  1. `ISSUE-BUILD-005`（严重）：`sdk/build.gradle` 的 Maven POM 许可证原误写为 `MIT License`，与仓库 `LICENSE`（`GNU General Public License v3.0`）不符；修正为 GPL v3.0 并在 `SdkPurityContractTest` 增加契约断言。
  2. `ISSUE-BUILD-006`（高）：补齐 `:mc-world-explorer-app:compileTestJava` 对 `:mc-world-explorer-sdk:testClasses` 的任务依赖，并扩充 `verifyCoreIsolation` 与 `SdkPurityContractTest` 对 `update/`、`viewer/lwjgl/`、`voxel/render/lwjgl/`、`App`、`Launcher` 的字节码泄漏拦截。
  3. `ISSUE-MCWORLD-001`（高）：为 `McWorld.renderMapImage` 补齐 `toRealPath()` 与 `Files.isSymbolicLink` 越界防护及缺失 `region` 目录空图回退，并在 `exportWavefrontObj` 中打通 `CancellationSignal` 传递。
  4. `ISSUE-MAPREQ-001`（中）：修复 `MapRenderRequest` 在极端负坐标下的 `long` 减法下溢，并将 `MapRenderRequest` 与 `SceneBuildRequest` 的区块整数溢出统一封装为 `IllegalArgumentException`。
  5. `ISSUE-OBJEXP-001`（高）：在 `WavefrontObjExporter` 引入 `OverlayMapping` 仿射 UV 变换与 `Math.max` 高分辨率遮罩保留，扩容导出图集行宽至 `4096`，并改为临时文件暂存原子替换以保证异常或取消时零残缺文件残留。
  6. `ISSUE-PACKAGEWINDOWS-004`（高）：`tools/package-windows.ps1` 的 `-Filter 'MC-World-Explorer-*.jar'` 在 Windows 文件系统下不区分大小写，误匹配 `mc-world-explorer-sdk-0.8.1.jar` 中断打包；补充 `-cmatch '\AMC-World-Explorer-\d+\.\d+\.\d+(-SNAPSHOT)?\.jar\z'` 精确筛选并在 `ModalOverlayContractTest` 增加断言后恢复通过。
