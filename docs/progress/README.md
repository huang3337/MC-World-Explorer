# 里程碑 Progress 记录规范

`CURRENT.md` 是唯一持续更新的阶段状态记录，帮助读者快速判断正在进行的里程碑、主要能力、验证结论、剩余限制和下一门禁。其余 `Vx.x.md` 是对应里程碑完成时固定的历史概况；其中的“当前状态”只指该历史记录形成时的状态，不代表今天的项目状态。历史正文不因后续开发而改写，也不承担逐任务开发日志或问题档案职责。

## `CURRENT.md` 应包含

- 记录日期、当前里程碑和阶段状态。
- 一段明确的版本目标。
- 主要已实现能力，并区分自动化通过与人工验收完成。
- 验证概况，只记录结论、覆盖类型和只读证明，不罗列每次命令与测试数量。
- 未完成内容、活动问题、已知限制和下一项门禁；里程碑完成、提交、推送、打包和发布授权必须分开表述。

里程碑完成并经确认后，将其结论固定为对应的 `Vx.x.md` 历史记录，再把 `CURRENT.md` 更新为下一阶段的状态。任何时候只维护一份实时状态；历史记录中的事实和验收结论不得在整理时丢弃。

## 不应包含

- Task 逐步记录、逐文件修改清单、单次命令输出或依赖安装过程。
- 问题调查、尝试失败、修复过程和逐条审查证据；这些内容进入 `docs/issues/`。
- 协议字节布局、缓存键、状态机和测试矩阵；这些内容进入 `docs/specs/`。
- 方案比较或废弃架构；重大且仍有效的结论进入 `docs/decisions/`，详细计划保留在 `docs/superpowers/`。
- 本机绝对路径、临时产物路径、易失哈希或未获授权的发布产物。

阶段状态变化时直接更新 `CURRENT.md` 的概况。日期只用于标识记录、确认、完成或发布事实，不按日期追加开发流水章节。
