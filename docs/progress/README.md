# 里程碑 Progress 记录规范

`docs/progress/` 每个文件只描述一个版本里程碑的当前概况。它帮助读者快速判断目标、主要能力、验证结论、剩余限制和下一门禁，不承担逐任务开发日志或问题档案职责。

## 每个里程碑应包含

- 当前状态以及必要的开始、完成或发布日期。
- 一段明确的版本目标。
- 主要已完成能力，按用户或架构层面的结果概括。
- 验证概况，只记录结论、覆盖类型和只读证明，不罗列每次命令与测试数量。
- 当前未完成内容、已知限制或明确排除范围。
- 与下一里程碑之间的门禁；提交、推送、打包和发布授权必须分开表述。

## 不应包含

- Task 逐步记录、逐文件修改清单、单次命令输出或依赖安装过程。
- 问题调查、尝试失败、修复过程和逐条审查证据；这些内容进入 `docs/issues/`。
- 协议字节布局、缓存键、状态机和测试矩阵；这些内容进入 `docs/specs/`。
- 方案比较或废弃架构；重大且仍有效的结论进入 `docs/decisions/`，详细计划保留在 `docs/superpowers/`。
- 本机绝对路径、临时产物路径、易失哈希或未获授权的发布产物。

里程碑状态变化时直接更新当前概况。日期只用于标识确认、完成或发布事实，不按日期追加开发流水章节。
