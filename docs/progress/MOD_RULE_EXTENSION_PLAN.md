# 开放模型规则扩展与本地实例覆盖任务规划

- **建立日期**：2026-10-26。
- **文档性质**：开发者要求的正式任务规划与验收定义，不是运行报告或已完成实现。
- **需求状态**：开放扩展入口、按规则复用、本地已有Mod覆盖目标已确认，见[DECISION-018](../decisions/DECISION-018.md)。
- **执行状态**：本轮仅交付0.7.3；此规划保留，后续安排等待开发者新要求，不启动0.7.4。

## 目标与成功定义

让本地基线中的有效Mod资源及实际使用状态生成正确几何、UV、纹理、材质和上下文外观；多个实例可以同时使用不同规则。规则不绑定实例路径或整合包，后续加入使用相同规则的Mod能够直接加载。新规则通过公开接口注册，不修改界面、资源叠加和通用绘制流程。

“解析不抛异常”不足以通过：缺失部分模型、丢失透明度、错误连接、全部画成立方体、未知模型静默为空、紫色占位均需验收失败或明确记录阻塞。有意空模型须由声明或游戏行为证据确认，不能计作可见模型成功。资源文件中未被使用的无效示例/废弃声明需单列证据，不等同存档实际方块；也不得静默删除失败记录。

## 初步范围盘点（2026-10-26，仅目录元信息）

只读检查已配置D:/MC/.minecraft/versions和项目MC/versions：发现13个含Mod目录、3274份外层JAR副本、共22个有level.dat的存档。副本尚未按内容去重，不代表3274个独立Mod。含Mod但没有存档的目录纳入资源/规则验证，不伪造真实世界验收。

此前0.7.3只对一个264-Mod整合包完成全声明代表状态审计：22276唯一ID中19260可见、703无静态面、2313明确失败；这不能替代全部本地实例验收。0.7.3原全量393项及后续30项专项是各自时点的证据，关闭本版本前需要对最后代码重跑应有的完整检查。

G0需要固定实例清单、版本/loader、Mod和启用资源包内容身份、对应原版资源、实际世界入口；内容去重与验收仍按各实例的有效资源覆盖顺序进行，不能把多个包素材混在一起帮助某个实例虚假通过。基线冻结后新增的Mod作为新增输入验证，不无限移动本次完成门禁。

## 扩展契约需要具体解决的问题

1. **识别依据**：loader ID、已定义格式/能力声明。无关的Mod名称、实例位置、当前本地文件名不得成为支持名单。相同字段名称不保证同语义，别名必须核实。
2. **共享输出**：规则输出统一局部几何、UV、资源引用、材质/透明度和诊断；共享图集/渲染、资源生命周期及预算。规则可以组合，不给每个Mod另写一套浏览器。
3. **位置依赖**：规则声明需要哪些邻居/NBT信息；按这些依赖构造烘焙身份。缓存同时纳入资源源、规则集版本/配置和实际上下文，禁止只按方块ID缓存连接贴图。
4. **扩展稳定性**：公开API版本、规则ID/别名、输入/输出限制及冲突处理；增加示例、兼容测试和最小接入说明，不承诺未经定义的永久二进制兼容。
5. **外部适配器**：设计显式注册/启用与来源说明，区分受信任的浏览器规则扩展和被当作数据读取的Mod本体；不扫描mods并执行其中任意类。第三方规则执行方式在G1具体设计后核对权限/版本/失败隔离边界。
6. **宽松与准确性**：未知namespace、不同作者命名及无关元数据不应阻断通用模型；未知几何/材质语义必须处理或报错。不得用无条件吞字段、抬高所有预算或虚假空模型提高通过率。

先做支撑真实格式所需的有限接口，保留现有JavaFX/LWJGL及资源源。暂不建设在线插件商店、自动下载、全功能脚本语言或任意Mod运行沙箱。

## 验收矩阵

- **资源层**：每个实例只读取自己的有效来源，启用/覆盖顺序与内容身份正确；缺引用查到具体来源、尝试链和字段。
- **声明层**：覆盖所有已声明variants分支及multipart条件/连接边界，记录代表状态与覆盖缺口；不以一个代表状态代替全部分支。
- **存档层**：扫描基线存档实际使用的状态/外观NBT/邻域依赖，按签名去重后分批验证，保留出现次数和定位；不要求对无限可能的NBT组合做无穷枚举。
- **画面层**：各规则族至少一组可复核画面，检查形体、朝向、纹理、UV、染色、透明及连接/多块拼接；对有争议外观用匹配游戏环境的已有证据或开发者提供的对照核实。
- **扩展层**：同格式新namespace无需改主流程即可用；单独示例适配器能通过公开入口加入规则；混用多个规则不会互相覆盖缓存或资源。
- **性能与只读**：小/大选区测量冷准备、热缓存、峰值内存、绘制和取消；原文件清单/内容前后不变；新规则仍遵守集中预算及来源变化检查。

通过目标：实际使用的有效方块状态没有因尚未实现规则而降级，贴图/材质同步；有意空模型/不使用声明证据明确；无以占位/漏几何伪装成功。任何尚需运行时代码或缺失原始数据的有效方块均是待解决项，不能自动豁免后收口。

## 0.7.3收口建议与执行顺序

0.7.3交付实例资源接入、标准/常见声明格式、统一自动匹配和独立诊断入口；新增开放框架及全部本地实例覆盖是扩大的后续目标。建议先固定这一基线，再开展上述整体任务。

收口步骤：最新代码全量回归（含最后UI/配置调整）→逐文件最终复查→文档/版本从SNAPSHOT同步→内部打包身份和只读复验→开发者明确确认版本完成与提交/推送→创建统一提交并核对远端。当前HEAD仍为0.7.2的72145b0，本轮没有提交、推送、改源码或开启0.7.4。上传源码与创建公开Release/安装包分别授权，不混同。
