## 范围与顺序

首个验收目标为 Minecraft Java 1.21.1。默认按存档版本自动查找本地客户端资源；手动选择作为备用并可保存存档/版本绑定。仅查现有目录，不下载或执行客户端。基础纹理验收已经开发者确认；自动定位为随后授权的追加增量。

从客户端资源读取 blockstates、模型 JSON、纹理 PNG 及引用，不把游戏素材加入仓库。只实现支持清单所需的父模型、纹理变量引用、完整立方体六面 UV 和方向选择；不先建设全功能资源包框架。

第一批验收清单：stone、cobblestone、dirt、grass_block、oak_planks、oak_log、bricks、sand。均为 minecraft: 命名空间；核对具体名称/资源存在后建立对应固定样本。草方块必须区分顶/底/侧；原木必须区分端面/侧面与轴向。需要 tintindex 时明确采用的着色规则，第一阶段允许声明固定近似草色，不承诺群系颜色完全一致。

## 验收矩阵

| 场景 | 通过标准 | 证据类型 |
|---|---|---|
| 本地资源有效、缺失、不匹配 | 使用真实内容；错误可见，简化模式可用，地图不受影响 | 自动化 + 人工 |
| 父引用、纹理变量、循环/非法路径 | 正确解析支持子集；拒绝越界/循环/过量数据 | 合成自动化 |
| 支持清单逐面显示 | 贴图、UV、原木轴向、草顶底侧可辨识，不以近似纯色冒充真实纹理 | 原生窗口视觉验收 |
| 固定建筑 | 建筑整体可辨识，清单内外支持情况明确，缺失资源不拖垮整个预览 | 真实样本 + 人工 |
| 开关/切换/取消/缓存重开 | 无旧请求覆盖新状态；资源签名变化正确失效；简化模式可返回 | 自动化 + 原生窗口 |
| 删除、清空及关闭窗口 | 列表和 CPU 缓存同步，GPU 资源按窗口生命周期释放，重复循环无不可接受增长 | 自动化 + 测量 |
| 加载与交互性能 | 记录冷/热资源、生成、首帧、持续帧时间及内存；与同样本简化模式对照 | 原生实测 |
| 文件只读 | 存档与客户端资源的清单/大小/mtime/SHA-256 前后相同；运行数据在程序目录 | 文件证据 |

性能数值先取得基线再确定接受范围，不能把本清单当成已完成验证。原生操作、帧率和自动化证据分别记录。

## 本阶段排除项

- 完整 Mod 支持、Mod 专用渲染器、实体或方块实体。
- 楼梯/台阶等复杂模型、复杂 multipart、全部透明/裁剪与流体材质、动画纹理。
- 自由飞行、动态流送、天气、动态光影、三维嵌入、更换框架。
- 世界搜索、地点持久化、永久三维磁盘缓存或部分重叠网格复用。

Mod 名称仍应准确报告支持状态，不能仅换掉紫色就宣称模型兼容。后续模型与 Mod 任务基于本阶段实测再细化。

## R2 实施记录（2026-10-25）

### 实际完成

- 新增 voxel/resource/BlockModelResolver，复用 R1 的受控资源访问与现有 BlockState；仅处理 CPU 模型数据，不依赖 JavaFX、OpenGL 或存档读取，不持有归档所有权、不建立跨来源缓存。
- 支持清单保持为 8 种原版完整立方体。按 blockstate 属性精确选择 variants；缺属性、匹配冲突、multipart、复杂几何、自定义 loader、无效字段与越界资源 ID 均给出明确降级原因，不把未知模型直接当成六面立方体。
- 真实资源中的 stone/dirt/grass_block/sand 包含模型数组。当前明确固定选择第一候选，结果携带 fixedFirstAlternative 和中文说明，不实现 Minecraft 的位置随机、权重分布或全部候选兼容性检查。未选候选不加载，不宣称它们已通过解析。
- 父模型先继承后覆盖；子 textures 可覆盖父变量，子 elements 替换父 elements。检测父链和纹理变量循环、缺失引用；包含未用于面的 particle 变量在内的合并纹理表均验证最终 ID。
- 输出不可变的模型面数据：方向、纹理 ID、0..16 UV、面内旋转、tintindex、cullface、覆盖层编号，以及 blockstate 的 x/y 旋转和 uvlock。坐标仍处于模型空间；实际旋转/图集 UV/绘制属于 R3/R4。
- 草方块保留六面基础层和四侧面覆盖层；保留顶面及覆盖层的 tintindex=0。雪覆盖状态单独解析；原木 x/y/z 三种状态及水平模型顶面 180 度 UV 旋转均保留。尚未选择或应用草色，也未完成透明覆盖层合成；这些数据不能当作已渲染正确的证明。
- 结果区分已解析、超出方块清单、缺资源、非法 JSON/模型、不支持模型、无匹配/匹配冲突、引用循环和容量超限；携带客户端指纹与按顺序的 blockstate/模型读取链及最终面纹理引用。纹理来源项表示引用，不表示 PNG 已存在、解码或上传成功（R3 负责）。归档关闭、来源变化等 R1 I/O 异常继续向调用方传播，避免用普通模型降级掩盖资源会话失效。

### 容量与支持边界

JSON 使用严格 JsonReader，拒绝重复字段、尾随内容与注释；每项最多 32 层、16384 节点。父模型最多 32 层；blockstate 最多 256 分支/单分支 256 候选；合并纹理变量最多 128 个。继续受 R1 的每项 JSON 1 MiB/会话读取 64 MiB 约束。只支持 from=[0,0,0]、to=[16,16,16] 的六面基础立方体与一层带 tintindex=0/同向 cullface 的四侧面覆盖；旋转限 90 度整数倍，UV 限 0..16，tintindex 限 -1/0。元素旋转、非同向裁剪、关闭 shade/ambientocclusion 等未保留的渲染语义明确降级；display/gui_light 是物品展示元数据，不参与世界方块解析。

## R3–R5 接入记录（2026-10-25）

### 本次实际完成

- 新增 TextureAtlas：通过标准 PNG reader 先检查尺寸，再解码；拒绝错误 PNG、超限尺寸和非正方形动画条带。采用逐行图集布局，四周挤出 1 像素边缘、GL_NEAREST 采样、不启用 mipmap，避免相邻纹理串色。不是全功能资源包/动画加载器。

- 场景携带不可变 CPU 图集；GL 上传增加 UV 顶点属性、单场景纹理、采样开关与片元着色。资源只在 GL 所属线程上传/释放；失败上传、拒绝替换、替换成功及关闭均处理图集生命周期；旧场景在新场景提交前保留。
