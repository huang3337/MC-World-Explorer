# V0.4 三维技术可行性验证进度记录

## 当前阶段

V0.4 已于 2026-08-01 完成设计范围内的实现、自动化、真实存档只读验证、性能采样、便携打包、Rule 16 审查、渲染后端重大决策和最终整体一致性审查。

开发者已明确选择 LWJGL/OpenGL 作为后续三维渲染基础，决策记录见 `docs/decisions/DECISION-007.md`。开发者于 2026-08-01 确认 V0.4 整体开发完成；本版本统一提交后是否推送 GitHub 仍需单独确认，V0.5 尚未开始。

## 开发目标

- 在不改动 V0.3.1 正式入口的前提下读取真实区块全部 Section 和完整方块属性。
- 生成普通方块不透明立方体与原版流体空气接触外壳。
- 用共享网格和共享环绕相机隔离比较 JavaFX 3D 与 LWJGL/OpenGL。
- 验证 Windows x64 开发运行、性能、资源释放、严格只读和非发布 app-image。
- 形成后端对比事实，由开发者确认重大技术决策。

- 新增隔离的数据、网格、相机、指标和双后端代码，核心源码位于 `src/main/java/com/mcworldexplorer/experimental/v04/`；正式 `com.mcworldexplorer.Launcher` 与 V0.3.1 二维界面未修改。

- 新增 `scripts/v04/measure-v04.ps1`，采集阶段耗时、帧时间、JVM 堆、Windows 工作集和四分段趋势。

## 解析正确性独立自检

2026-08-01 在人工画面审核后新增原始 NBT 独立交叉验证。验证器不调用生产代码的位解包方法，而是逐位重建调色板索引，再按每个 Section 的全部 4096 个位置比较方块名称和完整 `Properties`。

- 对画面审核使用的三个区块比较 72 个 Section、294912 个方块位置和 993 个调色板条目，全部一致。
- 三个区块均为 `DataVersion=3465`，真实覆盖单调色板及 4、5、6、7 位 padded 存储。
- 对版本目录中的 25 个世界各抽取一个主世界区块；24 个现代调色板区块比较 1202 个 Section、4923392 个方块位置和 4878 个调色板条目，全部一致。
- 跨版本真实样本覆盖 `DataVersion=3465/3955/4325`，以及单调色板和 4 至 8 位 padded 存储；旧版 compact 5 位跨 long 存储继续由独立合成测试覆盖。
- 所有已验证区块的 NBT `xPos/zPos` 均与 Region 槽位一致；新增保护会拒绝坐标矛盾，不再将区块静默放到错误位置。
- `RLCraft/saves/0` 使用 `DataVersion=1343` 的预扁平化 `Blocks/Data` 格式，不在 V0.4 调色板解析范围内；解析器现在明确报告 `UNSUPPORTED_CHUNK_LAYOUT`，不再错误返回空区块。
- 扫描中记录 10 个不可读 Region 样本：9 个来自 DeceasedCraft 的两个存档，1 个来自乌托邦存档。自检跳过损坏文件后仍在每个世界找到可验证样本，没有将损坏内容计为解析成功。
- 所有被读取 Region 文件的大小、修改时间和 SHA-256 前后不变。

## 性能结果

环境快照：2026-08-01，OpenJDK 21.0.11，实际 OpenGL 设备为 NVIDIA GeForce RTX 5060 Laptop GPU，驱动 `32.0.16.1074`。系统同时存在 Intel UHD Graphics，但未强制验证核显路径；显示缩放未自动采集。

每端每样本包含一次 120 秒长测（静置 60 秒、确定性旋转/俯仰/缩放 60 秒）和 5 次新进程复测。复测中位数代表操作系统文件缓存和驱动已预热后的新 JVM 启动，不代表同一 JVM 内 JIT 预热。

| 指标 | JavaFX 3D | LWJGL/OpenGL |
|---|---:|---:|
| 长测首帧 | 789.38–932.74 ms | 738.09–740.06 ms |
| 后端上传 | 31.11–36.83 ms | 10.57–12.46 ms |
| 帧时中位数 | 4.316–4.327 ms | 4.166–4.168 ms |
| 帧时 P95 | 16.348–16.384 ms | 4.543–4.601 ms |
| 平均 FPS（仅参考） | 约 151 | 约 240 |
| 长测峰值工作集 | 215.9–220.4 MB | 179.7–185.4 MB |
| 第 3→第 4 时间段工作集变化 | -0.8–+1.9 MB | -0.9–+0.3 MB |
| 5 次复测首帧中位数 | 788.18–796.10 ms | 676.42–695.25 ms |
| 5 次复测上传中位数 | 33.42–38.51 ms | 10.00–11.40 ms |

两端后半程工作集均已收敛，没有观察到持续增长。JavaFX 的 P95 呈约 16.3 ms 周期，工作集和上传成本也更高；LWJGL 在本机独显环境中更稳定，但引入本地库、显式资源生命周期和更高维护复杂度。

共享读取、解析和网格阶段不用于后端优劣判断：两端在不同启动顺序下运行，JavaFX 在管线前已经完成 JavaFX 平台启动，LWJGL 则在管线后初始化 GLFW/OpenGL，JIT 条件不完全相同。

## 已知限制

- 只验证单区块加四个水平邻区块，不支持正式三维入口、范围选择或动态加载。
- 所有非空气方块仍按完整不透明立方体简化；未知 Mod 流体按普通实体方块处理。
- 无纹理、复杂模型、透明排序、贪心网格和光照还原。
- 预扁平化 `Blocks/Data` 和外部 `.mcc` 区块尚不支持；现在会明确失败而不是显示伪造结果。
- 初始相机为了容纳完整负 Y 几何，会让地表建筑在画面中显得较小；后续用户预览需要单独设计地表/垂直聚焦策略。
- JavaFX classpath 启动会输出未命名模块配置警告，但开发运行和 app-image 均未失败。
- 只实际验证 NVIDIA 独显路径，Intel 核显、其他厂商和远程桌面环境仍待后续兼容性验证。

## 版本边界

- V0.4 是内部技术验证，不接入正式主界面，也不构建或发布正式用户软件包。
- V0.5 尚未开始。

## 后端决策结果

开发者已确认选择 LWJGL/OpenGL。它在相同几何下具有更低的上传成本、P95 帧时和工作集，资源释放及 Windows x64 app-image 已验证可行，更符合后续受控范围三维预览、纹理和动态浏览的性能空间。

JavaFX 继续承担现有二维主界面；JavaFX 3D 对照原型暂时保留为 V0.4 验证证据，但不继续作为正式三维后端扩展。完整依据和长期约束见 `docs/decisions/DECISION-007.md`。
