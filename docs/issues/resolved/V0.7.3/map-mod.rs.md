### ISSUE-RUSTMAP-001：每次瓦片请求都从 Region 原始数据重新解码和逐列采样，没有任何可复用结果

- **严重程度**：🟠 高
- **类别**：资源管理 / 模块耦合
- **文件**：`crates/mcwe-core/src/map/mod.rs`
- **行号**：`56-165,195-260`
- **状态**：待修复

**问题描述**：
`load_map_tile()` 每次调用都重新打开相交 Region，遍历矩形内每个区块，读取和解压完整 NBT、构造完整 `DecodedChunk`、对 256 个方块列自顶向下采样，随后才按倍率聚合成 256×256 瓦片。函数及会话层没有区块、表面列或瓦片缓存。

**当前代码**（审查时快照）：

```rust
for chunk_z in start_z..=end_z {
    for chunk_x in start_x..=end_x {
        let payload = reader.read_chunk_payload(coordinate, cancel)?;
        let chunk = decode_chunk(&payload.bytes, coordinate, cancel)?;
        let sampled = sample_chunk(&chunk, cancel)?;
        accept_chunk(/* ... */);
    }
}
```

**问题分析**：
输出始终只有 65,536 个像素，但画面越向外缩小（`blocksPerPixel` 越大），单个像素聚合的方块和单块瓦片覆盖的区块越多。实现没有使用 Region 头先形成“实际存在区块集合”来缩减后续工作，也没有跨倍率复用较细粒度表面数据；同一区块在相邻瓦片请求、回看、世界内重复定位以及倍率切换时会再次完成整套解压、NBT 反序列化和垂直扫描。

Java 版 `MapTileService` 先查 128 项访问序内存缓存，再查带 Region 文件状态校验的磁盘缓存，只有未命中才调用生成器；Tauri 决策记录还明确限定 V0.7.2 不建立缓存。该早期垂直切片约束在二维范围扩大和自由视口启用后仍未重新评估，因而当前性能差距属于架构能力缺失，不是 Canvas 绘制速度差异。

现有 `map/mod.rs` 测试只验证瓦片坐标边界和非法倍率，未以真实或合成 Region 验证工作量、重复请求代价、各倍率耗时或大范围完整度。

**建议修改**：
本轮按开发者要求仅记录问题分析，暂不提出解决方案；等待后续专门的缓存与数据复用方案评审。

**影响范围**：
所有地图瓦片请求，尤其是低倍率、大视口、反复缩放、来回拖动和大体积 Mod 存档。

## 2026-09-26 实施复核

- **当前结论**：原审查时“每次瓦片请求都无复用”的结构性问题，已由 V0.7.3 的 `WorldSession` 两级内存缓存替换。正式 `start_map_viewport` 链路及保留的兼容 `load_map_tile` 命令均调用缓存版核心函数；上方原始审查快照保留不变。Issue 仍保持活动，等待真实存档与 Java 同条件验收。
- **实际实现**：最终瓦片以图层/维度/渲染版本/倍率/瓦片坐标及相交 Region 来源状态识别；区块级缓存复用解码区块和 256 列表面采样，支持跨倍率复用。两级缓存均有访问序、项数与字节上限；来源状态变化拒绝旧项，世界切换建立独立空缓存。取消期间已经完成的区块可保留供重试，但部分瓦片不写入最终缓存。本次补充取消检查，避免已取消请求直接从最终瓦片缓存返回成功。
- **自动化证据**：合成 Region 集成测试验证重复瓦片为同一 `Arc`、倍率切换命中区块缓存、来源变化失效、世界会话隔离、共享冲突不伪装成缓存成功、取消后区块复用及来源变化后拒绝保留项；新增已取消请求不能命中最终瓦片的测试。缓存单元测试覆盖访问序、项数/字节上限、超大项拒绝及清空。2026-09-26 定向缓存测试 9 项、Rust fmt、Clippy、workspace tests、TypeScript typecheck 与前端 126 项 Vitest 均通过；真实存档未读取。
- **边界与验收缺口**：当前仅有会话内内存复用；Java 的跨启动磁盘瓦片热缓存属于已确认的后续 V0.7.4 独立任务，不能视为本阶段已达成。区块缓存最多 512 项，而 2 方块/像素的单瓦片覆盖 1,024 个区块槽位；取消后再进入该瓦片时不保证所有已处理区块仍被保留。仍需单独批准真实存档只读测试，测量冷/热、倍率切换和回看耗时及解析次数，再判断体验是否足以收口本 Issue；不以自动化结果直接标记已修复或归档。

## 2026-09-26 来源变化竞态补充

- **问题与修复**：合成 Region 测试复现了生成期间 Region 从缺失变为存在时，请求虽返回来源变化错误，却留下 256 个旧来源区块缓存项。缓存版瓦片现使用同一份初始来源快照建立 Region 工作集；生成期间或最终写入前发现来源变化时，清除对应旧来源区块项，不影响其他 Region 或新来源项。未变化来源下，取消后复用已完成区块的行为保留。
- **验证**：新增生成中来源变化集成测试（修复前失败、修复后通过）及精确失效与容量统计单元测试；`cargo test -p mcwe-core` 通过，Rust 格式检查和针对 `mcwe-core` 的 Clippy 通过。真实存档未读取；Issue 仍待统一验证和人工验收。

## 2026-09-27 真实存档只读专项验证

- **测试范围**：经开发者确认，以“雪山”存档固定二维区域测试同一会话中的首次请求、重复请求、数据倍率切换及返回原瓦片；不把前端保留旧画面当作核心缓存命中，也不与 Java 后台预加载耗时直接比较。
- **结果**：首次 1 方块/像素瓦片约 2.1 秒、256 个成功区块；原请求重复约 0 毫秒，命中最终瓦片缓存且返回同一分配；改为 2 方块/像素时命中 256 个已有区块，新瓦片生成约 6.4 秒；返回原倍率约 1 毫秒，再次命中最终瓦片缓存。合成 Region 缓存集成测试 10 项通过。上述耗时仅为本机单次观察，不是性能门槛或 Java 对等结论。
- **只读核对**：测试前后存档 716 个文件的相对路径、大小和内容哈希完全一致。
- **尚待验收**：桌面端拖离并返回已浏览区域、倍率区间内缩放及跨倍率缩放时的画面连续性仍需开发者人工确认；在此之前保持活动状态。会话内缓存不等于跨启动磁盘热缓存。

## 2026-09-27 桌面复测反馈

- **通过部分**：开发者确认同一数据倍率区间内缩放及跨倍率缩放的现象符合本次测试要求。
- **未通过部分**：附近区域拖离再返回时，原画面仍在，但同一位置的瓦片会重新从头逐渐覆盖；因此不满足“返回已浏览区域不再整瓦片渐进重载”的体验标准，本 Issue 继续保持活动，不归档。
- **代码链路初查**：前端 `loadVisible()` 每次建立新视口仍提交全部当前可见瓦片，不区分已有终态图像；`commitItem()` 收到局部结果后又把同键旧图像改为 `partial` 并重绘。核心层单独测得的最终瓦片命中不能证明这次桌面往返的瓦片曾进入最终缓存：若旧任务在完整终态前被取消，只有有界区块缓存可复用。后续须区分“已终态瓦片被重复提交/覆盖”与“未终态瓦片取消后实际重复生成”，不得仅遮盖加载动画作为修复。

## 2026-09-27 回看续载修复，待桌面复验

- **批准方向与目标**：开发者确认采用有界、可取消、按 Region 来源失效的未完成瓦片进度复用；不采用单纯让屏幕外任务一直占据 worker 的方案。通过标准是附近区域返回时已处理区块不重算、已有终态图像不被局部结果降级覆盖，同时保持终态完整度与失败区分。
- **实际修改**：WorldSession 原有缓存新增未完成瓦片进度层，按图层/维度/渲染版本/倍率/瓦片坐标和相交 Region 来源状态识别；最多 8 项、32 MiB，访问序淘汰。取消或增量提交中断时仅在来源未变且已有完成区块时保存累积颜色、高度、状态、区块完成标记与统计；下次请求先提交已完成部分，再跳过这些区块继续处理。来源变化、最终瓦片完成、会话切换及缓存清空均不保留旧进度。前端当前代次仍验证局部修订号、终态和瓦片身份；若同键旧画面已终态，局部结果不再把它改成部分图像，直到新终态到达才替换。
- **自动化证据**：合成 Region 测试覆盖在 512 项区块缓存上限之后中断、恢复时不重复处理已完成区块，及来源变化、容量、清空和会话隔离；前端回看测试覆盖旧终态图像不被局部结果逐块覆盖。Rust workspace tests、fmt、Clippy、TypeScript typecheck 和前端 144 项 Vitest 通过。

## 2026-09-27 ISSUE-RUSTMAP-001 解决与归档

- **解决状态**：已修复并归档。上方原始审查快照和各阶段待验收说明保留为当时记录，本节为开发者确认后的当前结论。
- **解决日期**：2026-09-27。
- **实际修改**：WorldSession 内的区块、未完成瓦片进度和最终瓦片均有明确身份及容量边界。取消后的未完成瓦片在 Region 来源未变化时保留已处理区块，返回后从该进度继续；已有完整图像不会被新任务局部补丁降级为逐块覆盖。来源变化、缓存淘汰、世界切换和关闭仍按既有边界拒绝旧结果或释放资源；不建立跨启动磁盘缓存。
- **验证证据**：合成 Region 测试覆盖超过 512 项区块缓存容量后的中断续载、来源变化失效、容量上限、清空和会话隔离；前端测试覆盖已完成瓦片回看时不被局部结果逐块覆盖。2026-09-27 Rust workspace tests、fmt、Clippy、TypeScript typecheck 和前端 144 项 Vitest 通过。开发者对修改后的真实存档桌面复验确认：移开视口再移回会从瓦片原本加载的进度继续加载；此前同倍率区间与跨倍率缩放现象也已确认符合要求。存档 716 个文件的路径、大小和内容哈希与测试前只读基线一致。
- **范围边界**：该结论针对同一会话内、容量允许时的回看续载，不保证任意远距离返回后进度永不淘汰，也不代表 Java 的跨启动磁盘热缓存或整体加载速度已对等。后续磁盘缓存仍按独立里程碑处理。
