### ISSUE-MAPVIEW-005：旧手动查找可能在恢复自动之后写回绑定

- **严重程度**：中
- **类别**：错误处理
- **文件**：src/main/java/com/mcworldexplorer/ui/MapViewerController.java
- **行号**：961（修复后定位）
- **状态**：已修复

**问题描述**：后台任务校验成功后直接保存绑定，取消与写入之间存在间隙，旧结果尚未交给当前界面也可能写入配置。

**当前代码（审查时快照）**：
```java
if (isCancelled()) throw new CancellationException();
portableSettings.saveClientResourcePath(worldPath, version, selected);
```

**问题分析**：仅在call内检查取消不能使检查和后续保存保持一致。恢复自动或切世界后，过期手动结果不应产生绑定副作用。

**建议修改**：后台只校验并返回路径；在FX成功回调中通过lookupId/世界/关闭状态检查后才保存手动绑定。

**影响范围**：手动选择JAR、统一恢复自动及旧任务切换。

- **解决日期**：2026-10-26。
- **实际修改**：保存移至通过当前请求身份校验的FX回调；统一自动入口先取消旧任务，配置中一次清除两个键，再重启自动查找。
- **验证证据**：aCompletedOlderManualLookupCannotPersistAfterReturningToAutomatic在FX回调仍排队时完成后台校验，断言此时未保存；恢复自动后旧回调亦不能写回。当前三套件30项全部通过。
