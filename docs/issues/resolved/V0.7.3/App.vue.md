### ISSUE-APPVUE-008：3×3 三维选区生成时提示仍称“最大 8×8”

- **类别**：UI 健壮性

**问题描述**：

**影响范围**：

- **类别**：错误处理

## 2026-09-27 ISSUE-APPVUE-009 解决与验证

- **解决日期**：2026-09-27。
- **已确认的逻辑缺口**：正式二维视口已可动态浏览，但三维 Command 仍用兼容 `surface-v1` 的固定 1024² 表面边界校验选区。Java 稳定版三维请求只限制目标大小，不依附固定表面；这条旧校验会让范围外的合法选区在读取前返回 `INVALID_CHUNK`。
- **实际修改**：正式三维请求不再使用固定表面边界；仍检查 1～8 区块范围、坐标及一圈邻区溢出、会话、只读来源、解码累计预算、网格和 IPC 容量。当前有效协议规格已同步动态选区边界。
- **自动化证据**：合成世界在旧固定表面之外放置实际区块，通过正式 IPC 请求成功生成网格；Rust workspace tests、fmt 与 Clippy 于 2026-09-27 通过。
- **人工验收**：开发者于 2026-09-27 反馈边缘选区现可正常生成三维，并认为足以关闭本 Issue。未提供精确选区坐标，不能证明原失败位置已按同坐标重放，也不声称所有 `INVALID_CHUNK` 场景都已消除；真实缺失、不支持或损坏仍应按各自错误处理。
