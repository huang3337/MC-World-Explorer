### ISSUE-SURFACEMAP-001：固定 144×144 backing store 未处理 CSS 尺寸和设备像素比

- **严重程度**：🟡 中
- **类别**：渲染正确性 / 性能边界
- **文件**：`src/components/SurfaceMap.vue`、`src/composables/useSurfaceCanvas.ts`
- **状态**：已修复

**问题描述**：初版 Canvas 的逻辑尺寸和 backing store 都固定为 `144×144`，CSS 最多放大到 `576px`，没有在窗口尺寸或 DPR 改变时同步两层实际像素，也没有限制异常 DPR 导致的分配。

**问题分析**：逻辑栅格必须保持 `144×144`，但显示缓冲应依据 CSS 内容矩形和 DPR 独立计算；否则高 DPI 显示模糊，后续覆盖层也无法与基础层保持同一像素尺度。

**实际修改**：新增受 `2048×2048` 单层边长上限约束的 backing store 计算，监听容器及窗口尺寸变化，关闭图像平滑并使用最近邻缩放；尺寸和数据均未变化时不重建基础像素。

### ISSUE-SURFACEMAP-002：单 Canvas 无法隔离基础像素与交互覆盖层

- **严重程度**：🟡 中
- **类别**：性能 / 状态可视化
- **文件**：`src/components/SurfaceMap.vue`、`src/composables/useSurfaceCanvas.ts`
- **状态**：已修复

**问题描述**：初版只有一层 Canvas，只绘制颜色并用低 alpha 表示所有失败类型，没有区块线、出生点、悬停或选区覆盖层。

**问题分析**：悬停和选区会高频变化，若与 20,736 个基础像素共用重建路径，会造成无必要的大缓冲更新；缺失、不支持和损坏也不能只靠透明度表达。

**实际修改**：拆分基础与覆盖 Canvas；基础层缓存颜色和固定失败视觉键，覆盖层独立绘制区块线、失败符号、出生点、悬停和选区。专项测试证明悬停及无尺寸变化的 resize 不会重建基础 ImageData。

### ISSUE-SURFACEMAP-003：交互只能点击 1×1，无法选择 2×2 或使用键盘

- **严重程度**：🟠 高
- **类别**：核心功能 / 可访问性
- **文件**：`src/components/SurfaceMap.vue`
- **状态**：已修复

**问题描述**：初版点击直接提交单个区块，没有指针拖动、最大 `2×2` 钳制、活动区块或键盘入口，无法完成 DECISION-019/025 已确认的完整选区能力。

**问题分析**：二维到三维是 V0.7.2 主链路的一部分；缺少 `2×2` 和键盘触发会使核心范围只实现一半，并使不能使用指针的用户无法生成三维。

**实际修改**：加入区块对齐拖动，锚点与焦点在两个方向均限制为最大两格且不能越过 9×9 边界；方向键移动、Shift+方向键扩展，Enter/空格提交世界区块矩形。

### ISSUE-SURFACEMAP-004：Canvas 没有悬停、失败和选区的 DOM 文本等价信息

- **严重程度**：🟡 中
- **类别**：可访问性 / 可诊断性
- **文件**：`src/components/SurfaceMap.vue`
- **状态**：已修复

**问题描述**：初版只有一句方向说明；用户无法读取当前世界坐标、区块坐标、高度、颜色、状态、选区范围或局部失败风险，辅助技术也只能得到笼统 Canvas 标签。

**问题分析**：20,736 个隐藏 DOM 单元格不符合性能边界，但聚合状态和当前焦点必须由真实 DOM 提供，失败说明不能仅依赖颜色。

**实际修改**：新增悬停详情、选区世界区块范围、失败计数、操作帮助和符号图例，并通过 `aria-describedby`、焦点样式及 live status 关联交互 Canvas；仍不创建每格 DOM 或监听器。

- **解决日期**：2026-09-08。
