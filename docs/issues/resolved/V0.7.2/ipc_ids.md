### ISSUE-IPCID-001：session/task ID 可增长到 JavaScript 无法无损表达的范围

- **严重程度**：🟢 低
- **类别**：协议正确性
- **文件**：`src-tauri/src/protocol/mod.rs`、`tasks/registry.rs`、`world_session.rs`
- **状态**：已修复

**问题描述**：
Rust 使用 `u64` 单调编号并按 JSON number 输出；超过 `2^53-1` 后，JavaScript 会丢失整数精度，旧会话/任务身份可能无法准确比较。

**问题分析**：
实际应用生命周期几乎不可能达到该值，但协议不应声称支持一个接收端无法无损表示的范围。沿用数值 JSON 时应在产生端先耗尽。

**建议修改**：
将跨 IPC session/task ID 上限统一为 `Number.MAX_SAFE_INTEGER`，达到上限后复用现有耗尽错误，不改为字符串或提升协议版本。

**影响范围**：
仅影响理论极限编号；正常编号、错误码和 JSON 形状不变。

- **解决日期**：2026-09-07。
- **实际修改**：新增共享安全整数上限并用于会话、任务编号分配；TypeScript 同步验证。
- **验证证据**：既有会话/任务耗尽测试改为安全整数上限并通过，黄金 metadata 对不可无损 ID 的拒绝测试通过。
