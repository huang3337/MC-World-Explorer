### ISSUE-HEADER-001：公共编码器错误拒绝合法 UTF-8 元数据

- **严重程度**：🟡 中
- **类别**：正确性
- **文件**：`src-tauri/src/protocol/header.rs`
- **状态**：已修复

**问题描述**：
初版用 `is_ascii` 拒绝全部非 ASCII 元数据，导致包含中文模组方块名等合法 UTF-8 聚合警告时无法编码。

**问题分析**：
协议要求受限 UTF-8 JSON object，而不是 ASCII；Rust `str` 已保证 UTF-8，有效边界应是元数据字节上限和 JSON 生成规则。

**建议修改**：
移除 ASCII 限制，改为执行 `MAX_TOTAL_TEXT_BYTES` 上限，并由内部 JSON 构造器负责转义。

**影响范围**：
Surface/Mesh 元数据中的非英文警告文本。

- **解决日期**：2026-09-07。
- **实际修改**：允许 UTF-8 并新增 256 KiB 元数据硬上限。
- **验证证据**：中文元数据编码测试和超限拒绝测试通过。

### ISSUE-HEADER-002：段表未验证固定契约和标量字节长度

- **严重程度**：🟠 高
- **类别**：协议安全
- **文件**：`src-tauri/src/protocol/header.rs`
- **状态**：已修复

**问题描述**：
初版直接信任调用方提供的 kind、section id/scalar/count/bytes，且多处 `usize as u32` 截断转换未显式检查。

**问题分析**：
生产编码器也必须维护与前端解码器相同的不变量，否则内部调用错误可以生成自相矛盾或截断的载荷。

**建议修改**：
按 kind 固定段顺序与标量，验证 `byteLength=count×scalarWidth`，所有长度和偏移使用 checked 算术与 `try_from`，数值数组预计算容量后一次分配。

**影响范围**：
全部 v1 Surface/Mesh 响应。

- **解决日期**：2026-09-07。
- **实际修改**：新增公共段契约验证、受检长度/偏移转换和精确容量数值编码。
- **验证证据**：标量长度不一致、错位、重叠、截断、尾随和固定黄金布局测试通过。
