**问题描述**：
开发者在 V0.7.2 单 EXE 读取真实世界 `刀剑` 后确认：当前 Tauri 结果的读取准确度远不如稳定 Java 版，并且读取失败报警出现得比 Java 版更频繁。

**当前代码**：

**问题分析**：
定量诊断确认四类根因：`MAX_TOTAL_TEXT_BYTES=256 KiB` 被错误用于整棵 NBT 预检，使 19 个世界中的 17 个在读取 `level.dat` 时触发资源限制；`MAX_SECTIONS=64` 拒绝存在 68、72、131、132 个 Section 的真实区块；DECISION-019 与代码只使用世界出生点，违背 Java 的个人重生点优先规则；前端将任意 mesh warning 解释为部分失败，并把正常缺失区块计入失败总数。这些不是通过隐藏错误修复，而是分别校正安全预算、结构上限、中心语义和状态分类。

修复后的只读诊断覆盖 `D:\MC\.minecraft\versions` 下 19 个世界：19/19 世界信息读取成功，每个世界默认中心 `9×9` 范围均为 `81/81` 区块解析成功；“刀剑”从错误的世界出生点中心区块 `(16,-9)` 恢复到个人重生点中心区块 `(-45,-38)`。这证明原有主要误拒绝已消除，但不把尚未进行的桌面视觉人工复验标记为通过。
