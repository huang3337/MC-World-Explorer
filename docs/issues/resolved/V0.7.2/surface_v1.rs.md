### ISSUE-SURFACEPROTO-001：区块统计和状态数组可能自相矛盾

- **严重程度**：🟡 中
- **类别**：正确性
- **文件**：`src-tauri/src/protocol/surface_v1.rs`
- **状态**：已修复

**问题描述**：
初版只校验数组总长度，不验证每个 16×16 区块状态一致、成功/失败统计匹配，也始终输出空 warnings。

**问题分析**：
metadata 统计必须与密集状态段一致；取消状态不得作为成功载荷编码，局部失败应提供有界聚合摘要。

**建议修改**：
按 9×9 区块重新核对状态，拒绝混合状态、统计不一致和 cancelled，按 missing/unsupported/corrupt 聚合 warning。

**影响范围**：
二维载荷的状态解释、错误展示和协议自洽性。

- **解决日期**：2026-09-07。
- **实际修改**：新增区块级状态计数、一致性校验和静态字段聚合 warnings。
- **验证证据**：81 个 missing 聚合与统计不一致拒绝测试通过。

### ISSUE-SURFACEPROTO-002：编码器接受与中心区块矛盾的坐标和非法列值

- **严重程度**：🟡 中
- **类别**：协议正确性
- **文件**：`src-tauri/src/protocol/surface_v1.rs`、`src-tauri/src/protocol/tests.rs`
- **状态**：已修复

**问题描述**：
Task 8 的 Rust surface 黄金夹具使用了与 `centerChunk` 不一致的 `originBlock` 和出生点，编码器仍然生成成功载荷；颜色高位和失败列非零高度也未核对。

**问题分析**：
这些字段由不同数组和 metadata 重复表达同一结果。若编码前不交叉校验，TypeScript 无法区分合法载荷与内部状态拼接错误，黄金向量也会把矛盾固化为契约。

**建议修改**：
编码前验证中心区块、二维原点、出生点、`0x00RRGGBB` 颜色和失败列高度语义，并重新生成 Rust 黄金向量及固定哈希。

**影响范围**：
仅拒绝内部不一致的 surface 成功结果；正常加载器输出布局和协议版本不变。

- **解决日期**：2026-09-07。
- **实际修改**：补充坐标与列值校验，修正合成黄金数据并同步跨语言黄金夹具。
- **验证证据**：Rust 坐标/颜色/失败高度拒绝测试及 TypeScript Rust 黄金向量解码通过。
