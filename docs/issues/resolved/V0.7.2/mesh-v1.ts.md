### ISSUE-TSMESH-001：有限值检查会展开大型 TypedArray 并制造额外峰值内存

- **严重程度**：🟠 高
- **类别**：资源管理
- **文件**：`src/protocol/mesh-v1.ts`
- **状态**：已修复

**问题描述**：
初版通过 `[...positions, ...normals]` 检查有限浮点，会把两个潜在大数组展开为新的普通 JavaScript 数组。

**问题分析**：
在 128 MiB 响应上限附近，该操作会产生远大于原始 ArrayBuffer 的临时对象和引用数组，可能先触发参数/堆内存错误，违背只建立受控视图的轻量化边界。

**建议修改**：
按 xyz 三元组原地遍历 TypedArray，同时完成有限值、轴向法线和 bounds 校验，不建立与顶点数成比例的临时对象。

**影响范围**：
mesh 前端解码阶段的峰值内存与错误分类。

- **解决日期**：2026-09-07。
- **实际修改**：改为定额局部变量循环，移除全部大数组展开。
- **验证证据**：黄金 mesh、NaN、非轴向/零法线、bounds 与索引矩阵通过；静态审查确认循环内无按顶点创建数组。
