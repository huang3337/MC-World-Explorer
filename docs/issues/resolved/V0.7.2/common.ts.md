### ISSUE-TSCOMMON-001：TypeScript 解码器未完整执行冻结协议的规范布局与语义校验

- **严重程度**：🟡 中
- **类别**：协议正确性
- **文件**：`src/protocol/common.ts`、`surface-v1.ts`、`mesh-v1.ts`
- **状态**：已修复

**问题描述**：
初版只验证段 ID 属于允许集合和范围不重叠，未要求固定段顺序、连续对齐布局或 metadata 紧跟数据；surface/mesh metadata、轴向法线、颜色、批次统计和状态语义也未完整核对。

**问题分析**：
Rust 编码器是唯一生产来源，TypeScript 必须拒绝偏离同一 v1 契约的整份结果，否则畸形或前后端版本错配可能被解释为合法 TypedArray 并进入界面。

**建议修改**：
公共入口按固定顺序和标量检查每段并要求连续布局；两个专用解码器验证完整 metadata schema、数组统计、坐标、有限值、法线、索引、批次、状态与警告。

**影响范围**：
仅收紧无效或不兼容响应；Rust v1 正常结果保持零拷贝 TypedArray 视图。

- **解决日期**：2026-09-07。
- **实际修改**：重写公共与专用解码边界，并加入 Rust surface/mesh 黄金向量和逐字段畸形矩阵。
- **验证证据**：22 项协议测试读取 Rust 固定哈希夹具并覆盖头、段表、UTF-8、metadata、NaN、轴向法线、索引和批次错误。

### ISSUE-TSCOMMON-002：metadata 缺少独立解析上限

- **严重程度**：🟡 中
- **类别**：资源边界
- **文件**：`src/protocol/common.ts`
- **状态**：已修复

**问题描述**：公共容器只限制总响应为 `128 MiB`，攻击性或版本错配响应可把几乎全部空间声明为 metadata，随后进入 UTF-8 与 JSON 解析。

**实际修改**：增加 `256 KiB` 独立 metadata 上限，并在创建字符串和解析 JSON 前拒绝超限输入。

- **解决日期**：2026-09-09。
- **验证证据**：超过独立上限的结构自洽容器被协议测试稳定拒绝；前端 85 项测试通过。
