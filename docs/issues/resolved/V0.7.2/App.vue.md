### ISSUE-APPVUE-001：新世界验证后立即清空旧二维和三维

- **严重程度**：🟠 高
- **类别**：状态原子性
- **文件**：`src/App.vue`、`src/composables/useWorldExplorer.ts`
- **状态**：已修复

**问题描述**：原实现取得新 `WorldSummary` 后立即替换 `world` 并清空 `surface/mesh`，随后才请求并解码二维数据；加载失败或取消会让此前完整视图永久消失。

**问题分析**：世界会话在 Rust 侧替换与页面可见快照提交是不同边界。页面必须保留上一次完整结果，直到新世界的 surface 响应完整返回并通过协议解码，且不得展示半成品。

**实际修改**：新增独立页面状态机与 `pendingWorld`；新二维成功后一次性提交 `world/surface` 并清空旧 `mesh`，失败、取消和过期结果均保留此前完整快照。

### ISSUE-APPVUE-002：单个 busy/error 无法表达取消、部分成功和关闭状态

- **严重程度**：🟡 中
- **类别**：状态建模 / 可诊断性
- **文件**：`src/App.vue`、`src/composables/useWorldExplorer.ts`
- **状态**：已修复

**问题描述**：原实现只有 `select/surface/mesh/null` busy 和一个通用错误，任务取消会直接回到无 busy 状态，surface/mesh 的完整与部分成功也没有页面级区分，关闭只存在于局部布尔值中。

**问题分析**：用户无法判断任务是成功、部分成功、失败、取消还是结果过期；测试也无法覆盖完整状态转换矩阵。

**实际修改**：建立显式 `ExplorerPhase`，覆盖无世界、选择、二维、三维、部分成功、失败、取消和关闭；基于协议 metadata/warnings 生成真实 DOM 状态文本。

### ISSUE-APPVUE-003：Rust 会话已切换时保留的旧视图仍可发起操作

- **严重程度**：🟠 高
- **类别**：会话隔离 / 竞态
- **文件**：`src/App.vue`、`src/components/SurfaceMap.vue`、`src/components/VoxelViewer.vue`
- **状态**：已修复

**问题描述**：新世界被 Rust 接纳但 surface 尚未完成或失败时，若页面保留旧 surface，其选择事件会携带旧 `sessionId` 请求三维；保留的三维也仍响应相机输入。

**问题分析**：旧视图只可作为可解释的完整显示快照，不能伪装成当前活动会话；否则用户会看到无效选择变化并触发必然过期的请求。

**实际修改**：状态机单独跟踪活动会话 ID；保留视图期间禁止 surface 指针/键盘提交和 voxel 指针/滚轮/键盘/重置，并从焦点顺序移除交互宿主，页面明确说明仅保留显示。

### ISSUE-APPVUE-004：后端连接错误与业务错误相互覆盖且状态区主导页面

- **严重程度**：🟡 中
- **类别**：信息架构 / 错误隔离
- **文件**：`src/App.vue`、`src/composables/useWorldExplorer.ts`
- **状态**：已修复

**问题描述**：`app_status` 与世界业务共用一个 error，后续选世界会清除连接失败；后端和五个便携路径又位于业务区之前，占据页面主要位置。

**问题分析**：基础设施状态和业务任务有独立生命周期，互相覆盖会产生错误结论；便携边界需要保留但不应压过只读世界浏览主流程。

**实际修改**：拆分 `statusError` 与 `businessError`，将世界浏览前置，并把后端版本和便携目录收纳到次要 `details` 区域。

### ISSUE-APPVUE-005：目录选择阶段显示无法取消系统对话框的后台取消按钮

- **严重程度**：🟡 中
- **类别**：交互语义
- **文件**：`src/App.vue`
- **状态**：已修复

**问题描述**：原页面在 `busy=select` 时显示“取消当前任务”，但 `cancel_active_task` 只取消 surface/mesh 执行器任务，不能关闭正在等待用户操作的系统目录对话框。

**问题分析**：按钮会宣称一个后端不具备的能力，并可能让对话框和页面状态发生分歧。

**实际修改**：选择阶段仅由系统对话框自身取消；页面取消按钮只在 surface 或 mesh 后台任务活动时显示。

### ISSUE-APPVUE-006：只校验响应结构，未绑定当前会话和选区

- **严重程度**：🟠 高
- **类别**：响应身份 / 竞态
- **文件**：`src/composables/useWorldExplorer.ts`
- **状态**：已修复

**问题描述**：解码器会校验协议内部自洽，但初版状态机没有确认 surface metadata 的会话/出生点属于所选世界，也没有确认 mesh metadata 的会话/选区等于当前请求。

**问题分析**：结构合法的旧会话或错误选区响应若被误路由，仍可能通过解码并覆盖页面；页面代次只能拒绝已知旧 Promise，不能代替响应身份绑定。

**实际修改**：surface 提交前比对 `sessionId` 与出生点，mesh 提交前比对 `sessionId` 与完整 `chunkRect`；不一致统一按 `INVALID_RESPONSE` 拒绝并保留旧完整视图。

- **解决日期**：2026-09-09。
- **验证证据**：Task 15 新增 8 项状态机、页面和保留视图测试；前端共 82 项测试通过，TypeScript 类型检查通过。

### ISSUE-APPVUE-007：取消 IPC 失败被静默吞掉

- **严重程度**：🟡 中
- **类别**：错误反馈
- **文件**：`src/composables/useWorldExplorer.ts`
- **状态**：已修复

**问题描述**：页面先显示已取消，再以空 catch 忽略 `cancel_active_task` 的 IPC 失败，用户会得到与后端实际状态不一致的成功提示。

**实际修改**：取消仍立即提升页面代次以拒绝迟到结果，但现在等待取消 IPC；失败时使用稳定显示错误并进入对应 surface/mesh 错误态。组件关闭后的 best-effort 取消保持静默，因为页面已销毁且 Rust 关闭路径独立协调。

- **解决日期**：2026-09-09。
- **验证证据**：取消 IPC 拒绝、错误显示和迟到 mesh 不提交测试通过。
