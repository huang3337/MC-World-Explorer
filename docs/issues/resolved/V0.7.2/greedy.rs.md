### ISSUE-GREEDY-001：流体与实体边界错误生成内部面

- **严重程度**：🟡 中
- **类别**：正确性
- **文件**：`crates/mcwe-core/src/mesh/greedy.rs`
- **行号**：审查时约 221–248 行，`face_key` / `visible`
- **状态**：已修复

**问题描述**：
初版仅比较渲染层和颜色，水或熔岩贴着实体方块时因层不同而生成流体内部面，与 Java 基线“流体只面向空气可见”不一致。

**问题分析**：
同一简化渲染层不足以表达 Java 的非对称邻面规则，也无法正确处理 opaque/fallback 和不同透明方块状态。

**建议修改**：
可见性判断同时接收当前与相邻 `BlockState`，按 Java 已确认语义依次处理流体、空气、opaque/fallback 和透明状态差异。

**影响范围**：
流体、透明、opaque 与 fallback 相邻边界；不改变单方块立方体模型。

- **解决日期**：2026-09-07。
- **实际修改**：重写 `visible` 的分类顺序，并保留缺失邻居保守开面。
- **验证证据**：流体-实体、相同/不同玻璃、opaque-fallback 回归测试均通过；流体用例修复前为 6 面、修复后为 5 面。

### ISSUE-GREEDY-002：空邻域会绕过取消检查

- **严重程度**：🟡 中
- **类别**：资源管理
- **文件**：`crates/mcwe-core/src/mesh/greedy.rs`
- **行号**：审查时约 34–63 行，`build_mesh`
- **状态**：已修复

**问题描述**：
取消检查只存在于后续体素和合并循环；邻域没有可用 section 时函数会提前返回空结果，已取消任务仍被当作成功。

**问题分析**：
所有输入路径都必须先观察取消状态，不能依赖后续循环一定执行。

**建议修改**：
在任何校验、扫描和分配前执行一次取消检查。

**影响范围**：
空邻域或全部目标不可用时的任务接纳语义。

- **解决日期**：2026-09-07。
- **实际修改**：`build_mesh` 入口首先调用 `cancel.check()`。
- **验证证据**：修复前空邻域取消用例返回成功，修复后稳定返回 `Cancelled`。

### ISSUE-GREEDY-003：网格结果和分配缺少冻结计划要求的安全边界

- **严重程度**：🟠 高
- **类别**：资源管理
- **文件**：`crates/mcwe-core/src/mesh/greedy.rs`、`types.rs`、`limits.rs`
- **行号**：Task 7 初版整体
- **状态**：已修复

**问题描述**：
初版没有 origin、bounds、局部失败/fallback warnings，也未在聚合矩形、批次和输出数组增长前实施核心上限。

**问题分析**：
最坏方块排列可能在最终 IPC 总长检查之前形成大量矩形和数组，且应用层无法向前端解释降级边界。

**建议修改**：
领域结果补齐局部原点、bounds 和确定性 warning DTO；面、顶点、索引和批次使用与 128 MiB 响应预算一致的硬上限，并在插入/扩容前检查。

**影响范围**：
核心网格 DTO、Task 8 协议映射以及极端合成输入。

- **解决日期**：2026-09-07。
- **实际修改**：新增网格计数上限、合并阶段取消和上限检查、输出数组前置检查、bounds 计算及目标/halo/fallback 警告聚合。
- **验证证据**：上限关系单元测试证明最大数组预算低于 128 MiB；1×1/2×2、halo、失败空洞、bounds、warnings 和确定性专项测试通过。
