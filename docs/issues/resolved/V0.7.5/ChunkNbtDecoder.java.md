## ISSUE-CHUNKDEC-002 紧凑默认状态丢失语义，三维无法匹配原版模型

| 项目 | 记录 |
|---|---|
| 严重程度、类别 | 高，跨版本解析与模型正确性 |

| 状态 | 0.7.5 工作区已修复并回归 |
| 影响范围 | 采用紧凑默认状态的调色板条目，以及依赖这些属性的模型分支；同一状态可影响大量方块 |

**问题描述与复现**  
26.3 允许直接以方块 ID 表示该方块的默认状态。[Minecraft 26.3 格式说明](https://www.minecraft.net/en-us/article/minecraft-java-edition-26-3)

本机主世界区块 (0, 0) 的 DataVersion 为 5023，14,573 个深板岩方块解码为同一个空属性状态。同区块有 14 个高海草方块采用紧凑写法，均无法匹配模型，另外 14 个显式保存 `half=upper` 的方块能匹配。使用实际实例资源、单区块选区及正常模型与网格构建入口，场景诊断对深板岩和高海草报 `NO_VARIANT`。在出生点区块 (0, 7)，同一路径对深板岩和草方块报相同错误。

**审查时的代码**

```java
return new BlockState(name,Map.of());
```

**原因与建议**  
解码器认识字符串和混合调色板中的字符串包装形式，两者最终都生成空属性表。模型选择随后要求匹配资源中声明的属性。例如选中客户端的深板岩资源声明 `axis=x/y/z` 三个分支，高海草资源声明 `half=lower/upper` 两个分支。资源中的分支顺序无法证明哪个是注册默认值。

建议保留原始编码形态与显式属性，在模型选择前按对应版本的可信方块状态定义恢复有效属性。核对区块 DataVersion 与所选资源版本，复用同一调色板条目的解析结果。默认值来源缺失或冲突时，在诊断中保留原始状态与原因。二维只需方块 ID 的路径可继续使用原始身份。

**验收依据**  
用上述深板岩、高海草上下半部及草方块从真实调色板跑到场景，核对选中的分支、几何和诊断。另测旧版显式属性、无属性方块、缺少默认值来源和混合版本区块。现有资源覆盖测试会从资源选择器构造属性，能验证模型资源自身可读，还需以真实调色板补上存档到模型的链路。

**2026-11-19 验证**  
已在 0.7.5 工作区修复。区块读取器按条目形状解码，根据区块 DataVersion 和离线注册数据恢复有效属性。实际实例资源、区块读取、模型选择与网格构建链路复查 (0, 0) 和 (0, 7)，两处的 NO_VARIANT 已消失。前者产生 15,000 面且无警告，后者产生 2,712 面，当时记录的草方块[颜色绑定问题](ClientBlockColors.java.md)已另行修复。单元测试覆盖简写与显式上下半部、部分属性、不同数据版本和缺少注册来源。
