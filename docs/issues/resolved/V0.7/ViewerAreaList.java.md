### ISSUE-VAREALIST-001：浮层父子高度循环可将条目压缩至零高度

- **严重程度**：🟠 高
- **类别**：UI 健壮性
- **文件**：src/main/java/com/mcworldexplorer/ui/MapViewerController.java；src/main/java/com/mcworldexplorer/ui/ViewerAreaList.java；src/main/resources/fxml/map-view.fxml
- **行号**：初始化区域浮层和 ViewerAreaList.setAreas 的首选高度设置
- **状态**：已修复

**问题描述**：短列表从选择模式回到普通地图时，卡片节点虽存在，滚动容器却可能缩为零高度，只剩标题和容量说明，无法点击重新打开。

**当前代码**（审查时快照）：
```java
viewerAreaList.maxHeightProperty().bind(viewerAreasHost.heightProperty());
```
```xml
<StackPane fx:id="viewerAreasHost" maxHeight="-Infinity" .../>
```

**问题分析**：浮层按内容首选高度确定最大高度，同时子组件又将最大高度绑定到父容器当前高度。父子求值互相约束，滚动区允许零最小高度，短列表可以退化为仅标题和说明的高度。只断言 ImageView 节点存在无法检测可见性。

**建议修改**：解除父子最大高度绑定，明确组件按卡片数计算首选高度，继续由地图可用空间限制浮层，滚动容器承担超出内容；增加实际可见高度验算。

**影响范围**：已加载区域列表展开、生成成功后退出三维选区、短列表卡片可达性。

- **解决日期**：2026-10-25
- **实际修改**：移除上述绑定；组件给出随条目/状态变化的首选高度，保留可滚动内容与固定两行说明空间，缩放按钮留出浮层阴影距离。
- **验证证据**：WorkspaceLayoutTest 的合成缓存列表与真实 test001 缩略图/缓存重开检查；断言真实滚动区高度至少 90 px，截图再复核卡片可见。窗口为替身，不视为原生 GL 人工验收。
