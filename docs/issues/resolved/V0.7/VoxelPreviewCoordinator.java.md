### ISSUE-VCOORD-001：缓存重开丢失区块读取失败数量

- **严重程度**：🟡 中
- **类别**：UI 健壮性
- **文件**：src/main/java/com/mcworldexplorer/viewer/VoxelPreviewCoordinator.java；src/main/java/com/mcworldexplorer/ui/MapViewerController.java
- **行号**：协调器 147–149；控制器 838–839（修复后位置）
- **状态**：已修复

**问题描述**：缓存命中把 failedChunks 固定传为 0；同时 UI 的缓存分支优先显示成功文案，重新打开后不再提示原来的部分读取失败。

**当前代码**（审查时快照）：
```java
show(request, cached.orElseThrow(), true, 0);
// UI 缓存分支优先返回成功文案，忽略 partialSuccess。
String state = result.fromCache() ? "已打开缓存中的三维预览" : ...;
```

**问题分析**：用户通过列表重复打开局部成功区域时，会误以为场景数据完整；缓存身份和实际网格均未改变，但状态信息丢失。

**建议修改**：缓存随场景保存失败区块数量，缓存命中恢复真实状态；UI 成功文案仍应附加部分失败提示。

**影响范围**：部分成功三维场景的缓存重开、列表状态与成功提示。

- **解决日期**：2026-10-25
- **实际修改**：缓存条目增加 `ViewerCachedArea` 元数据，保存缩略图及 failedChunks；缓存命中恢复该值，列表与成功提示均展示未完整加载数量。
- **验证证据**：`ViewerSceneCacheTest.thumbnailsAndPartialStatusFollowCacheEvictionInvalidationAndByteBudget` 以及 `WorkspaceLayoutTest.loadedAreaListReopensCachedScenesAndTracksDimensionAndSourceChanges`；窗口使用替身，不把该测试当作原生 GL 人工验收。
