# 常见问题

本文件集中说明版本安排、功能行为和使用中容易产生疑问的内容。后续发现的新问题会继续补充在这里。

## 为什么没有 V0.4 和 V0.5 软件包？

V0.4 和 V0.5 都是项目真实存在的源码开发阶段，但它们不是面向普通用户发布的软件版本。项目版本号同时记录内部技术里程碑，因此 GitHub Releases 中的软件包会从 V0.3.1 直接跳到 V0.6.0。

### V0.4：三维技术可行性验证

V0.4 用于验证 Minecraft 存档能否可靠转换为三维数据，并比较 JavaFX 3D 与 LWJGL/OpenGL 两种渲染方案。该阶段最终确定后续采用 LWJGL/OpenGL。

V0.4 的代码位于独立试验模块，没有接入正式启动器、主窗口或二维地图。它生成过仅供验证的 Windows app-image，但不属于可发布软件包。

- [V0.4 开发与验收记录](progress/V0.4.md)
- [DECISION-007：三维渲染后端选择](decisions/DECISION-007.md)

### V0.5：三维数据与渲染基础

V0.5 将 V0.4 的试验结论整理为正式、可复用的内部基础，包括完整方块状态、有限多区块加载、边界数据、分层简化网格、渲染快照和 LWJGL/OpenGL 资源管理。

V0.5 同样没有接入正式界面，只保留源码、测试和内部验证入口，因此没有制作软件包、版本标签或 GitHub Release。

- [V0.5 开发与验收记录](progress/V0.5.md)
- [DECISION-008：V0.5 三维基础边界](decisions/DECISION-008.md)

### 第一个正式三维软件包

V0.6 首次把小范围三维预览接入正式程序，也是第一个向用户发布三维功能的软件版本。因此普通用户看到的软件包版本顺序是 **V0.3.1 → V0.6.0**。

## 正在游玩时，能看到新放置的方块吗？

不一定需要退出游戏，但变化必须先保存到磁盘，再由工具重新读取。仍在游戏内存中、尚未保存的方块，刷新后也看不到；工具不会实时同步游戏画面。

- **二维地图**：使用“工具 → 清理存档缓存并重新加载”。普通拖动地图不保证刷新已有缓存；二维只显示当前图层的表面，地下新增方块不一定会改变地图。
- **三维预览**：重新打开或重新生成对应区域。已经打开的三维窗口不会自动更新。

游戏正在保存时，读取结果不保证来自同一个保存时刻。三维若提示“生成期间存档 Region 文件发生变化，请重新生成”，请等保存完成后重试；二维没有同等的前后变化检查。需要稳定结果时，建议先保存并退出世界，再刷新预览。

## 三维画面中的荧光紫方块是什么？

荧光紫色 `#E83EED` 是简化显示中的未知分类色，不代表存档损坏。0.7.4 会先按所选资源尝试生成模型；只有资源未使用、缺失或模型无法解析等情况下才可能降级为简化方块，不能据此说所有 Mod 方块都不受支持。

查看“资源与插件 → 解析诊断”中的原始 ID、原因和资产来源，区分缺资源、未知 loader 与颜色未绑定。[方块颜色规则](方块颜色规则.md)描述简化颜色底座；[当前解析范围](MODEL_PROTOCOL_CAPABILITIES.md)说明模型解析边界。

## 0.7.4 自带 Mod 插件吗？

不自带。应用包含通用资源解析与插件管理，安装后默认停用。只安装可信插件；停用释放 worker 和旧场景，卸载删除宿主管理的副本与状态，用户原始 JAR 保留。第三方可参考[插件开发说明](PLUGIN_DEVELOPMENT.md)。

## 二维、三维和内存设置何时生效？

下表适用于带统一设置页的 Java 工作区。二维地图与独立三维窗口分别报告实际设备。

| 选项 | 可控制的范围 | 生效时机 |
|---|---|---|
| 二维渲染偏好 | Windows 设置页按型号列出已连接的实体显卡，并显示当前窗口的实际设备 | 点击“保存并重启 MCWE”，或保存后下次启动生效。只需重启程序 |
| 三维 OpenGL | 系统驱动创建 OpenGL 3.3 Core 上下文。支持该能力的核显与独显均可使用。设置页单独显示最近一次三维窗口的实际设备和 OpenGL 版本 | 首次打开三维窗口后可查看；驱动可能选用与二维不同的显卡 |
| JVM 最大堆 | 自动、1、2 或 4 GiB；界面另显示当前客户端 JVM 的实际最大堆 | 重启程序 |
| 二维扫描并发 | 同一个调度器允许 1 或 2 个瓦片扫描任务并行，原有启动参数优先 | 保存后生效，正在执行的扫描可完成 |
| 三维场景缓存 | 基础档最多 2 个场景、估算 256 MiB；增强档最多 4 个、估算 512 MiB。选区上限分别为 9 和 256 个区块 | 保存后立即按最近使用顺序淘汰超限条目 |

整个进程的工作集还包含线程、原生库、堆外缓冲和驱动分配。场景缓存按网格、索引、图集、诊断等估算占用；GPU 专用及共享内存由驱动分配。三项统计各自记录，不能将 JVM 最大堆或缓存预算当作整进程内存上限。

三维依赖系统提供的 OpenGL 3.3 Core。无法创建上下文时，三维窗口报告错误并可重试；二维地图仍可使用。正常浏览无需安装 Mesa。在 Windows 上，三维预览单独关闭文字输入。使用中文输入法时，点击预览画面即可用 WASD 移动，回到主窗口可继续输入中文。

从 `run-app.bat` 启动时，MCWE 使用项目专用运行目录；便携包使用自己的 EXE。共享 `java.exe` 启动时可查看实际设备。插拔外接显卡后，等 30 秒再打开设置即可刷新列表。

所选型号保存在便携配置中。启动时，MCWE 只为自己的 EXE 临时应用 Windows 显卡偏好。二维窗口确认实际设备后恢复原设置。多个实例同时运行时，最后一个释放临时偏好的实例负责恢复。设备不符、驱动未报告型号或沿用旧版省电／高性能配置时，正常退出会恢复。

在核对或恢复完成前强制结束，临时偏好可能留在原 EXE 路径。需要清理时，从原位置启动并正常退出一次即可。
