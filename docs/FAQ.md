# 常见问题

本文件集中说明版本安排、功能行为和使用中容易产生疑问的内容。后续发现的新问题会继续补充在这里。

## 为什么没有 V0.4 和 V0.5 软件包？

V0.4 和 V0.5 都是项目真实存在的源码开发阶段，但它们不是面向普通用户发布的软件版本。项目版本号同时记录内部技术里程碑，因此 GitHub Releases 中的软件包会从 V0.3.1 直接跳到 V0.6.0。

### V0.4：三维技术可行性验证

V0.4 用于验证 Minecraft 存档能否可靠转换为三维数据，并比较 JavaFX 3D 与 LWJGL/OpenGL 两种渲染方案。该阶段最终确定后续采用 LWJGL/OpenGL。

V0.4 的代码位于独立试验模块，没有接入正式启动器、主窗口或二维地图。它生成过仅供验证的 Windows app-image，但不属于可发布软件包。

- [V0.4 开发与验收记录](progress/V0.4.md)
- [DECISION-007：三维渲染后端选择](decisions/DECISION-007.md)

### V0.5：三维数据与渲染基础

V0.5 将 V0.4 的试验结论整理为正式、可复用的内部基础，包括完整方块状态、有限多区块加载、边界数据、分层简化网格、渲染快照和 LWJGL/OpenGL 资源管理。

V0.5 同样没有接入正式界面，只保留源码、测试和内部验证入口，因此没有制作软件包、版本标签或 GitHub Release。

- [V0.5 开发与验收记录](progress/V0.5.md)
- [DECISION-008：V0.5 三维基础边界](decisions/DECISION-008.md)

### 第一个正式三维软件包

V0.6 首次把小范围三维预览接入正式程序，也是第一个向用户发布三维功能的软件版本。因此普通用户看到的软件包版本顺序是 **V0.3.1 → V0.6.0**。

## 三维画面中的荧光紫方块是什么？

荧光紫色 `#E83EED` 表示程序已经成功读取方块 ID 和属性，但该非原版方块还没有明确的三维分类规则。当前版本会将它作为不透明立方体安全显示，而不会根据名称猜测其材质或透明类型。

这通常不表示 Region、NBT 或 Palette 解析失败。完整分类、颜色和已适配方块 ID 见[方块颜色规则](方块颜色规则.md)。
